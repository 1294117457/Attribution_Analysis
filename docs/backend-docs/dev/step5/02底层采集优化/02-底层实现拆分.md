# 02 底层实现拆分：XxxClient + XxxAdapter

> 对应 README 中的第三层，流程 ⑦⑧。Tushare 在 P1 完成，adata / pytdx 在 P3 完成。

## 1. 拆分原则

- **Client**：一个 SDK 一个。只负责连接、鉴权、把同步 SDK 调用变成 `async`、把 SDK 的错误翻译成 01 §6 的四种异常。不认识任何业务字段。
- **Adapter**：一个"Port × 工具"一个小类，继承对应的 Port。只做三件事：入参转换 → 调 Client → 出参解析成 BO。
- **Parser**：保留现有 `TushareKlineParser` / `PytdxKlineParser` 和各 `_parse_xxx_row`，原样搬到对应文件，不改解析逻辑。
- 现有每个 `fetch_*` 方法里重复的 `try → _is_rate_limit → raise RateLimitError` 收到 Client 里，只写一次。

## 2. Tushare

### 2.1 现状

`TushareFetcher` 约 1050 行，17 个 `fetch_*` 方法，每个都是相同结构：

```python
try:
    df = self._pro.xxx(...)
except Exception as e:
    if _is_rate_limit(e):
        raise RateLimitError(str(e)) from e
    raise self._wrap_error(...)
if df is None or df.empty: return []
return [self._parse_xxx_row(r) for r in df.to_dict("records") if ...]
```

### 2.2 TushareClient

```python
# adapter/data/tushare/client.py
class TushareClient:
    def __init__(self, token: str, pool_size: int): ...   # 内部维护 pro_api 实例池

    async def query(self, api: str, **kwargs) -> pd.DataFrame:
        """调 pro.<api>(**kwargs)；空返回空 DataFrame；限频抛 RateLimited，其它抛 SourceUnavailable"""
        pro = await self._pool.get()
        try:
            return await asyncio.to_thread(getattr(pro, api), **kwargs)
        except Exception as e:
            if _is_rate_limit(e):
                raise RateLimited(str(e), retry_after=60) from e
            raise SourceUnavailable(f"tushare.{api}: {e}") from e
        finally:
            self._pool.put_nowait(pro)
```

- `pool_size` 取 `COLLECT_MAX_CONCURRENCY`，替代 `daily_kline` 里自己维护的 `_fetcher_pool`。
- token 从 `get_settings().TUSHARE_TOKEN` 读，与现在一致（认证信息仍统一放 `k8s/public/public.env`）。
- 股票名称缓存 `_name_cache` / `_resolve_name` 只有日 K 用，移到 `TushareDailyKlineAdapter` 里。

### 2.3 Adapter 示例

```python
# adapter/data/tushare/capital.py
class TushareMoneyflowAdapter(MoneyflowPort):
    tool, origin, priority = "tushare", "tushare", 10
    throttle_group = "tushare"

    def __init__(self, client: TushareClient): self._c = client

    async def fetch(self, p: MoneyflowParams) -> list[CapMoneyflowBO]:
        kwargs = {"trade_date": p.trade_date.strftime("%Y%m%d")}
        if p.symbols:
            kwargs["ts_code"] = ",".join(symbol_to_ts_code(s) for s in p.symbols)
        df = await self._c.query("moneyflow", **kwargs)
        return [bo for r in _rows(df) if (bo := _parse_moneyflow_row(r))]
```

## 3. adata（同花顺）

### 3.1 现状

- `AdataConceptFetcher` 一个类提供 6 种数据，其中 `fetch_current_snapshot` 不在 `ConceptFetcher` 协议里，`concept_snapshot` 任务直接调用实现类方法，协议形同虚设。
- `_call` 内部同时做了限速（`REQUEST_DELAY=0.5`）、重试（`RETRY_BACKOFF=(1,3)`）、限流识别（返回 `Exception` 对象）。
- 各方法带 `delay` 参数，给任务重试时放慢节奏用。

### 3.2 拆分

```python
# adapter/data/adata/client.py
class AdataClient:
    async def call(self, fn: Callable[[], Any]) -> Any:
        """to_thread 调用；返回 Exception 对象 → RateLimited；其它异常 → SourceUnavailable"""
```

- 限速和重试从 `_call` 移到横向装饰器（03），Client 只保留"返回 Exception 视为限流"这一条 adata 特有的识别逻辑。
- 去掉所有方法的 `delay` 参数。任务重试时的放慢由 `run_units` 的 `retry_delay` 负责（它在调用前 sleep），与现在效果一致。

```
adapter/data/adata/
  client.py        AdataClient
  concept.py       AdataConceptListAdapter、AdataConceptMembersAdapter、AdataStockConceptsAdapter、
                   AdataConceptIndexDailyAdapter、AdataConceptSnapshotAdapter、AdataConceptMinuteAdapter
```

所有 adata Adapter：`tool="adata"`、`origin="ths"`、`throttle_group="adata:ths"`。

## 4. pytdx（通达信）

- `PytdxClient`：保留现有连接管理（`_ensure_connected`、多 host 重连、`threading.Lock` 串行化）。
- `PytdxMinuteKlineAdapter`（`tool="pytdx"`、`origin="tdx"`、`throttle_group="tdx"`）：
  - `supports(p)` 返回 `is_supported(p.symbol)`，北交所返回 False（Gateway 跳过，以后接入支持北交所的源时自动生效），不再抛 `ValueError`。
  - `MinuteKlineBO` 移到 `application/port/data/tech.py`（它现在定义在 `fetcher/pytdx.py` 里，被实时接口引用，属于接口约束的一部分）。

```
adapter/data/pytdx/
  client.py        PytdxClient
  tech.py          PytdxMinuteKlineAdapter、PytdxKlineParser
```

## 6. 启动注册

```python
# adapter/data/setup.py
def setup_data() -> None:
    reg = get_data_port_registry()
    s = get_settings()

    adapters: list[DataPort] = []
    if s.TUSHARE_TOKEN:
        tushare = TushareClient(s.TUSHARE_TOKEN, pool_size=s.COLLECT_MAX_CONCURRENCY)
        adapters += [TushareDailyKlineAdapter(tushare), TushareMoneyflowAdapter(tushare), ...]
    else:
        logger.warning("TUSHARE_TOKEN 未配置，跳过 tushare 实现")
    adata = AdataClient()
    adapters += [AdataConceptListAdapter(adata), ...]
    adapters += [PytdxMinuteKlineAdapter(PytdxClient())]

    for a in adapters:
        reg.register(a, wrap=build_decorators)       # 见 03
```

- 某个 SDK 初始化失败（token 未配置、adata 未安装）时，只跳过这个 SDK 的实现并打 warning，不影响其他数据源。现在 `TushareFetcher.__init__` 抛错会导致整个注册失败。
- 新接入 akshare：新建 `adapter/data/akshare/`，写 Client + Adapter（继承已有 Port），在这里加一行注册。Port 和上层代码都不用改。
