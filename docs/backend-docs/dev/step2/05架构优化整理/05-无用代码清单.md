
### 2.2 `domain/kline/service/_legacy_init.py`

**位置**：`backend/src/domain/kline/service/_legacy_init.py`
**状态**：git status 标记存在，内容未知（推测为旧 `IndicatorCalculator` 导入路径的兼容 shim）。
**实质**：若 `IndicatorCalculator` 已迁出 `kline/service`，则 `_legacy_init.py` 是空壳。

**操作**：
```bash
# 1. 先确认无引用
grep -r "_legacy_init" backend/
# 2. 若 0 行引用，删除
rm backend/src/domain/kline/service/_legacy_init.py
```

### 2.3 空目录（git status 误报）

git status 标记以下目录"未跟踪"，实际磁盘不存在：
- `backend/src/infrastructure/adapter/akshare/`
- `backend/src/infrastructure/adapter/pytdx/`（不是 `fetcher/pytdx.py` 的目录）
- `backend/src/infrastructure/adapter/tushare/`（不是 `fetcher/tushare.py` 的目录）
- `backend/src/infrastructure/adapter/adata/`（不是 `fetcher/adata.py` 的目录）

**原因**：上一轮 DDD 重构时可能曾用 `git add -N` 标记了空目录，但实际从未创建。

**操作**：
```bash
git status | grep "^??"  # 列出所有未跟踪
# 如果只有这些目录，从 git 索引中移除（仅取消跟踪，磁盘不动）
git rm --cached -r backend/src/infrastructure/adapter/akshare
git rm --cached -r backend/src/infrastructure/adapter/pytdx
git rm --cached -r backend/src/infrastructure/adapter/tushare
git rm --cached -r backend/src/infrastructure/adapter/adata
```

### 2.4 `route/api/v1/` 重复文件

git status 显示以下 3 个文件重复出现：
- `route/api/v1/concept.py`
- `route/api/v1/collect_task.py`
- `route/api/v1/minute_kline.py`

**实际**：经过 `Get-ChildItem route/api/v1/*.py | Sort-Object Name` 验证，磁盘上每份只有 1 个文件。**这是 Windows 路径大小写不敏感导致的 glob 双重计数，不是文件重复**。

**操作**：无需操作。若 git status 显示错误，执行：
```bash
git update-index --refresh
```
