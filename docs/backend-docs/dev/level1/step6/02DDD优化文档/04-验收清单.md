# DDD 优化验收清单

> 本文档是 DDD 目录结构优化的最终验收依据。
> 每条 AC 给出"验证方法"和"通过标准"。

---

## 1. 验收矩阵

| 阶段 | 验收点 | 通过条件 | 验证方式 |
|:--|:--|:--|:--|
| 阶段 1：目录结构 | AC-1 ~ AC-4 | 目录符合方案 | 文件检查 |
| 阶段 2：转换方法 | AC-5 ~ AC-7 | 所有 `from_` 方法就位 | grep 扫描 |
| 阶段 3：业务验证 | AC-8 ~ AC-10 | 测试 + 运行时通过 | 自动化 |

---

## 2. 阶段 1：目录结构

### AC-1：domain/entities/ 存在

**验证命令**：

```bash
ls backend/src/contexts/market/domain/entities/
```

**预期输出**：

```
kline/  stock_info/  fin_top10_holders/  fin_top10_float/
fin_report/  fin_daily_basic/  cap_top_list/  cap_top_inst/
cap_moneyflow/  cap_margin/  cap_margin_detail/  cap_holder_num/
cap_block_trade/  base_suspend/  base_name_change/  base_adj_factor/
base_dividend/  panel/  mkt_calendar/  mkt_sector_daily/
mkt_market_daily/  mkt_index_member/
```

**通过**：目录数 = 22（不含 `__pycache__`）

---

### AC-2：每个 entity 子目录结构

**验证命令**：

```bash
ls backend/src/contexts/market/domain/entities/kline/
ls backend/src/contexts/market/domain/entities/panel/
```

**预期输出**：

```
kline/  → __init__.py  entity.py  vo.py  repository.py
panel/  → vo.py  repository.py  （无 entity.py）
```

**通过**：
- 完整聚合根（kline/stock_info）：3 个文件
- 无 VO 聚合根（fin_top10_holders）：2 个文件
- 无 Entity 聚合根（panel）：2 个文件（vo + repository）

---

### AC-3：domain/services/ 存在

**验证命令**：

```bash
ls backend/src/contexts/market/domain/services/
ls backend/src/contexts/concept/domain/services/
```

**预期输出**：

```
market/services/  → __init__.py  indicator_calculator.py  signal_detector.py  market_session.py
concept/services/ → concept_brief_service.py
```

**通过**：service 目录已重命名为 services

---

### AC-4：application/bo/ 存在且包含所有 BO

**验证命令**：

```bash
ls backend/src/contexts/market/application/bo/
ls backend/src/contexts/concept/application/bo/
```

**预期输出**：

```
market/bo/  → kline.py  stock_info.py  fin_top10_holders.py
            cap_moneyflow.py  base_dividend.py  base_suspend.py
            base_adj_factor.py  base_name_change.py  panel.py
            cap_margin.py  cap_margin_detail.py  ...
concept/bo/ → concept.py  concept_member.py
```

**通过**：
- 所有原 `domain/<name>/bo.py` 已迁移到 `application/bo/`
- 无遗漏 BO 文件

## 4. 阶段 3：业务验证

### AC-14：所有 import 路径已更新

**验证命令**：

```bash
# 查找仍引用旧路径的代码

grep -r "from contexts.market.domain.service\." backend/src/ --include="*.py"
grep -r "from contexts.concept.domain.service\." backend/src/ --include="*.py"
```

**预期输出**：空

**通过**：所有 import 已更新为新路径

---

### AC-15：循环导入测试

**验证命令**：

```bash
cd backend && python -c "from src.contexts.market.application.service.stock_info_service import StockInfoService"
cd backend && python -c "from src.contexts.concept.application.service.concept_service import ConceptService"
cd backend && python -c "from src.contexts.collect.application.service.collect_manage_service import CollectManageService"
```

**预期输出**：无 ImportError

**通过**：所有 context 可正常导入

---

**预期输出**：所有测试 PASSED

**通过**：100% 测试通过

**通过**：所有 API 路径保持不变

## 5. 综合验收

### AC-20：domain 层无外部依赖

**验证命令**：

```bash
# domain 层不应 import sqlalchemy / fastapi / pydantic
grep -r "import sqlalchemy" backend/src/contexts/*/domain/ --include="*.py"
grep -r "import fastapi" backend/src/contexts/*/domain/ --include="*.py"
grep -r "from pydantic" backend/src/contexts/*/domain/ --include="*.py"
```

**预期输出**：空（除 `domain/base.py` 等显式允许的）

**通过**：domain 层零外部依赖

---

### AC-21：application 层不依赖 infrastructure

**验证命令**：

```bash
grep -r "import infrastructure" backend/src/contexts/*/application/ --include="*.py"
grep -r "from.*infrastructure" backend/src/contexts/*/application/ --include="*.py"
```

**预期输出**：空

**通过**：application 层不直接依赖 infrastructure

---

### AC-22：context 之间通过 port 通信

**验证命令**：

```bash
# market 不应 import concept 的 domain
grep -r "from src.contexts.concept.domain" backend/src/contexts/market/ --include="*.py"

# 反之亦然
grep -r "from src.contexts.market.domain" backend/src/contexts/concept/ --include="*.py"
```

**预期输出**：空（context 之间仅通过 port 通信）

**通过**：DDD 严格边界得到保证

---

## 6. 性能与质量

### AC-23：导入时间不显著增加

**验证命令**：

```bash
cd backend && python -X importtime -c "from src.app.main import app" 2>&1 | tail -5
```

**预期输出**：导入时间增加 < 100ms

**通过**：目录结构调整未显著影响启动时间

---

### AC-24：测试覆盖率不下降

**验证命令**：

```bash
cd backend && pytest tests/ --cov=src/contexts --cov-report=term
```

**预期输出**：覆盖率 ≥ 优化前

**通过**：测试覆盖率保持或提升
