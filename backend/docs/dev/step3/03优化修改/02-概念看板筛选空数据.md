# 02 · 概念看板筛选"全部"以外没数据

## 1. 问题描述

**复现路径**：菜单 → 「实验性」→「概念大盘」→ 默认进入 → 显示"行业概念 8 / 主题概念 15 / ..."等多分组卡片（`type_filter=all`）。点 toolbar 的"行业概念"下拉 → 卡片区几乎只剩 1 组（"行业概念 N 个"），其他类型没了。

**用户反馈**："除了全部的情况下有显示部分数据其他情况没有"。

**期望**：选了某类型后，该类型的所有概念仍全部展示（不应该是空）。

---

## 2. 根因分析

### 2.1 数据流（前端 → 后端）

`ConceptBoard.vue` L106-122：

```ts
async function load() {
  loading.value = true
  try {
    const res = await getConceptBoard({
      type_filter: filters.value.type_filter,  // 'all' | 'industry' | ...
      sort_by: 'pct_change',
      order: 'desc',
      page: 1,
      page_size: 500,
    })
    boardItems.value = res.items
  } ...
}
```

- `type_filter=all` → 后端 SQL 跳过 WHERE 过滤 → 返回所有 390 个概念
- `type_filter=industry` → 后端 SQL `WHERE concept_type = 'industry'` → 只返 industry 类型

### 2.2 后端仓储逻辑 (`concept_repository.py` L474-478)

```python
if type_filter and type_filter != "all":
    stmt = stmt.where(ConceptsDB.concept_type == type_filter)
```

逻辑正确，**数据上没问题**。

### 2.3 前端 CardGrid 分组逻辑 (`ConceptCardGrid.vue` L63-77)

```ts
const grouped = computed(() =>
  TYPE_ORDER.map((t) => ({
    type: t,
    label: TYPE_LABELS[t],
    items: props.items
      .filter((i) => i.concept_type === t)   // ← 再次按类型过滤
      .sort((a, b) => (b.pct_change ?? -999) - (a.pct_change ?? -999)),
  })).filter((g) => g.items.length > 0),
)
```

**问题**：
- 后端已经按 type_filter 过滤过 → items 都是同一种 type（如全是 industry）
- 前端又把 items 按 type 再分一次组 → 只有 1 组有数据，其他 5 组空
- `.filter((g) => g.items.length > 0)` → 其他 5 组被隐藏
- **视觉结果**：只看到 "行业概念（120）"，下面平铺 120 个卡片
- 用户期望：选了"行业概念"后，**只看到行业概念的卡片**（如当前一样），但要更直白地显示
- **真正的问题**：当 type_filter≠all 时，**卡片的分组标题冗余**（标题"行业概念（120）"下面是全是 industry 的卡片），用户可能误以为分组标题没生效或数据缺失

### 2.4 同步组件：`ConceptRankBoard.vue`

**未读源码前需确认**：左侧的涨幅榜组件，是否也有 type_filter 联动？如有，是否只显示同类型的 top20？

预期：它应该**接收当前 items**，按 pct_change 排序取 top20（已筛选），这是设计预期。

## 3. 修复方案

### 3.1 方案对比

`★ 不确定点 Q2 ─────────────────────────────────────`
- 方案 A：筛单 type 时，卡片区去掉分组标题，平铺展示（推荐）
- 方案 B：保留分组，但只对 type 匹配的那 1 组高亮，其他组彻底隐藏（视觉差异小）
- 方案 C：筛某 type 时切换视图为"概念列表"模式（类似股票列表），不再用卡片网格
- `─────────────────────────────────────────────────`

### 3.2 推荐方案 A（最简单、最符合直觉）

**改动文件**：`frontend/src/views/concept-board/components/ConceptCardGrid.vue`

**逻辑**：
- 当 props.items 中只有 1 种 concept_type（即用户选了某 type）→ 直接平铺，不显示分组标题
- 当 props.items 中有多种 type（默认 all）→ 按原逻辑分组

**伪代码**：

```ts
const grouped = computed(() => {
  // 推断是否单 type（数据流层面 type 已确定）
  const typeSet = new Set(props.items.map((i) => i.concept_type))
  if (typeSet.size <= 1) {
    // 单类型模式：直接平铺,顶部不再重复显示分组标题
    const t = props.items[0]?.concept_type ?? 'all'
    return [{
      type: t,
      label: TYPE_LABELS[t] ?? '全部',
      items: [...props.items]
        .sort((a, b) => (b.pct_change ?? -999) - (a.pct_change ?? -999)),
    }]
  }
  // 多类型模式:保持原分组逻辑
  return TYPE_ORDER.map((t) => ({
    type: t,
    label: TYPE_LABELS[t],
    items: props.items
      .filter((i) => i.concept_type === t)
      .sort((a, b) => (b.pct_change ?? -999) - (a.pct_change ?? -999)),
  })).filter((g) => g.items.length > 0)
})
```

模板同步调整（伪代码）：

```vue
<!-- 当只有一组时,隐藏分组标题,直接平铺 -->
<template v-for="(group, gi) in grouped" :key="group.type">
  <div class="type-group">
    <!-- 多类型时显示标题,单类型时隐藏 -->
    <div v-if="grouped.length > 1" class="type-group__title">
      {{ group.label }}（{{ group.items.length }}）
    </div>
    <div class="type-grid">
      <div v-for="item in group.items.slice(0, 8)" ...>
        ...
      </div>
    </div>
  </div>
</template>
```

**说明**：当用户筛某 type（如 "行业概念"）后，items 全部是 industry：
- `grouped.length = 1`，`group.items.length = 120`
- 模板里 `grouped.length > 1` 为 false，**不显示 "行业概念（120）" 标题**
- 下面直接平铺 120 个卡片，每组前 8 个

**注意点**：
- 当前模板有 `.slice(0, 8)` 限制每组最多展示 8 个 → 选中 type 后可能看到不全
- 如果想要选中 type 后看全部，需要去掉 `.slice(0, 8)` 或者改 slice 为 `props.items.length`
- 这是**又一个不确定点**（Q2-b）

### 3.3 备选方案 B

保留分组 UI 不变，但选中某 type 后，**最外层弹一个 el-alert 提示**：当前已筛某类型，统计当前展示 N 个。

仅在前端改动小，未触及 `ConceptCardGrid.vue`。
