# 操作池 - 数据库设计

> 本文档定义"操作池"模块的三张核心表的结构、索引、约束和迁移方案。
> **策略**：全量覆盖，不考虑兼容旧数据。

---

## 1. 表清单

| # | 表名 | 作用 | 表数量级 |
|---|------|------|---------|
| 1 | `stock_pools` | 操作池主表（池元信息） | < 1000 |
| 2 | `stock_pool_members` | 池成员关联表 | < 100万 |
| 3 | `pool_operations` | 池操作记录表 | < 10万 |

## 2. 表结构

### 2.1 `stock_pools`（操作池主表）

#### 建表 SQL

```sql
CREATE TABLE stock_pools (
    -- 主键
    id              SERIAL          PRIMARY KEY,
    
    -- 业务字段
    name            VARCHAR(64)     NOT NULL,
    description     VARCHAR(255),
    pool_type       VARCHAR(32)     NOT NULL DEFAULT 'custom',
    
    -- 展示字段
    color           VARCHAR(16),
    icon            VARCHAR(32),
    sort_order      INTEGER         NOT NULL DEFAULT 0,
    
    -- 标记
    is_default      BOOLEAN         NOT NULL DEFAULT FALSE,
    is_archived     BOOLEAN         NOT NULL DEFAULT FALSE,
    
    -- 预留（未来多用户/分享）
    owner_id        INTEGER,                -- v1 不使用
    share_token     VARCHAR(64),            -- v1 不使用
    
    -- 时间
    created_at      TIMESTAMP       NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP       NOT NULL DEFAULT NOW()
);

-- 索引
CREATE INDEX ix_stock_pools_pool_type  ON stock_pools (pool_type);
CREATE INDEX ix_stock_pools_is_default ON stock_pools (is_default);
CREATE INDEX ix_stock_pools_owner_id   ON stock_pools (owner_id);
CREATE INDEX ix_stock_pools_updated_at ON stock_pools (updated_at DESC);

-- 注释
COMMENT ON TABLE  stock_pools IS '操作池主表（元信息）';
COMMENT ON COLUMN stock_pools.name IS '池名称';
COMMENT ON COLUMN stock_pools.pool_type IS '池类型: watchlist/industry/strategy/custom';
COMMENT ON COLUMN stock_pools.color IS '前端展示颜色 HEX，如 #FF5722';
COMMENT ON COLUMN stock_pools.icon IS '前端展示 emoji 或 icon 名';
COMMENT ON COLUMN stock_pools.sort_order IS '池列表展示顺序';
COMMENT ON COLUMN stock_pools.is_default IS '是否默认池（系统预置，不可删）';
COMMENT ON COLUMN stock_pools.is_archived IS '是否归档（隐藏但不删）';
COMMENT ON COLUMN stock_pools.owner_id IS '所属用户 ID（v1 暂未启用）';
COMMENT ON COLUMN stock_pools.share_token IS '分享 token（v1 暂未启用）';
```

#### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | SERIAL | ✅ | 主键 |
| `name` | VARCHAR(64) | ✅ | 池名称，用户可重命名 |
| `description` | VARCHAR(255) | ❌ | 池描述 |
| `pool_type` | VARCHAR(32) | ✅ | `watchlist`（自选）/ `industry`（行业）/ `strategy`（策略）/ `custom`（自定义） |
| `color` | VARCHAR(16) | ❌ | 前端展示用颜色，如 `#FF5722` |
| `icon` | VARCHAR(32) | ❌ | 前端展示图标，如 `🔥` 或 `star` |
| `sort_order` | INTEGER | ✅ | 列表展示顺序（小者在前，默认 0） |
| `is_default` | BOOLEAN | ✅ | 默认池标记（系统预置 1 个） |
| `is_archived` | BOOLEAN | ✅ | 归档标记（软删除） |
| `owner_id` | INTEGER | ❌ | 预留多用户 |
| `share_token` | VARCHAR(64) | ❌ | 预留分享 |
| `created_at` | TIMESTAMP | ✅ | 创建时间 |
| `updated_at` | TIMESTAMP | ✅ | 更新时间（自动维护） |

#### 约束

| 约束 | 说明 |
|------|------|
| 默认池不可删 | `is_default=TRUE` 时禁止 DELETE |
| 默认池数量约束 | 数据库层不强约束，应用层校验 `COUNT(*) WHERE is_default=TRUE <= 1` |
| `pool_type` 取值 | 应用层枚举校验（数据库用 VARCHAR 灵活） |

### 2.2 `stock_pool_members`（池成员关联表）

#### 建表 SQL

```sql
CREATE TABLE stock_pool_members (
    -- 联合主键
    pool_id         INTEGER         NOT NULL,
    symbol          VARCHAR(10)     NOT NULL,
    
    -- 业务字段
    memo            VARCHAR(255),
    sort_order      INTEGER         NOT NULL DEFAULT 0,
    
    -- 时间
    added_at        TIMESTAMP       NOT NULL DEFAULT NOW(),
    
    PRIMARY KEY (pool_id, symbol),
    FOREIGN KEY (pool_id) REFERENCES stock_pools(id) ON DELETE CASCADE
);

-- 反向索引：哪些池包含某只 symbol
CREATE INDEX ix_pool_members_symbol      ON stock_pool_members (symbol);
CREATE INDEX ix_pool_members_pool_sort   ON stock_pool_members (pool_id, sort_order);

-- 注释
COMMENT ON TABLE  stock_pool_members IS '操作池成员关联表';
COMMENT ON COLUMN stock_pool_members.memo IS '用户对该成员的备注';
COMMENT ON COLUMN stock_pool_members.sort_order IS '池内排序';
COMMENT ON COLUMN stock_pool_members.added_at IS '加入时间';
```

#### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pool_id` | INTEGER | ✅ | FK → `stock_pools.id`，CASCADE 删除 |
| `symbol` | VARCHAR(10) | ✅ | 6 位股票代码 |
| `memo` | VARCHAR(255) | ❌ | 用户备注 |
| `sort_order` | INTEGER | ✅ | 池内排序 |
| `added_at` | TIMESTAMP | ✅ | 加入时间 |

#### 关于 `symbol` 的外键

**决策**：**不建物理外键到 `stock_infos.symbol`**。

**理由**：
1. 业务上允许池包含**退市 / 暂停**股票
2. `stock_infos.symbol` 是 UNIQUE 但不是主键，外键要指向 PK 才规范
3. 退市股票可能被删除，但池成员仍要保留
4. 应用层查询时通过 `LEFT JOIN stock_infos` 校验存在性

**反范式代价**：池成员中的 `symbol` 可能指向已不存在的股票
**应用层补偿**：查询时 `JOIN stock_infos` 并标记 `is_valid`

### 2.3 `pool_operations`（池操作记录表）

#### 建表 SQL

```sql
CREATE TABLE pool_operations (
    -- 主键
    id              SERIAL          PRIMARY KEY,
    
    -- 关联
    pool_id         INTEGER         NOT NULL,
    
    -- 操作元信息
    operation_type  VARCHAR(32)     NOT NULL,
    status          VARCHAR(16)     NOT NULL DEFAULT 'pending',
    
    -- 参数与结果（JSONB 灵活存储）
    params          JSONB           NOT NULL DEFAULT '{}'::jsonb,
    result_summary  JSONB,
    progress        JSONB           NOT NULL DEFAULT '{"done":0,"total":0,"failed":0}'::jsonb,
    
    -- 错误信息
    error_message   TEXT,
    
    -- 时间
    started_at      TIMESTAMP,
    finished_at     TIMESTAMP,
    created_at      TIMESTAMP       NOT NULL DEFAULT NOW(),
    
    FOREIGN KEY (pool_id) REFERENCES stock_pools(id) ON DELETE SET NULL
);

-- 索引
CREATE INDEX ix_pool_operations_pool_id     ON pool_operations (pool_id);
CREATE INDEX ix_pool_operations_status      ON pool_operations (status);
CREATE INDEX ix_pool_operations_type_status ON pool_operations (operation_type, status);
CREATE INDEX ix_pool_operations_created_at  ON pool_operations (created_at DESC);
CREATE INDEX ix_pool_operations_pool_time   ON pool_operations (pool_id, created_at DESC);

-- 注释
COMMENT ON TABLE  pool_operations IS '池操作记录表';
COMMENT ON COLUMN pool_operations.operation_type IS '操作类型: kline_collect / news_fetch / factor_calc';
COMMENT ON COLUMN pool_operations.status IS '状态: pending/running/success/partial/failed/cancelled';
COMMENT ON COLUMN pool_operations.params IS '操作参数（如 {days: 365, source: "tushare"}）';
COMMENT ON COLUMN pool_operations.result_summary IS '结果摘要';
COMMENT ON COLUMN pool_operations.progress IS '进度 {done, total, failed}';
COMMENT ON COLUMN pool_operations.error_message IS '失败原因';
```

#### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | SERIAL | ✅ | 主键 |
| `pool_id` | INTEGER | ✅ | FK → `stock_pools.id`，池删除时置 NULL（保留记录） |
| `operation_type` | VARCHAR(32) | ✅ | 操作类型枚举 |
| `status` | VARCHAR(16) | ✅ | 状态枚举 |
| `params` | JSONB | ✅ | 操作参数，结构按 `operation_type` 而定 |
| `result_summary` | JSONB | ❌ | 结果摘要（如成功 N 条，失败 M 条） |
| `progress` | JSONB | ✅ | 进度 `{done: int, total: int, failed: int}` |
| `error_message` | TEXT | ❌ | 失败原因 |
| `started_at` | TIMESTAMP | ❌ | 实际开始执行时间 |
| `finished_at` | TIMESTAMP | ❌ | 完成时间 |
| `created_at` | TIMESTAMP | ✅ | 记录创建时间 |

#### 状态枚举（`status`）

| 值 | 含义 | 触发条件 |
|----|------|---------|
| `pending` | 已创建未开始 | 写入记录后、派发任务前 |
| `running` | 执行中 | 任务开始第一只 symbol |
| `success` | 全部成功 | `failed == 0 && done == total` |
| `partial` | 部分失败 | `failed > 0 && done == total` |
| `failed` | 失败 | 任务未跑起来（如派发失败） |
| `cancelled` | 已取消 | 用户主动取消 |

#### `operation_type` 枚举（v1）

| 值 | 说明 | 实现阶段 |
|----|------|---------|
| `kline_collect` | 采集K线 | ✅ P0 |
| `news_fetch` | 获取新闻 | ⏳ P2 |
| `factor_calc` | 因子计算 | ⏳ P2 |

#### `params` JSONB 结构（按 operation_type）

**kline_collect**：
```json
{
  "days": 365,
  "start_date": "2025-09-15",
  "end_date": null,
  "source": "akshare"
}
```

**news_fetch**：
```json
{
  "days": 7,
  "source": "akshare"
}
```

#### `result_summary` JSONB 结构

```json
{
  "total": 30,
  "saved": 28,
  "skipped": 1,
  "failed": 1,
  "details": [
    { "symbol": "000001", "status": "success", "count": 365 },
    { "symbol": "000002", "status": "skipped", "message": "no data" },
    { "symbol": "000003", "status": "failed", "message": "network error" }
  ]
}
```

## 4. 数据量估算

| 表 | 单条大小 | 估算行数 | 估算占用 |

## 5. 关键查询模式与索引覆盖

### 5.1 池列表（按更新时间倒序）

```sql
SELECT * FROM stock_pools
WHERE is_archived = FALSE
ORDER BY is_default DESC, sort_order ASC, updated_at DESC
LIMIT 20 OFFSET 0;
```
**索引**：`updated_at DESC` + 应用层过滤

### 5.2 池成员列表（带股票信息）

```sql
SELECT m.symbol, m.memo, m.sort_order, m.added_at,
       s.name, s.industry, s.market, s.exchange
FROM stock_pool_members m
LEFT JOIN stock_infos s ON s.symbol = m.symbol
WHERE m.pool_id = $1
ORDER BY m.sort_order ASC, m.added_at DESC
LIMIT 50 OFFSET 0;
```
**索引**：`pool_id, sort_order`

### 5.3 反向查询：某 symbol 在哪些池

```sql
SELECT p.id, p.name, p.pool_type, p.icon, p.color
FROM stock_pools p
JOIN stock_pool_members m ON m.pool_id = p.id
WHERE m.symbol = $1 AND p.is_archived = FALSE;
```
**索引**：`symbol`

### 5.4 池操作历史

```sql
SELECT * FROM pool_operations
WHERE pool_id = $1
ORDER BY created_at DESC
LIMIT 20;
```
**索引**：`pool_id, created_at DESC`

### 5.5 单只股票在某池的状态

```sql
SELECT op.id, op.operation_type, op.status, op.created_at
FROM pool_operations op
JOIN jsonb_array_elements(op.result_summary->'details') d ON TRUE
WHERE op.pool_id = $1 AND d->>'symbol' = $2
ORDER BY op.created_at DESC;
```
**索引**：JSONB GIN 索引（视实际查询频率可选建）

## 6. 迁移策略

### 6.1 dbmate / Alembic 迁移文件

新建 migration：

```bash

alembic revision --autogenerate -m "add_stock_pools_tables"
```

### 6.2 手动建表 SQL（开发环境直接执行）

如果项目用 `Base.metadata.create_all()` 自动建表（参考 `main.py` 的 lifespan），则：
- 在 `infrastructure/database/models/pool.py` 中定义 ORM 类即可
- 应用启动时自动建表
- 但要注意：`create_all` 不会处理外键依赖顺序，需要在 `pool.py` 中 import 依赖

### 6.3 应用启动时的初始化

```python
# 在 main.py 的 lifespan 中添加
async def _init_stock_pools(conn):
    """首次启动：创建系统预置池"""
    result = await conn.execute(text(
        "SELECT COUNT(*) FROM stock_pools WHERE is_default = TRUE"
    ))
    count = result.scalar()
    if count == 0:
        await conn.execute(text("""
            INSERT INTO stock_pools (name, pool_type, is_default, icon, color)
            VALUES ('我的自选', 'watchlist', TRUE, '⭐', '#FFB800')
        """))
```

## 7. 数据完整性保障

### 7.1 应用层校验

| 校验项 | 实现位置 |
|--------|---------|
| 默认池不可删 | `StockPoolAppService.delete_pool` 检查 `is_default` |
| 默认池不可改名 | 同上 |
| 池成员 symbol 存在性 | 添加前校验 `StockInfoRepo.find_by_symbol` |
| 删除股票时级联清理 | `StockService.delete_stock` 同步清理 `stock_pool_members` |
| 操作任务唯一性 | 同一 pool 同时只能有一个 running 的 `kline_collect` |

### 7.2 数据库层兜底

| 兜底项 | 实现 |
|--------|------|
| CASCADE 删除成员 | `stock_pool_members.pool_id` FK |
| 操作记录保留 | `pool_operations.pool_id` FK 用 `ON DELETE SET NULL` |
| 进度 JSONB 结构 | 应用层序列化保证 |
| 状态枚举 | 应用层枚举，DB 用 VARCHAR 灵活 |

## 8. 备份与归档建议

| 建议 | 理由 |
|------|------|
| `pool_operations` 保留 90 天后可清理 | 避免历史数据无限增长 |
| 删除池时同时归档 `pool_operations` | 池删除 SET NULL，但记录仍占空间 |
| 备份策略：每日 pg_dump | 与现有备份一致 |
| 软删除（`is_archived=TRUE`） | 默认 30 天后硬删除 |

**v1 暂不实现归档 / 清理**，P2 阶段考虑。
