# 02 配置表升级 — `sys_data_ports` 精简 + 加 `facet` 字段

> 阶段 D1。本文做表结构迁移：
> 1. **删** `output_schema` / `table_config` / `output_schema_hash`
> 2. **加** `facet` 字段（5 个面之一）
> 3. 表名 / 库名 / 前缀的最终决定见 [`10-分库与表结构.md`](10-分库与表结构.md)

## 1. 迁移 DDL（PostgreSQL）

```sql
-- ★ 删掉 3 个字段（不再需要）
ALTER TABLE sys_data_ports
    DROP COLUMN IF EXISTS output_schema,
    DROP COLUMN IF EXISTS table_config,
    DROP COLUMN IF EXISTS output_schema_hash;

-- ★ 新增 facet 字段（5 个面：tech / capital / fundamental / news / sentiment）
ALTER TABLE sys_data_ports
    ADD COLUMN facet VARCHAR(16) NOT NULL DEFAULT 'fundamental'
        COMMENT 'tech / capital / fundamental / news / sentiment';

-- 最终结构
ALTER TABLE sys_data_ports
    MODIFY COLUMN name         VARCHAR(64)  PRIMARY KEY,     -- 注：MySQL 语法，PostgreSQL 改用 ALTER TABLE
    MODIFY COLUMN label        VARCHAR(128) NOT NULL,
    MODIFY COLUMN source       VARCHAR(32)  NOT NULL COMMENT 'tushare / adata',
    MODIFY COLUMN unit         VARCHAR(16)  NOT NULL COMMENT 'trade_date / symbol',
    MODIFY COLUMN kind         VARCHAR(16)  NOT NULL COMMENT 'batch / realtime',
    MODIFY COLUMN params_schema JSON        NOT NULL COMMENT '入参 JSON Schema',
    MODIFY COLUMN upsert_mode  VARCHAR(16)  NOT NULL DEFAULT 'by_unique'
        COMMENT 'by_unique | on_conflict_do_nothing | insert_only';
```

> **PostgreSQL 真实 DDL**（建表时使用，MySQL 语法仅作示意）：

```sql
CREATE TABLE sys_data_ports (
    name           VARCHAR(64)  PRIMARY KEY,
    label          VARCHAR(128) NOT NULL,
    source         VARCHAR(32)  NOT NULL,
    unit           VARCHAR(16)  NOT NULL,
    kind           VARCHAR(16)  NOT NULL,
    facet          VARCHAR(16)  NOT NULL DEFAULT 'fundamental',
    params_schema  JSON         NOT NULL,
    upsert_mode    VARCHAR(16)  NOT NULL DEFAULT 'by_unique'
);

-- 老表精简：先删 3 字段，再加 facet
ALTER TABLE sys_data_ports
    DROP COLUMN IF EXISTS output_schema,
    DROP COLUMN IF EXISTS table_config,
    DROP COLUMN IF EXISTS output_schema_hash;

ALTER TABLE sys_data_ports
    ADD COLUMN IF NOT EXISTS facet VARCHAR(16) NOT NULL DEFAULT 'fundamental';

-- 加 facet 索引（前端按面分组用）
CREATE INDEX IF NOT EXISTS ix_sys_data_ports_facet ON sys_data_ports (facet);
```

## 2. 最终字段定义

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `name` | `VARCHAR(64)` PK | port 唯一标识，如 `capital_moneyflow` |
| `label` | `VARCHAR(128)` | 前端显示名，如 `资金流向` |
| `source` | `VARCHAR(32)` | 数据源：`tushare` / `adata` |
| `unit` | `VARCHAR(16)` | 增量单元类型：`trade_date` / `symbol` |
| `kind` | `VARCHAR(16)` | 采集类型：`batch` / `realtime` |
| **`facet`** | `VARCHAR(16)` | **5 个面**：`tech` / `capital` / `fundamental` / `news` / `sentiment` |
| `params_schema` | `JSON` | 入参定义（沿用 step5 格式，如 `{"trade_date": {"type": "string"}}`） |
| `upsert_mode` | `VARCHAR(16)` | 沿用 step5 约定，见下表 |

> ⚠️ **表前缀 vs facet 字段值**：
> - 表前缀（建表用）：`capital_` / `fundamental_` / `tech_` / `news_` / `sentiment_`（**带下划线**）
> - facet 字段值（sys_data_ports.facet）：`capital` / `fundamental` / `tech` / `news` / `sentiment`（**不带下划线**）
> 详见 [`10-分库与表结构.md §8`](10-分库与表结构.md)。

`upsert_mode` 取值（PostgreSQL 语义）：

| 值 | 含义 | PostgreSQL 语法 |
| :-- | :-- | :-- |
| `by_unique`（默认） | 按主键覆盖非主键列 | `INSERT ... ON CONFLICT (pk) DO UPDATE SET ...` |
| `on_conflict_do_nothing` | 主键撞键直接跳过 | `INSERT ... ON CONFLICT (pk) DO NOTHING` |
| `insert_only` | 纯 INSERT，撞键报错 | `INSERT ...`（不写 ON CONFLICT） |

## 3. 出参不再需要配置

> **核心变化**：`output_schema` / `table_config` 字段**全部删除**。

出参的来源是采集时用户所选的**目标表**（`INFORMATION_SCHEMA`）：

```
用户选表（前端从 INFORMATION_SCHEMA.TABLES 拉表列表）
  │
  ▼
后端查 INFORMATION_SCHEMA.COLUMNS 得出参字段
  │
  ▼
第三方返回字段 ⊆ 表列？  → 通过
  └─ 不通过 → 抛错返回前端
```

好处：
- **不可能字段漂移**：字段名以数据库为准，不以 JSON 配置为准
- **不需要 seed output_schema**：删了 14 条 JSON，运维直接建表即可
- **加新数据源 = 建 1 张表 + 1 条 `sys_data_ports`**：不再需要写字段定义

## 7. 启动期行为

`PortCatalog.load()` 启动时：
- 只读 `sys_data_ports` 的 name / label / source / unit / kind / **facet** / params_schema / upsert_mode
- **不查 DDL**，**不校验表存在**
- 表存在性在**采集时**由 `resolve_table_schema()` 校验

如果表不存在：
- `resolve_table_schema()` 抛 `PortSchemaMismatchError`
- 采集任务 fail，返回友好错误给前端
- **不影响应用启动**

## 8. 新增 API 端点

前端"选表"需要可用的表列表：

```
GET /collect/tables
```

**PostgreSQL 实现**：

```python
@router.get("/tables")
async def list_tables():
    """从 INFORMATION_SCHEMA 拉表列表供前端选表（采集库）"""
    async with engine.begin() as conn:
        rows = await conn.execute(text("""
            SELECT TABLE_NAME, TABLE_COMMENT
            FROM INFORMATION_SCHEMA.TABLES
            WHERE TABLE_SCHEMA = current_schema()
              AND TABLE_NAME NOT LIKE 'sys_%'      -- 排除元数据表
              AND TABLE_NAME NOT LIKE 'pg_%'        -- 排除系统表
            ORDER BY TABLE_NAME
        """))
    return {"tables": [dict(r._mapping) for r in rows]}
```

> **注意**：双库后，采集库是 `raw_data_db`，业务库是 `attribution_db`。
> `/collect/tables` 应该查 `raw_data_db` 而不是 `attribution_db`——因为选表是给采集用的。
> 详见 [`10-分库与表结构.md §7`](10-分库与表结构.md)。
