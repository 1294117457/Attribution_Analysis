# 转换方法规范（`from_` 类方法）

> 本文档定义 BO / Entity / VO / Model / DTO 之间转换的"类方法"规范。
> 替代原先的 `Converter` 目录，把转换逻辑分散到各自的类型定义中。

---

## 1. 核心原则

### 1.1 转换流向

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          转换流向                                        │
│                                                                         │
│   ┌──────┐                                                              │
│   │ Port │  (数据源抽象)                                                  │
│   └──┬───┘                                                              │
│      ↓                                                                 │
│   ┌──────┐         from_entity         ┌────────┐                       │
│   │  BO  │  ─────────────────────────→ │  DTO   │  → HTTP Response      │
│   │      │  ←───────────────────────── │        │                       │
│   └──────┘         to_entity            └────────┘                       │
│      ↑                                                                 │
│      │ from_bo                                                          │
│   ┌──────┐                                                              │
│   │Entity│  ← from_db (model.to_entity)                                │
│   └──┬───┘                                                              │
│      ↑                                                                 │
│      │ from_entity                                                      │
│   ┌──────┐                                                              │
│   │ Model│ (ORM)                                                        │
│   └──────┘                                                              │
│      ↑                                                                 │
│      │ SELECT/UPSERT                                                    │
│   ┌──────┐                                                              │
│   │  DB  │                                                              │
│   └──────┘                                                              │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 转换方法位置

| 类型 | 拥有的类方法 | 调用方 | 理由 |
|:--|:--|:--|:--|
| **Entity** | `from_bo(cls, bo)` | Application Service | Domain 接受 Application 的输入（依赖倒置） |
| **BO** | `from_entity(cls, entity)` | Application Service | Application 接受 Domain 的输出 |
| **VO** | `from_entity(cls, entity)` / `from_dict(cls, dict)` | Application Service | 投影构造（多次复用） |
| **Model** | `from_entity(cls, entity)` + `to_entity(self) -> Entity` | Infrastructure | 双向转换都在持久化层 |
| **DTO** | `from_entity(cls, entity)` | Interface | Interface 接受 Domain 的输出 |

### 1.3 设计原则

1. **对称性**：`from_X` 必须有对应的 `to_X` 或反过来有 `from_Y`
2. **单向依赖**：BO 依赖 Entity，Entity 可以依赖 BO（但 BO 是 application 层，Entity 是 domain 层——这是允许的"依赖倒置"）
3. **避免循环导入**：使用 `from __future__ import annotations` + `TYPE_CHECKING`
4. **不可变构造**：类方法返回新对象，不修改入参
5. **可空字段**：使用 `Optional[T]`，转换时显式处理

## 2. Entity 的 `from_bo`

### 2.1 定义位置

```python
# contexts/market/domain/entities/kline/entity.py
from __future__ import annotations
from dataclasses import dataclass
from datetime import date
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from contexts.market.application.bo.kline import KlineBO

@dataclass
class Kline(AggregateRoot):
    """K线 聚合根"""
    id: int
    symbol: str
    trade_date: date
    open: float
    high: float
    low: float
    close: float
    volume: int
    
    @classmethod
    def from_bo(cls, bo: "KlineBO") -> "Kline":
        """从 BO 构造 Entity
        
        用于：
        - ApplicationService 接收 BO 后构造 Entity
        - 测试时快速构造
        """
        return cls(
            id=bo.id,
            symbol=bo.symbol,
            trade_date=bo.trade_date,
            open=bo.open,
            high=bo.high,
            low=bo.low,
            close=bo.close,
            volume=bo.volume,
        )
```

### 2.2 何时使用

- ApplicationService 从外部（HTTP / 调度 / MQ）接收到 BO，需要进入 Domain 层做业务规则
- 单元测试中需要快速构造 Entity

### 2.3 反例

```python
# ❌ Entity 接受 DTO（违反依赖方向）
@classmethod
def from_dto(cls, dto: KlineResponseDTO): ...

# ❌ Entity 接受 ORM Model（Domain 不应依赖 Infrastructure）
@classmethod
def from_model(cls, model: KlineDB): ...
```

## 3. BO 的 `from_entity`

### 3.1 定义位置

```python
# contexts/market/application/bo/kline.py
from __future__ import annotations
from pydantic import BaseModel, Field
from datetime import date
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from contexts.market.domain.entities.kline.entity import Kline

class KlineBO(BaseModel):
    """K线 BO（应用层数据载体）"""
    id: int
    symbol: str = Field(..., max_length=10)
    trade_date: date
    open: float
    high: float
    low: float
    close: float
    volume: int
    
    @classmethod
    def from_entity(cls, entity: "Kline") -> "KlineBO":
        """从 Entity 构造 BO
        
        用于：
        - ApplicationService 从 Domain 取出 Entity 后构造 BO
        - 跨层传递（Entity → BO）
        """
        return cls(
            id=entity.id,
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            open=entity.open,
            high=entity.high,
            low=entity.low,
            close=entity.close,
            volume=entity.volume,
        )
```

### 3.2 何时使用

- ApplicationService 从 Repository 取出 Entity，组装成 BO 返回给上层
- BO 跨层传递时（Application → Interface）

### 3.3 BO 与 Entity 字段差异

BO 可以包含一些 Entity 没有的字段（如计算字段、外部数据）：

```python
class KlineBO(BaseModel):
    # ... Entity 字段
    id: int
    symbol: str
    
    # 额外字段：BO 独有
    industry: Optional[str] = None       # 从其他 context 拼装
    change_pct: Optional[float] = None   # 计算字段
    is_limit_up: Optional[bool] = None   # 业务标记
    
    @classmethod
    def from_entity(
        cls, 
        entity: Kline, 
        industry: Optional[str] = None,
        change_pct: Optional[float] = None,
        is_limit_up: Optional[bool] = None,
    ) -> "KlineBO":
        return cls(
            id=entity.id,
            symbol=entity.symbol,
            industry=industry,
            change_pct=change_pct,
            is_limit_up=is_limit_up,
        )
```

## 4. VO 的 `from_entity` / `from_dict`

### 4.1 定义位置

```python
# contexts/market/domain/entities/kline/vo.py
from __future__ import annotations
from dataclasses import dataclass
from datetime import date
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from contexts.market.domain.entities.kline.entity import Kline

@dataclass(frozen=True)
class KlineBriefVO:
    """K线简略投影（用于列表展示）"""
    symbol: str
    trade_date: date
    close: float
    
    @classmethod
    def from_entity(cls, entity: "Kline") -> "KlineBriefVO":
        """从 Entity 构造投影"""
        return cls(
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            close=entity.close,
        )
    
    @classmethod
    def from_dict(cls, data: dict) -> "KlineBriefVO":
        """从 dict 构造投影（如直接查询结果）"""
        return cls(
            symbol=data["symbol"],
            trade_date=data["trade_date"],
            close=data["close"],
        )

@dataclass(frozen=True)
class KlineDetailVO:
    """K线详细投影"""
    symbol: str
    trade_date: date
    open: float
    high: float
    low: float
    close: float
    volume: int
    
    @classmethod
    def from_entity(cls, entity: "Kline") -> "KlineDetailVO":
        return cls(
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            open=entity.open,
            high=entity.high,
            low=entity.low,
            close=entity.close,
            volume=entity.volume,
        )
```

### 4.2 VO 与 BO 的区别

| 维度 | VO | BO |
|:--|:--|:--|
| 依赖层 | domain（零外部依赖） | application（依赖 pydantic） |
| 主要用途 | 投影 / 内部计算 | 跨层数据载体 |
| 是否可序列化 | 可（dataclass） | 强（pydantic 校验） |
| 修改频率 | 稳定 | 多变（拼装业务字段） |

## 5. Model 的 `from_entity` / `to_entity`

### 5.1 定义位置

```python
# contexts/market/infrastructure/persistence/models/tech_kline.py
from __future__ import annotations
from sqlalchemy import Column, Integer, String, Date, Float
from contexts.shared.infrastructure.persistence.connection import Base
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from contexts.market.domain.entities.kline.entity import Kline

class KlineDB(Base):
    """K线 ORM 模型"""
    __tablename__ = "tech_kline_dailys"
    
    id = Column(Integer, primary_key=True, autoincrement=True)
    symbol = Column(String(10), nullable=False, index=True)
    trade_date = Column(Date, nullable=False, index=True)
    open = Column(Float, nullable=False)
    high = Column(Float, nullable=False)
    low = Column(Float, nullable=False)
    close = Column(Float, nullable=False)
    volume = Column(Integer, nullable=False)
    
    @classmethod
    def from_entity(cls, entity: "Kline") -> "KlineDB":
        """从 Entity 构造 ORM Model
        
        用于：
        - Repository.save() 时 Entity → Model
        - Repository.update() 时
        """
        return cls(
            id=entity.id,
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            open=entity.open,
            high=entity.high,
            low=entity.low,
            close=entity.close,
            volume=entity.volume,
        )
    
    def to_entity(self) -> "Kline":
        """从 ORM Model 构造 Entity
        
        用于：
        - Repository.find_by_id() 时 Model → Entity
        - Repository.list() 时
        """
        return Kline(
            id=self.id,
            symbol=self.symbol,
            trade_date=self.trade_date,
            open=self.open,
            high=self.high,
            low=self.low,
            close=self.close,
            volume=self.volume,
        )
```

### 5.2 双向转换

| 方向 | 方法 | 调用方 |
|:--|:--|:--|
| Entity → Model | `KlineDB.from_entity(entity)` | Repository.save() / update() |
| Model → Entity | `model.to_entity()` | Repository.find() / list() |

### 5.3 Model 与 DB Schema 的差异

Model 字段可以与 DB 字段不同（如加计算字段、聚合字段）：

```python
class KlineDB(Base):
    # ... DB 字段
    
    # 额外的 ORM 字段（如聚合查询字段）
    avg_close_20d = Column(Float)  # 20日均线（计算列）
    
    def to_entity_with_indicator(self) -> Kline:
        return Kline(
            id=self.id,
            symbol=self.symbol,
            trade_date=self.trade_date,
            close=self.close,
            avg_close_20d=self.avg_close_20d,  # 透传
        )
```

## 6. DTO 的 `from_entity`

### 6.1 定义位置

```python
# contexts/market/interface/dto/response/kline.py
from __future__ import annotations
from pydantic import BaseModel, Field
from datetime import date
from typing import Optional, TYPE_CHECKING

if TYPE_CHECKING:
    from contexts.market.domain.entities.kline.entity import Kline

class KlineResponseDTO(BaseModel):
    """K线响应 DTO"""
    symbol: str = Field(..., description="股票代码")
    trade_date: date = Field(..., description="交易日期")
    open: float
    high: float
    low: float
    close: float
    volume: int
    change_pct: Optional[float] = Field(None, description="涨跌幅")
    
    @classmethod
    def from_entity(cls, entity: "Kline") -> "KlineResponseDTO":
        """从 Entity 构造响应 DTO"""
        return cls(
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            open=entity.open,
            high=entity.high,
            low=entity.low,
            close=entity.close,
            volume=entity.volume,
        )
```

### 6.2 DTO 与 BO 的区别

| 维度 | DTO | BO |
|:--|:--|:--|
| 依赖层 | interface（HTTP 协议） | application（领域） |
| 主要用途 | HTTP JSON 序列化 | 跨层数据载体 |
| 字段来源 | 业务 + 协议（描述、分组） | 业务 |
| 是否可重复 | 多次传输（缓存、文档） | 单次传输 |

### 6.3 DTO 的 from_entity 可以接受 BO

如果 DTO 字段主要来自 BO，可以用 BO 作为入参：

```python
class KlineResponseDTO(BaseModel):
    # ...
    
    @classmethod
    def from_bo(cls, bo: "KlineBO") -> "KlineResponseDTO":
        """从 BO 构造响应 DTO（适用于 route 直接接收 BO）"""
        return cls(
            symbol=bo.symbol,
            trade_date=bo.trade_date,
            close=bo.close,
        )
```

> **推荐**：用 `from_entity` 而不是 `from_bo`，让转换保持在 Domain 边界外。

## 7. 完整调用链示例

### 7.1 场景：从 DB 查询一只股票的 K线，返回给 HTTP

```python
# === Interface Layer (route.py) ===
@router.get("/kline/{symbol}")
async def get_kline(symbol: str):
    # route 不直接处理 Entity
    bo = await stock_info_service.get_kline_bo(symbol)
    return KlineResponseDTO.from_bo(bo)  # BO → DTO


# === Application Service ===
class StockInfoService:
    async def get_kline_bo(self, symbol: str) -> KlineBO:
        # 1. Repository 取 Entity
        entities = await self.kline_repo.list_by_symbol(symbol)
        
        # 2. Entity → BO
        bos = [KlineBO.from_entity(e) for e in entities]
        
        # 3. 返回 BO
        return bos


# === Infrastructure (Repository) ===
class KlineRepositoryImpl:
    async def list_by_symbol(self, symbol: str) -> list[Kline]:
        # 1. ORM 查询
        models = await self.session.execute(
            select(KlineDB).where(KlineDB.symbol == symbol)
        )
        
        # 2. Model → Entity
        return [m.to_entity() for m in models.scalars().all()]


# === Domain (Entity + VO) ===
@dataclass
class Kline:
    id: int
    symbol: str
    trade_date: date
    close: float
    
    @classmethod
    def from_bo(cls, bo: KlineBO) -> "Kline":
        # 从 BO 反向构造（业务规则校验、领域方法调用）
        return cls(...)
```

### 7.2 场景：保存一条 K线（写入流程）

```python
# === Interface (route.py) ===
@router.post("/kline")
async def create_kline(dto: KlineRequestDTO):
    bo = KlineBO.from_request_dto(dto)
    await stock_info_service.create_kline(bo)
    return {"ok": True}


# === Application Service ===
class StockInfoService:
    async def create_kline(self, bo: KlineBO):
        # 1. BO → Entity
        entity = Kline.from_bo(bo)
        
        # 2. 业务规则校验
        self._validate_kline(entity)
        
        # 3. Repository 保存
        await self.kline_repo.save(entity)


# === Infrastructure (Repository) ===
class KlineRepositoryImpl:
    async def save(self, entity: Kline):
        # 1. Entity → Model
        model = KlineDB.from_entity(entity)
        
        # 2. ORM 保存
        self.session.add(model)
        await self.session.commit()
```

## 8. 常见反模式

### 8.1 反模式 1：Converter 类中央化

```python
# ❌ 反例
class KlineConverter:
    @staticmethod
    def entity_to_dto(entity: Kline) -> KlineResponseDTO:
        return KlineResponseDTO(...)
    
    @staticmethod
    def dto_to_entity(dto: KlineRequestDTO) -> Kline:
        return Kline(...)
```

**问题**：
- 转换方法与类型分离，找不到
- 每加一个类型都要改 Converter
- 单元测试不友好

**正确做法**：

```python
# ✅ 正例
@dataclass
class Kline:
    @classmethod
    def from_bo(cls, bo: KlineBO) -> "Kline":
        return cls(...)

class KlineResponseDTO(BaseModel):
    @classmethod
    def from_entity(cls, entity: Kline) -> "KlineResponseDTO":
        return cls(...)
```

### 8.2 反模式 2：Entity 直接 import ORM Model

```python
# ❌ 反例
from contexts.market.infrastructure.persistence.models.tech_kline import KlineDB

@dataclass
class Kline:
    @classmethod
    def from_model(cls, model: KlineDB) -> "Kline":
        # Domain 依赖 Infrastructure
        return cls(...)
```

**问题**：
- 违反依赖倒置（Domain → Infrastructure）
- Domain 不再纯净

**正确做法**：

```python
# ✅ 正例
# Model 主动提供 to_entity
class KlineDB(Base):
    def to_entity(self) -> Kline:
        return Kline(...)

# Entity 通过 TYPE_CHECKING 引用 BO
if TYPE_CHECKING:
    from contexts.market.application.bo.kline import KlineBO

@dataclass
class Kline:
    @classmethod
    def from_bo(cls, bo: KlineBO) -> "Kline":
        return cls(...)
```

### 8.3 反模式 3：DTO 反向 import Domain

```python
# ❌ 反例
# contexts/market/interface/dto/response/kline.py
from contexts.market.domain.entities.kline.entity import Kline

class KlineResponseDTO:
    @classmethod
    def from_entity(cls, entity: Kline):
        return cls(...)
```

**问题**：
- Interface 层依赖 Domain 层（违反"Interface 可依赖 application+domain"的规则）
- DTO 变成"通用"但与具体 Entity 耦合

**正确做法**：

```python
# ✅ 正例
# DTO 用 TYPE_CHECKING + 显式构造
from __future__ import annotations
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from contexts.market.domain.entities.kline.entity import Kline

class KlineResponseDTO(BaseModel):
    symbol: str
    close: float
    
    @classmethod
    def from_entity(cls, entity: "Kline") -> "KlineResponseDTO":
        return cls(
            symbol=entity.symbol,
            close=entity.close,
        )
```

> **注意**：实际上 Interface 层依赖 Domain 是允许的（参考 DDD.md §4）。关键是：**Interface 只能"使用"Domain 的类做转换，不能"修改"Domain**。

### 8.4 反模式 4：循环导入

```python
# ❌ 反例
# entity.py
from contexts.market.application.bo.kline import KlineBO  # 运行时导入

# bo.py
from contexts.market.domain.entities.kline.entity import Kline  # 运行时导入
```

**问题**：
- 循环导入

**正确做法**：

```python
# ✅ 正例
# entity.py
from __future__ import annotations
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from contexts.market.application.bo.kline import KlineBO

@dataclass
class Kline:
    @classmethod
    def from_bo(cls, bo: "KlineBO") -> "Kline":  # 用字符串
        return cls(...)
```

## 9. 检查清单

| 检查项 | 状态 |
|:--|:--|
| Entity 引用 BO 使用 TYPE_CHECKING | ☐ |
