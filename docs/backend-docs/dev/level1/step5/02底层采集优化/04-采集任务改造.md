# 04 采集任务改造：DeclarativeCollectTask

> 对应 README 的使用方式"采集入库"。阶段 P2（tushare 系任务）、P3（概念任务）、P6（目录上移）。

## 1. 不变的部分

- `BaseCollectTask`、`execute_task`、`run_units`、`UnitResult` / `TaskSummary`、取消标志、增量工具（`resolve_trade_dates` / `existing_dates` / `existing_symbols`）全部保留。模板方法骨架不动。
- `task_type` 名称、`default_params`、`full_params`、`mode` 语义、Redis 进度键、`sys_collect_tasks` 写法不变。
- `CollectManageService` 的 `prepare` / `submit` / `run_one` / `run_plan` 不变。

## 2. 现在的问题

`cap_moneyflow.py` 和 `cap_holder_num.py` 这类任务约 90–100 行，真正不同的只有 5 处：

1. 元数据（name / facet / label / description）——和 Port 重复；
2. 单元怎么列（按交易日 / 按上市股票）；
3. 已有单元查哪一列；
4. 调哪个 fetcher 方法；
5. 写哪个 Repository。

其余都是复制的：取 fetcher、`to_thread`、限频重试、可取消 sleep、空结果视为跳过、`save_batch([b.to_entity() ...])`、`summary_message`。按股票的任务还各自复制了一份"查上市股票 + only_missing + limit"。

## 3. 新增：规划器（注入的策略）

```python
# collect/declarative.py
class UnitPlanner(Protocol):
    async def units(self, params: dict, column) -> list[str]: ...
    async def existing(self, column, units: list[str]) -> set[str]: ...

class TradeDatePlanner:
    """trade_date / start_date+end_date / days → 交易日（YYYYMMDD）"""
    async def units(self, params, column): return resolve_trade_dates(params)
    async def existing(self, column, units): return await existing_dates(column, units)

class SymbolPlanner:
    """symbol 指定单只；否则全部上市股票；only_missing 且 column 非空时跳过已有的；limit 截断"""
    async def units(self, params, column): ...
    async def existing(self, column, units): return await existing_symbols(column, units)

class ConceptPlanner:
    """有效概念的 index_code；limit 截断（即现在 concept.py 的 _active_concepts）"""
```

`SymbolPlanner` 合并了现在 6 个按股票任务里重复的 `list_units` / `_symbols`。`only_missing` 用的列和 `existing_units` 用的列是同一列，统一由任务声明的 `existing_column` 提供。

## 4. 新增：DeclarativeCollectTask（模板方法里的可变步骤）

```python
class DeclarativeCollectTask(BaseCollectTask):
    port: ClassVar[type[DataPort]]          # 取哪份数据
    planner: ClassVar[UnitPlanner]          # 单元怎么列
    existing_column: ClassVar[Any] = None   # 如 CapMoneyflowDB.trade_date；None 表示不做增量跳过
    repo: ClassVar[type]                    # 有 save_batch(entities) 的 RepoImpl
    unit_word: ClassVar[str] = "单元"        # 汇总文案：交易日 / 股票
    empty_word: ClassVar[str] = "无数据"     # 汇总文案：无数据 / 无财报

    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        port = cls.__dict__.get("port")
        if port:                            # 元数据默认取 Port，任务只在需要时覆盖
            for attr in ("facet", "sub_facet", "label", "description"):
                if attr not in cls.__dict__:
                    setattr(cls, attr, getattr(port, attr))

    def build_params(self, unit: str, params: dict) -> dict:
        """单元 + 任务参数 → Port 参数；默认 {port.unit: unit}"""
        return {self.port.unit: unit}

    async def list_units(self, params):
        return await self.planner.units(params, self.existing_column)

    async def existing_units(self, units, params):
        if self.existing_column is None:
            return set()
        return await self.planner.existing(self.existing_column, units)

    async def collect_one(self, unit, params):
        result = await get_data_gateway().fetch(self.port, self.build_params(unit, params))
        if not result.items:
            return UnitResult(success=True, detail=unit, skipped=True)
        async with AsyncSessionLocal() as session:
            saved = await self.repo(session).save_batch([b.to_entity() for b in result.items])
        return UnitResult(success=True, detail=unit, saved_count=saved)

    def summary_message(self, t):
        return f"完成: {self.unit_word} {t.success}（{self.empty_word} {t.skip}），失败 {t.fail}；写入 {t.saved} 条"
```

改造后一个任务的完整定义：

```python
# collect/tasks/tushare_tasks.py
class CapMoneyflowCollectTask(DeclarativeCollectTask):
    name = "cap_moneyflow"
    port = MoneyflowPort
    planner = TradeDatePlanner()
    existing_column = CapMoneyflowDB.trade_date
    repo = CapMoneyflowRepoImpl
    unit_word = "交易日"
    default_params = {"days": 1}
    full_params = {"days": 365}
    sort_order = 10

class FinReportCollectTask(DeclarativeCollectTask):
    name = "fin_report"
    port = FinIncomePort
    planner = SymbolPlanner()
    existing_column = FinReportDB.symbol
    repo = FinReportRepoImpl
    unit_word, empty_word = "股票", "无财报"
    label = "季报财务"                           # 和 Port 不同时覆盖
    default_params = {"years": 1}
    full_params = {"years": 3}

    def build_params(self, unit, params):
        years = params.get("years", 1)
        start = date.today() - timedelta(days=int(float(years) * 365)) if years else None
        return {"symbol": unit, "start_date": start}
```

类名保持不变，`main.py` 里的注册列表和 `collect/__init__.py` 的导出都不用改。

## 6. execute_task 的一处改动

在 `execute_task` 开头设置取消检查上下文（见 03 §4.1），其余不变：

```python
token = cancel_check.set(lambda: _raise_if_cancelled(task_id))
try:
    ...原有流程...
finally:
    cancel_check.reset(token)
    ...原有 finally...
```

`run_one`（业务同步调用单元）不经过 `execute_task`，没有取消检查，与现在一致。

## 7. catalog 的改动

`CollectTaskRegistry.catalog()` 现在把采集任务和实时接口拼在一起。改造后：

- 采集任务部分不变（元数据已由 `__init_subclass__` 从 Port 填好）。
- 实时接口部分不再读 `realtime` 注册表，改为遍历声明了 `cache` 的 Port（见 05 §5）。
