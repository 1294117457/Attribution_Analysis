## 3. 关键改造点

| 改造项 | 说明 |
|---|---|
| `StockPanelQuery` | 收敛 `StockInfoService.page(...)` 的 **13 个位置参数** |
| `KlineQuery` / `StockListQuery` | 收敛 4~5 个位置参数 |
| `PoolMembersRequest` | 合并原先的 `PoolAddMembersRequest`（新增）/ `PoolRemoveMembersRequest`（移除）为一个对称 DTO |
| `PoolMemberMemoRequest` | 单字段入参仍建 DTO（保持前端 `{ memo }` 契约一致）|
| `DataBoardService` | **拆掉 `list(String kind, String symbol)` 字符串分发**，改为 16 个强类型方法 |
| `ConceptService.detail` | 返回值由 `Map` 改为 `ConceptDetailVO`（含 `members`）|
| `MarketConverter.toSummaryVO` | `IndicatorUtil.summarize` 的 `Map` 输出 → `TechnicalSummaryVO`（计算在 Util 内，出参是强类型）|
| `PoolConverter.toProgress` | `progress` JSON 文本 → `OperationProgressVO` |
| `GlobalExceptionHandler` | 收集**全部**字段错误（`joining("; ")`），不再只返回第一个 |
| `mapper-locations` | `application.yml` 增加 `classpath*:/mapper/**/*.xml`，启用 XML Mapper |

## 4. 保留 Map 的合理场景（规范允许）

| 位置 | 原因 |
|---|---|
| `CollectorClient` / `CollectRequest.params` | Python collector 的外部结构，跨语言契约 |
| `CollectProxyController.*` | 同上，纯透传 |
| `ScheduleServiceImpl.trigger` 返回值 | collector 原始响应透传 |
| `ConceptService.quotes` 返回值 | 前端契约是 `Record<string, ConceptSnapshot>`（动态 key），但 **value 已是 `ConceptSnapshotVO`** |
| `IndicatorUtil.calculate/summarize` | 内部计算中间态，非接口契约；对外由 Converter 转 VO |

## 5. 整改落地路径（2026-10-28 制定）

| 阶段 | 内容 | 风险 |
|---|---|---|
| **P0** | Service 层 60 处 JDBC → XML Mapper | 高（改动面大，需逐表核对）|
| **P0** | `GlobalExceptionHandler` 收集全部字段错误 | 极低 |
| **P1** | `LoginRequest`（修 `"null"` 字符串 Bug）| 低 |
| **P1** | PATCH 类 DTO（`PoolUpdateRequest` / `StockUpdateRequest`）| 低 |
| **P2** | 查询条件 DTO（`StockPanelQuery` 13 参数、`KlineQuery` 5 参数）| 中 |
| **P2** | VO（`UserVO` / `PoolVO` / `PoolMemberVO`）+ 同步前端 TS | 中 |
| **P3** | 包结构调整：新增 `dto/` `vo/` `converter/` | 低（纯移动）|
| **P4** | 映射点 > 30 时引入 MapStruct | 需加依赖 |
