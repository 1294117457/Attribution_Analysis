```mermaid
    subgraph L1["L1 数据源统一 API（DataSourceAPI）"]

        A2["AdataAPI<br/>call(method, **kwargs)"]
        A3["PytdxAPI<br/>call(method, **kwargs)"]
    end

    subgraph RAW["底层 fetcher（保留不变）"]
        direction LR
        R1[TushareFetcher]
        R2[AdataConceptFetcher]

    L2 -->|call source.method| L1
    L1 -->|包装转发| RAW

    style L2 fill:#fff3e0,stroke:#f57c00

```

**怎么读**：
- **L2 编排层**：声明式 pipeline 配置，不写代码
- **L1 API 层**：所有数据源统一 `call(method, **kwargs)` 接口
- **RAW 底层**：现有 fetcher 0 改动，L1 用薄包装类转发

## 2. Pipeline 内部结构（一个 pipeline 长什么样）

```mermaid
classDiagram
    class Pipeline {
        +pipeline_id: str
        +name: str
        +facet: str
        +unit: UnitSpec
        +steps: tuple~APIStep~
        +schedule: ScheduleSpec
        +rate_limit: RateLimitConfig
        +retry: RetryConfig
        +tags: tuple
        +enabled: bool
    }

    class UnitSpec {
        +style: str
        +unit_source: str
        +unit_filter: dict
        +unit_template: dict
    }

    class APIStep {
        +name: str
        +source: str
        +method: str
        +args_template: dict
        +save_to: str
        +depends_on: tuple
        +on_error: str
    }

    class ScheduleSpec {
        +kind: str
        +cron: str
        +interval_seconds: int
        +trading_day_only: bool
        +to_apscheduler()
    }

    Pipeline "1" *-- "1" UnitSpec
    Pipeline "1" *-- "many" APIStep
    Pipeline "1" *-- "0..1" ScheduleSpec
```

**Pipeline 的一句话结构**：
> **1 个 Pipeline = 1 个 UnitSpec（怎么切单元）+ N 个 APIStep（每个单元跑什么）+ 1 个 ScheduleSpec（何时跑）+ tags（归类）**

## 3. 单 Pipeline vs 多 Pipeline 工作流（核心差异）

```mermaid
flowchart LR
    subgraph SINGLE["单步 Pipeline: daily_kline"]
        direction LR
        S1["APIStep<br/>source=Tushare<br/>method=fetch_kline"]
    end

    subgraph WF["多步 Pipeline: after_market_sync"]
        direction LR
        S2["Step 1<br/>Tushare.fetch_kline"]
        S3["Step 2<br/>Tushare.fetch_daily_basic<br/>depends_on=Step1"]
        S4["Step 3<br/>Adata.fetch_concept_list"]
    end

    subgraph CALL["统一调用"]
        A1[TushareAPI.call]
        A2[AdataAPI.call]
    end

    SINGLE --> A1
    S2 --> A1
    S3 --> A1
    S4 --> A2

    style SINGLE fill:#e8f5e9,stroke:#388e3c
    style WF fill:#fff3e0,stroke:#f57c00
    style CALL fill:#e3f2fd,stroke:#1976d2
```

**关键设计点**：
- Pipeline **本身不限制 step 数**：可以是 1 个（单采集），也可以是 N 个（工作流）
- 多步时按 `steps` 顺序执行，可选 `depends_on` 声明依赖
- 所有 step **走同一个 `DataSourceAPI.call(method, **kwargs)` 入口**

## 4. Pipeline 执行流程（一次采集怎么跑）

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户/调度器
    participant R as 路由层
    participant Reg as PipelineRegistry
    participant Run as PipelineRunner
    participant UR as UnitResolver
    participant DS as DataSourceRegistry
    participant API as TushareAPI/AdataAPI
    participant F as 底层 Fetcher
    participant DB as PostgreSQL
    participant Cache as Redis

    U->>R: POST /collect/pipelines/{id}/trigger
    R->>Reg: get(pipeline_id)
    Reg-->>R: Pipeline 配置
    R->>DB: INSERT sys_collect_tasks
    R->>Cache: HSET total=?
    R->>Run: PipelineRunner(pipeline, task_id).run(params)

    Run->>UR: resolve(unit_spec, params)
    UR-->>Run: AsyncIterator[unit]

    loop 每个 unit
        Run->>Run: render(args_template, {**unit, **params})
        Note over Run: 极简 Jinja {{var}} 替换

        loop 每个 step
            Run->>DS: get(step.source)
            DS-->>Run: TushareAPI / AdataAPI
            Run->>API: call(step.method, **args)
            API->>F: 转发到 fetcher.method(**args)
            F-->>API: BO 列表
            API-->>Run: CallResult(ok=True, data=...)
        end

        Run->>Cache: HINCRBY done/success/fail
    end

    Run->>DB: UPDATE sys_collect_tasks SET status
    Run-->>R: 完成
```

**关键路径**：
- **Step 1-2**：解析单元（symbol / 日期 / 概念...）
- **Step 3-7**：渲染模板 + 调用 `DataSourceAPI.call()`
- **Step 8-9**：所有 step 都通过同一个 `call()` 入口，**屏蔽数据源差异**

```mermaid
        P2[daily_basic<br/>tags=Tushare·全市场·盘后]
        P3[fin_report<br/>tags=Tushare·单股]
        P4[concept_membership<br/>tags=Adata·概念]

    end

    P1 -.-> T1
    P1 -.-> T4
    P2 -.-> T1
    P2 -.-> T4

    style TAG fill:#f3e5f5,stroke:#7b1fa2
```

**群组用 tag 实现**：
- **不引入"群组"概念**，Pipeline 自己的 `tags` 字段就是群组
- 调用：`registry.list_by_tag("盘后")` 拿所有盘后 pipeline
- 用户可在 UI 上按 tag 一键触发整组（前端二次开发）

## 6. 调度器（PipelineScheduler）

```mermaid
flowchart LR
    subgraph SCH["PipelineScheduler (APScheduler)"]
        J1["job: pipeline:daily_kline<br/>cron '0 17 * * 1-5'"]
        J2["job: pipeline:after_market_sync<br/>cron '30 16 * * 1-5'"]
    end

    subgraph PR["PipelineRegistry"]
        P1[daily_kline<br/>schedule=cron 17:00]
        P2[after_market_sync<br/>schedule=cron 16:30]
        P3[manual_run<br/>schedule=None]
    end

    J1 -. 触发 .-> ROUTE["POST /collect/pipelines/{id}/trigger"]
    J2 -. 触发 .-> ROUTE
    USER[用户手动] --> ROUTE
    P1 --> J1
    P2 --> J2
    P3 -. 仅手动 .-> USER

    style SCH fill:#e8f5e9,stroke:#388e3c
    style PR fill:#fff3e0,stroke:#f57c00
```

**调度原理**：
1. 启动时扫所有 pipeline，**有 `schedule` 的注册为 cron job**
2. 到点 → 触发内部 trigger 接口 → 复用现有执行链路
3. `schedule=None` 的 pipeline 仅手动触发（保留 admin UI 入口）

## 7. 重构前后对比（旧 CollectTask vs 新 Pipeline）

```mermaid
flowchart TB
    subgraph OLD["重构前：硬编码"]
        direction TB
        OT[DailyKlineCollectTask<br/>类 + 187 行 run]
        OT -->|get(KlineFetcher)| OF[TushareFetcher]
        OT -->|写库| OK[KlineAppService]
    end

    subgraph NEW["重构后：声明式"]
        direction TB
        NP["Pipeline 配置（20 行）<br/>pipeline_id=daily_kline"]
        NP --> NR[PipelineRunner]
        NR -->|call('fetch_kline')| NA[TushareAPI]
        NA -->|转发| NF[TushareFetcher]
        NR -->|save_to hook| NK[落库（可选）]
    end

    style OLD fill:#ffebee,stroke:#c62828
    style NEW fill:#e8f5e9,stroke:#388e3c
```

**核心差异**：
- **旧**：每个采集任务 = 1 个 Python 类 + ~120 行样板代码
- **新**：每个采集任务 = 1 段 ~20 行的 Pipeline 配置 + 共用 PipelineRunner
- 加新采集任务 = **复制一段配置改 2-3 行**，不写代码
