# DDD 目录结构优化方案

> 本文档定义 backend 目录结构重组的完整方案。
>
> 目标：将"每个 entity 一个目录"改为"按领域模型聚合"，BO 移到 application 层，Converter 分散到各自类型中。

---

## 1. 核心原则

### 1.1 四层职责

| 层级 | 目录 | 职责 |
|:--|:--|:--|
| **Domain** | `domain/` | 业务核心（Entity、VO、Repository 接口、Domain Service） |
| **Application** | `application/` | 用例编排（BO、Application Service、Port） |
| **Infrastructure** | `infrastructure/` | 技术实现（Repository Impl、ORM、Adapter） |
| **Interface** | `interface/` | 对外接口（HTTP 路由、DTO） |

### 1.2 关键变更

| 变更项 | 原因 |
|:--|:--|
| Domain 层按领域模型聚合 | 避免 15+ 个子目录爆炸，相关代码内聚 |
| BO 移到 application/bo/ | BO 是应用层数据载体，属于 Application 层 |
| 删除 converter/ 目录 | `from_` 类方法分散到 entity/vo/bo/dto/model 中 |
| Domain Service 独立 services/ 目录 | 跨领域模型的服务需要聚合 |

## 3. 转换方法位置

### 3.1 转换流向

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          转换流向                                        │
│                                                                         │
│   Port → BO → Entity → Repository → Model → DB                         │
│           ↓                                                             │
│           DTO → HTTP Response                                           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 `from_` 类方法定义位置

| 类型 | 定义 `from_` 方法 | 理由 |
|:--|:--|:--|
| **Entity** | `from_bo(bo)` | Domain 接受 Application 的 BO（依赖倒置） |
| **BO** | `from_entity(entity)` | Application 接受 Domain 的 Entity |
| **VO** | `from_dict(dict)` / `from_entity(entity)` | 投影构造 |
| **Model** | `from_entity(entity)` | Infrastructure 接受 Domain 的 Entity |
| **DTO** | `from_entity(entity)` | Interface 接受 Domain 的 Entity |

### 3.3 代码示例

```python
# === Entity (domain/entities/kline/entity.py) ===
from dataclasses import dataclass
from contexts.market.application.bo.kline import KlineBO

@dataclass
class Kline(AggregateRoot):
    symbol: str
    trade_date: date
    close: float
    # ... 其他字段
    
    @classmethod
    def from_bo(cls, bo: KlineBO) -> "Kline":
        """从 BO 构造 Entity"""
        return cls(
            id=bo.id,
            symbol=bo.symbol,
            trade_date=bo.trade_date,
            close=bo.close,
        )


# === BO (application/bo/kline.py) ===
from pydantic import BaseModel
from contexts.market.domain.entities.kline.entity import Kline

class KlineBO(BaseModel):
    id: int
    symbol: str
    trade_date: date
    close: float
    
    @classmethod
    def from_entity(cls, entity: Kline) -> "KlineBO":
        """从 Entity 构造 BO"""
        return cls(
            id=entity.id,
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            close=entity.close,
        )


# === Model (infrastructure/persistence/models/tech_kline.py) ===
from sqlalchemy import Column, Integer, String, Date

class KlineDB(Base):
    __tablename__ = "tech_kline_dailys"
    
    id = Column(Integer, primary_key=True)
    symbol = Column(String(10))
    trade_date = Column(Date)
    close = Column(Float)
    
    @classmethod
    def from_entity(cls, entity: Kline) -> "KlineDB":
        """从 Entity 构造 ORM Model"""
        return cls(
            id=entity.id,
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            close=entity.close,
        )
    
    def to_entity(self) -> Kline:
        """从 ORM Model 构造 Entity"""
        return Kline(
            id=self.id,
            symbol=self.symbol,
            trade_date=self.trade_date,
            close=self.close,
        )


# === DTO (interface/dto/response/kline.py) ===
from pydantic import BaseModel

class KlineResponseDTO(BaseModel):
    symbol: str
    trade_date: date
    close: float
    
    @classmethod
    def from_entity(cls, entity: Kline) -> "KlineResponseDTO":
        """从 Entity 构造响应 DTO"""
        return cls(
            symbol=entity.symbol,
            trade_date=entity.trade_date,
            close=entity.close,
        )


# === VO (domain/entities/kline/vo.py) ===
from dataclasses import dataclass

@dataclass(frozen=True)
class KlineBriefVO:
    """K线简略投影"""
    symbol: str
    close: float
    
    @classmethod
    def from_entity(cls, entity: Kline) -> "KlineBriefVO":
        return cls(symbol=entity.symbol, close=entity.close)
    
    @classmethod
    def from_dict(cls, data: dict) -> "KlineBriefVO":
        return cls(symbol=data["symbol"], close=data["close"])
```

## 5. 实施步骤

### Phase 1: market Context 重构

1. 创建 `domain/entities/` 目录结构
2. 迁移所有领域模型到 `entities/` 子目录
3. 重命名 `domain/service/` → `domain/services/`
4. 创建 `application/bo/` 目录
5. 迁移所有 BO 文件到 `application/bo/`
6. 删除 `application/*/converter.py`
7. 更新所有 `from_` 类方法到各自类型中
8. 更新所有 import 语句

### Phase 2: concept Context 重构

1. 创建 `domain/entities/concept/` 目录
2. 迁移 `domain/entity.py` → `domain/entities/concept/entity.py`
3. 创建 `application/bo/` 目录
4. 迁移 BO 文件
5. 移动 domain service
6. 删除 converter

### Phase 3: collect Context 重构

1. 移动 domain service 到 `domain/services/`

### Phase 4: 验证

1. 运行所有测试
2. 验证 import 路径
3. 验证业务逻辑不变

## 6. 兼容性策略

### 6.1 旧 import 路径兼容

在迁移期间，可以在旧位置创建兼容文件：

```python
# domain/kline/entity.py（旧路径，迁移期间保留）
# 兼容旧代码，新代码应使用新路径
from contexts.market.domain.entities.kline.entity import Kline

__all__ = ["Kline"]
```

### 6.2 渐进式迁移

1. **Phase 1-3**: 创建新路径，保持旧路径兼容
2. **Phase 4**: 验证通过后，删除旧路径
3. **后续 PR**: 逐步更新所有 import 语句
