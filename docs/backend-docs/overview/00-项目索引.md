## 1. 项目概览

A 股个股归因分析系统：采集行情 / 估值 / 概念等多维数据入库，前端做股票面板、操作池、采集管理，并为后续 AI 归因提供统一数据入口（`GET /api/v1/stocks/{symbol}/analysis`）。

| 层 | 技术 |
|---|---|
| 后端 | Python 3.13 · FastAPI · SQLAlchemy 2（async + asyncpg）· pydantic-settings |
| 存储 | PostgreSQL（`stock_db`）· Redis（采集进度 `collect:progress:{task_id}`、实时 Port 缓存 `ds:cache:{port}:{hash}` / 调用统计 `ds:stats:*`） |
| 数据工具 | tushare 1.4.3 · adata 2.9.5 · tdxpy（pytdx 协议）· pandas |
| 前端 | Vue 3 · TypeScript · Vite · Element Plus · Pinia |

## 2. 运行方式

```powershell
# 后端（backend/ 目录，读取 backend/.env）
python .\src\main.py            # uvicorn :8000，Swagger: /docs
```

关键配置（`src/shared/infrastructure/config/settings.py`，`.env` 覆盖）：`DATABASE_URL`、`REDIS_URL`、`TUSHARE_TOKEN`、`COLLECT_CONCURRENCY`(3) / `COLLECT_MAX_CONCURRENCY`(8) / `COLLECT_CHUNK_SIZE`(30) / `COLLECT_SCHEDULER_ENABLED`(true)。

**表结构（`backend/init.sql` 为唯一来源）**：
- 启动时 `lifespan` 调 `schema_init.ensure_schema()`：
  - **空库**（`init.sql` 里的表一张都不存在）→ 单事务整份执行 `init.sql` 建表；
  - **已有库** → 只比对 表 / 列名 / 列类型 / NOT NULL，并检查 ORM 模型是否都写进了 `init.sql`，有差异打 `WARNING`，**不自动改表**。
- `init.sql` 是 `pg_dump --schema-only` 格式（DB 客户端导出即可），执行前自动去掉 psql 元命令（`\restrict`）、`CREATE/ALTER/COMMENT ON SCHEMA public`、`OWNER TO`、`SET transaction_timeout`。
- **改表流程**：DB 客户端改开发库 → 同步改 ORM 模型 → 重新导出覆盖 `backend/init.sql` → 提交。已有的生产库需手动执行对应 DDL（启动告警会列出差异）。
- 镜像内路径 `/app/init.sql`（`Dockerfile` `COPY init.sql`）。
- **没有 Alembic / 迁移函数**；数据备份由运维层 `pg_dump` 完成，应用内无备份功能。
- 启动后还会做：残留 `running` 采集任务标 failed、默认操作池、初始 admin、`collect_fetchers` 对账。

## 6. 采集框架

> 摘要：[`collectmanage摘要.md`](collectmanage摘要.md)（链路 / 任务表 / 业务侧采集入口 / 已知问题）

- **任务基类** `shared.infrastructure.adapter.collect.base` `BaseCollectTask`
  - 元数据 ClassVar：`name`（task_type）/ `facet` / `sub_facet` / `label` / `description` / `status`（`ready`|`planned`）/ `sort_order`（同子分类内排序）
  - 生命周期：`estimate_total(params)` → `run(params, on_unit_done)` → `TaskSummary`；取消通过 `is_cancelled` 协作式检查（抛 `Cancelled`），`execute_task` 同时设置 `context.cancel_check`，让装饰器里的限频等待 / 重试等待也能及时响应取消
  - 单元接口：`list_units(params)` + `collect_one(unit, params) -> UnitResult`；默认 `run()` 遍历单元（`concurrency` 分批、失败末尾重试一轮），`default_params` 为默认参数
  - 状态判定：仅 `success == 0 且 fail > 0` 时为 failed
  - **声明式任务** `collect/declarative.py` `DeclarativeCollectTask`：只声明 `port` + 规划器（`TradeDatePlanner` / `SymbolPlanner` / `ConceptPlanner`）+ 仓储，facet / label / description 等元数据取自 Port；14 个 tushare 按日 / 按股票任务集中在 `tushare_tasks.py`（`task_type` 不变）

## 10. 维护约定

以下变更发生时，同一次改动里更新本文档（以及 `step2/01当前实现/` 下的总结）：

1. 新增 / 删除 / planned→ready 采集任务：更新 §6 与数据面总结文档的任务表。
2. 新增 / 修改表：重新导出 `backend/init.sql`，同步 ORM 模型，并更新 §5（行数可只写"有数据/空"）。
3. 新增路由模块或重要端点：更新 §4。
4. 新增数据 Port / Adapter 或切换数据源：更新 §6 数据 Port 绑定表与数据面总结文档。
5. 新增 / 重命名 context：在 §3 目录结构中更新，新增模块的概要文档链接到 §9 文档地图。
6. 修掉 / 发现已知问题：更新 §8。
7. 更新文首"最后更新"日期与一句话摘要。
