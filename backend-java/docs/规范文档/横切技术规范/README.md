# 横切技术规范

> `backend-java` **跨层关注点**的规范目录。每份文档管一类横切能力，配套使用。
> 适用范围：`backend-java` 全部 Maven 模块。
> 配套目录：`../纵向分层规范/`（每层各管一段：Controller / Service / Mapper / POJO）

---

## 为什么单独一个目录

纵向分层回答的是「**这段逻辑放哪一层**」；
横切规范回答的是「**这类问题怎么统一处理**」。

这两类问题**正交**，且横切问题天然**跨越所有层**——
异常要从 Service 抛出、被 handler 转换、被前端拦截器消费；
连接池要在 Mapper 层生效、却在事务边界上被 Service 层影响。

把它们塞进任何一份分层文档都会让那份文档臃肿且失焦。

```
┌─────────────────────────────────────────────────────────┐
│  横切技术规范/  ← 本文目录                              │
│    · 异常与响应规范   跨 Controller / Service / Mapper    │
│    · 基础设施规范     跨 Service / Mapper / 配置          │
│    · 依赖注入与Bean规范  跨所有层的 Bean 创建与注入       │
├─────────────────────────────────────────────────────────┤
│  纵向分层规范/    跨 Controller / Service / Mapper / POJO │
│    · Controller层规范   · Service层规范                    │
│    · Mapper层规范      · POJO规范                        │
└─────────────────────────────────────────────────────────┘
```

## 三份文档的分工

| | 异常与响应规范 | 基础设施规范 | 依赖注入与Bean规范 |
|---|---|---|---|
| **性质** | 编码期契约 | 部署期配置 | 编码期契约 |
| **什么时候看** | 写代码时 | 改配置 / 扩容 / 排查故障时 | 写代码时（新建 Bean、注入依赖）|
| **管什么** | 异常类型、错误码、响应体结构、日志级别 | 资源池参数、降级策略、超时、跨域 | 注入方式、Bean 创建者、作用域、代理 |
| **改动频率** | 低（契约稳定）| 中（扩容 / 调优时变）| 低（约定稳定）|

## 写规范的规矩

**只写规则，不写现状。**

| ❌ 不要写 | ✅ 应该写 |
|---|---|
| 「当前有 3 处 `new ObjectMapper()`」 | 「禁止 `new ObjectMapper()`，必须注入」|
| 「`WebConfig` 现在用的是 `allowedOriginPatterns("*")`」 | 「允许源必须显式配置，禁止生产写死 `*`」|
| 「HikariCP 现在没配」 | 「连接池必须显式配置 `maximum-pool-size` 与 `connection-timeout`」|

> 📌 现状信息会随代码变化而失真，一旦失真就没人信它了。
> 需要记录现状时，写进 `../审计与整改/` 下带日期的快照文件。

**参数表要同步。**
`基础设施规范.md` §2.2 / §3.6 的参数表是 `application.yml` 的索引——
改了配置**必须**同步该表，否则规范与实现脱节。
