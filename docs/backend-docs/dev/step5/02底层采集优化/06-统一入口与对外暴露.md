# 06 统一入口与对外暴露

> 对应 README 流程 ①②（命令 + 门面）。业务 Service 迁移在 P4，HTTP / Agent 在 P5。

## 1. 三种调用方

| 调用方 | 需要什么 | 用哪个入口 |
| :-- | :-- | :-- |
| 应用层 Service（业务代码） | 取数，不一定入库，要类型提示 | `gateway.fetch(Dataset, params)` |
| 采集管理 / 采集方案 / 定时 | 取数并入库，带进度和历史 | 不变：`CollectManageService.submit / run_plan`，任务内部走 Gateway |
| Agent / 其他服务 / HTTP | 运行时才知道调哪个接口 | `gateway.invoke(DataCommand(name, params))`，经 `/api/v1/data/*` |

"只取数"走 Gateway，"取数 + 入库"走采集任务（`run_one` 同步单元或 `submit` 后台任务），两者不混。

## 2. 业务 Service 迁移（P4）

### 2.1 stock_info_service

```python
# 改造前
async def sync_stocks(self, fetcher: StockBasicFetcher, list_status="L"):
    raw_data = await asyncio.to_thread(fetcher.fetch_stock_basic, CollectParams(list_status=list_status))

# 改造后
def __init__(self, ..., gateway: DataGatewayPort): ...
async def sync_stocks(self, list_status="L"):
    raw_data = (await self._gateway.fetch(StockBasic, {"list_status": list_status})).items
```

- 构造时注入 `DataGatewayPort`（`build_stock_info_service` 里传 `get_data_gateway()`），方法签名去掉 `fetcher` 参数。
- `stock_basic` 采集任务相应改为 `service.sync_stocks(list_status=...)`。
- `collect` / `collect_batch`（按单只股票采日 K）同样改为注入 Gateway。迁移时先 grep 调用方；若已无调用方（日 K 已统一走 `daily_kline` 任务），直接删除。

### 2.2 concept_service

```python

def fetch_concepts_by_stock(self, symbol): bos = self._fetcher.fetch_concepts_by_stock(symbol)

# 改造后
async def fetch_concepts_by_stock(self, symbol):
```

## 3. 统一目录

现在 `/collect/catalog` 由 `CollectTaskRegistry.catalog()` 把采集任务和实时接口拼在一起。改造后增加一个 Dataset 目录，三者关系：

```
Dataset（取什么，23 个）
  ├── 采集任务（取 + 入库，21 个，task_type 不变）    → /collect/catalog（不变）
  ├── 实时接口（取 + 缓存，2 个）                      → /collect/catalog（不变）
  └── 直接调用（只取）                                  → /data/catalog（新增）
```

- `/collect/catalog` 返回结构不变，前端不用改；元数据改为从 Dataset 读取（04 §4、05 §6）。
- `main.py` 中 `collect_fetchers` 表的对账逻辑不变，对账的是采集任务和实时接口。Dataset 不入这张表。

## 4. HTTP 接口（P5）

```
GET  /api/v1/data/catalog
POST /api/v1/data/{name}       body: {"params": {...}, "source": "tushare" | null}
```

`GET /data/catalog` 响应：

```json
[
  {
    "name": "moneyflow",
    "label": "个股资金流向",
    "facet": "capital",
    "sub_facet": "moneyflow",
    "description": "...",
    "unit": "trade_date",
    "params_schema": { "...": "MoneyflowParams.model_json_schema()" },
    "providers": [{ "tool": "tushare", "origin": "tushare", "origin_label": "Tushare", "priority": 10 }]
  }
]
```

`POST /data/{name}` 响应：

```json
{ "items": [ ... ], "source": "tushare", "latency_ms": 820, "attempts": [] }
```

错误映射：

| 异常 | HTTP |
| :-- | :-- |
| 未知 `name` | 404 |
| `InvalidParams` | 422 |
| `NotSupported` | 400 |
| `RateLimited` / `SourceUnavailable`（全部数据源失败） | 503，响应带 `attempts` |

约束：

- 走 `policy=QUERY`（不等限频），避免 HTTP 请求挂 60 秒。
- 鉴权沿用 `/collect` 路由现有方式；这些接口会消耗 tushare 积分和同花顺 IP 配额，建议加 `require_permission("collect:run")` 之类的权限（权限码按现有 RBAC 定义）。
- 单次返回条数上限 5000，超出时提示改用采集任务入库。
- 路由只做参数透传和错误映射，不写业务逻辑。

## 5. Agent 工具

Agent 侧不需要额外定义工具，直接由目录生成：

```python
def build_agent_tools(gateway) -> list[dict]:
    return [
        {
            "name": f"data_{d.name}",
            "description": f"{d.label}：{d.description}",
            "parameters": d.params_schema,
        }
        for d in gateway.catalog()
    ]
```

调用时 `gateway.invoke(DataCommand(name, args))`。新增一个 Dataset，Agent 自动多一个工具。

如果 Agent 需要"采集并入库"，调用现有的 `/collect/tasks` 提交任务，不在 Gateway 里做入库。
