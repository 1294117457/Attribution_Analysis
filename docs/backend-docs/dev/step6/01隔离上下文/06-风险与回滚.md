## 2. 风险逐项预案

### R1. import 改漏

**症状**：
```
ModuleNotFoundError: No module named 'domain.entitys.auth'
```

**预防**：
```bash
# 阶段 B 完成后跑：静态扫描所有 import
grep -rE "^import (domain|application|infrastructure|route)|^from (domain|application|infrastructure|route)" src/contexts/ --include="*.py" | grep -v "_legacy_compat" | grep -v "from contexts\."
# 期望：空
```

**修复**：
1. 找到报错文件
2. 替换为新路径（参考 [`02-迁移映射`](02-迁移映射.md) §3）
3. 重新跑验证

**回滚**：
- 不需要回滚（改 import 是局部操作）

---

### R2. 旧 import 被其他 context 引用

**症状**：
```
ModuleNotFoundError: No module named 'domain.entitys.concept'
```

**触发**：
- 某 context 已经被迁了，但其他 context 还在用旧路径 import 它

**预防**：
- **顺序很关键**：必须按 §3.1 的顺序迁（先迁 auth/collect，因为它们是"被引用方"）
- 每阶段迁完一个 context，先跑该 context 自己的入口测试

**修复**：
- 把"还在旧路径"的代码也迁到新路径
- 或者保留 `_legacy_compat.py` 转发

---

### R3. 路由重复注册

**症状**：
```
AssertionError: Router already has prefix /api/v1
```

**预防**：
```python
# app/main.py 里 include_router 时去掉 prefix，由 bootstrap 内部加
# 错误示例：
app.include_router(auth_router, prefix="/api/v1")
# contexts/auth/bootstrap.py 里又有：
app.include_router(auth_router, prefix="/api/v1")  # 重复！

# 正确：
# main.py：不加 prefix
# bootstrap.py：加 prefix
```

**修复**：
- 让 `include_router` 只在一处发生（main.py OR bootstrap.py，二选一）

**回滚**：
- 找最近的 git tag，回滚到上一个能启动的版本

---

### R4. ORM 外键跨 context

**症状**：
```
sqlalchemy.exc.NoReferencedTableError: Foreign key associated with column 'xxx' could not find table 'yyy'
```

**原因**：
- 例如 `news_symbol_rel.symbol` 是外键 → `stock_info.symbol`
- 但 news 和 stock_info 在不同 context

**预防**：
```python
# ❌ 错：跨 context 加外键
class NewsSymbolRel(Base):
    __tablename__ = "news_symbol_rel"
    news_id = Column(BigInteger, ForeignKey("news_raw.id"))
    symbol = Column(String(6), ForeignKey("stock_info.symbol"))  # 跨 context

# ✅ 对：不加 FK，靠应用层约束
class NewsSymbolRel(Base):
    __tablename__ = "news_symbol_rel"
    news_id = Column(BigInteger, ForeignKey("news_raw.id"))
    symbol = Column(String(6), primary_key=True)  # 纯字段，不加 FK
    # 写入时：检查 symbol 存在于 stock_info
```

**修复**：
- 移除跨 context 外键
- 在 service 层加约束检查

### R5. settings.py 路径错（dotenv 找不到）

**症状**：
```
pydantic_settings.errors.SettingsError: error parsing environment variable
# 或 .env 没生效（默认值生效）
```

**原因**：
- `settings.py` 里 `env_file` 用相对路径，移动到 `contexts/shared/infrastructure/config/` 后路径变了

**修复**：
```python
# 现状
env_file=Path(__file__).parent.parent.parent.parent / ".env"

# 新位置（src/contexts/shared/infrastructure/config/settings.py）
# .parent = src/contexts/shared/infrastructure/config
# .parent.parent = src/contexts/shared/infrastructure
# .parent.parent.parent = src/contexts/shared
# .parent.parent.parent.parent = src/contexts
# .parent.parent.parent.parent.parent = src
# .parent.parent.parent.parent.parent.parent = backend
env_file=Path(__file__).parent.parent.parent.parent.parent / ".env"
```

> 数一下层数：原 settings.py 在 `src/infrastructure/config/`，要往上 4 级到 `backend/`。
> 新位置在 `src/contexts/shared/infrastructure/config/`，要往上 5 级。
>
> **更稳妥的写法**：用绝对路径或环境变量
> ```python
> from pathlib import Path
> BACKEND_ROOT = Path(__file__).resolve().parents[5]  # 5 层上
> env_file=BACKEND_ROOT / ".env"
> ```

### R6. collect 找不到 data gateway

**症状**：
```
KeyError: 'data'  （collect 启动时）
# 或
RegistryNotFoundError: 数据源未配置: xxx
```

**原因**：
- collect 在 data 之前 setup
- 或 collect 没通过 `CollectContext.gateway` 拿到 gateway

**修复**：
- 严格按 [`03-依赖矩阵与启动序列`](03-依赖矩阵与启动序列.md) §3.1 的顺序启动
- 阶段 D 完成前，data context 的 setup 是 stub，collect 的 setup 也应是 stub
- 阶段 D 完成后，data 和 collect 一起 commit

---

### R7. 23 任务对账失败

**症状**：
```
WARNING: collect_fetchers 中有 5 个接口在代码里已不存在，已标 orphan
# 或
ERROR: collect_fetchers 同步失败
```

**原因**：
- 迁某个 collect 任务时，忘记 import 或改名
- `_sync_fetcher_catalog` 找不到对应 task_type

**修复**：
- 检查 `app/lifespan.py` 的 `all_collect_tasks()` 列表
- 跑 23 任务清单校验：
  ```bash
  python -c "
  from app.main import create_app
  app = create_app()
  from src.app.main import get_collect_task_registry
  # 注：lifespan 未跑，先手动触发
  "
  ```

### R8. 启动时序不对

**症状**：
- `lifespan` 启动时报错（依赖未就绪）

**修复**：
- 严格按顺序：`shared → data → {market, concept} → user → auth → collect → scheduler`
- 阶段 E 完成前，user / auth / collect 的 setup 是 stub

---

### R9. 兼容 shim 漏写

**症状**：
```
外部脚本（如 init_data.py）：
ModuleNotFoundError: No module named 'domain.entitys.auth'
```

**修复**：
- 在 `contexts/_legacy_compat.py` 里加 shim（参考 [`02-迁移映射`](02-迁移映射.md) §3）
- 重新启动即可

---

### R10. 性能下降

**症状**：
- 启动时间从 3s 变 5s+

**接受**：
- 启动慢 1~3 秒可接受（最多 -3 秒）
- 长期可优化：精简 import、用 `__init__.py` lazy import

**修复**：
- 如果超过 5 秒，分析启动期耗时（`python -X importtime`）

---

### R11. 前端报错

**症状**：
- 前端 console 报 404 或 CORS

**原因**：
- **不**应该发生（本期不修改 API 路径）
- 但如果发生，多半是 route prefix 写错

**修复**：
- 检查每个 context 的 `include_router(prefix="/api/v1")` 是否唯一
- 用 [`03-依赖矩阵与启动序列`](03-依赖矩阵与启动序列.md) §3.3 的约束

---

### R12. 测试代码未跟上

**症状**：
- 跑 `pytest` 报错：`ModuleNotFoundError` 或 `ImportError`

**原因**：
- 旧测试 `from domain.entitys.xxx import Yyy` 不工作了
- 单元测试 / 集成测试需要同步改

**修复**：
- `find . -name "test_*.py" -exec grep -l "from domain\|from application\|from route\|from infrastructure" {} \;`
- 找到后批量改
- 或者用 `_legacy_compat.py` 兜底

---

### R13. 旧路由被遗弃

**症状**：
- 前端访问 `/api/v1/old/path` → 404
- 但代码里这个路径应该还在

**原因**：
- 迁 route 时把 path 改错了（比如 `/auth` 改成了 `/auth-old`）

**修复**：
- 在 route 里加 alias：
  ```python
  @router.post("/auth/login", ...)
  @router.post("/auth-old/login", ..., deprecated=True)  # 兼容期保留
  ```

## 3. 回滚策略

### 3.1 阶段级回滚（推荐）

**每个阶段开始前**：
```bash
git tag -a "step6-stage-B-start" -m "阶段 B 开始前"
```

**每个阶段完成后**：
```bash
git tag -a "step6-stage-B-done" -m "阶段 B 完成"
```

**回滚到阶段 B 开始前**：
```bash
git checkout step6-stage-B-start
# 删 contexts/ 里阶段 B 之后加的
rm -rf src/contexts/{auth,collect,data,market,concept,user,news,sentiment}
# 重新装依赖（如果有）
# 跑测试
pytest tests/
```

### 3.2 紧急回滚（最坏情况）

```bash
# 假设 step6 全做完了，但生产崩了
git reset --hard pre-step6-isolation  # 回到 step6 之前
rm -rf src/contexts  # 删 contexts/ 目录
rm -rf src/app  # 删 app/ 目录（如果已建）
# 此时 src/ 还是旧结构，可以直接跑
```

### 3.3 物理备份回滚

```bash
# 整目录替换
$backup_root = "D:\codes\_backup\attribution_step6_YYYYMMDD"
Copy-Item -Path "$backup_root\backend" -Destination "D:\codes\Attribution_Analysis" -Recurse -Force
# 启动测试
```

### 3.4 局部回滚（推荐：只回滚某个文件）

```bash
# 假设只是 stock_pool_service 迁错了
git log --oneline -- src/contexts/user/application/service/stock_pool_service.py
# 找到上一个 good commit
git checkout <good_commit_hash> -- src/contexts/user/application/service/stock_pool_service.py
# 同步改 import
```

## 4. 验证脚本（每次提交前跑）

```bash
# scripts/verify_step6.sh（草稿，见 [04-实施阶段](04-实施阶段.md) §9）

#!/bin/bash
set -e
SRC=src

# 1. 结构验证
echo "=== 1. 8 个 context ==="
for ctx in auth collect data market concept user news sentiment; do
    [ -d "$SRC/contexts/$ctx" ] || { echo "FAIL: $ctx"; exit 1; }
done
echo "OK"

# 2. import 规则验证
echo "=== 2. application/ 不 import infrastructure ==="
violations=$(grep -rE "^import (infrastructure)|^from (infrastructure)" "$SRC/contexts"/*/application/ --include="*.py" 2>/dev/null | wc -l)
[ "$violations" -eq 0 ] || { echo "FAIL: $violations 处"; exit 1; }
echo "OK"

# 3. domain 干净
echo "=== 3. domain/ 不 import 框架 ==="
violations=$(grep -rE "^import (fastapi|sqlalchemy|pydantic)|^from (fastapi|sqlalchemy|pydantic)" "$SRC/contexts"/*/domain/ --include="*.py" 2>/dev/null | wc -l)
[ "$violations" -eq 0 ] || { echo "FAIL: $violations 处"; exit 1; }
echo "OK"

# 4. 启动
echo "=== 4. 启动验证 ==="
cd "$SRC" && python -c "from app.main import create_app; app = create_app(); print('OK')"

# 5. 路由数
echo "=== 5. 路由数 ==="
cd "$SRC" && python -c "
from app.main import create_app
app = create_app()
print(f'路由数: {len(app.routes)}')
"

# 6. 测试
echo "=== 6. 跑测试 ==="
cd "$SRC/.." && pytest tests/ -x --tb=short 2>&1 | tail -20

echo "=== 全部通过 ==="
```
