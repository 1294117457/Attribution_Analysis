# 操作池 - 实施路线

> 本文档定义"操作池"模块的实施阶段划分、优先级、工作量估算和验收标准。

---

## 1. 阶段总览

```
Phase 1: 核心框架 (P0)
├── 1.1 数据库迁移
├── 1.2 领域层 + 基础设施层
├── 1.3 应用层 + API
└── 1.4 前端基础（池 CRUD + 成员管理）

Phase 2: 操作功能 (P0)
├── 2.1 任务派发器（K 线采集）
├── 2.2 进度追踪（轮询）
└── 2.3 前端操作界面

Phase 3: 体验优化 (P1)
├── 3.1 SSE 进度推送
├── 3.2 操作取消
├── 3.3 操作详情
└── 3.4 成员备注编辑

Phase 4: 高级功能 (P2)
├── 4.1 操作历史清理
├── 4.2 拖拽排序
├── 4.3 池导入/导出
└── 4.4 任务重启恢复
```

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| asyncio.create_task 任务丢失 | 低 | 中 | P2 引入持久化 |
| 大池（1000+）采集超时 | 中 | 中 | 并发控制 + 分批 |
| 前端轮询性能问题 | 低 | 低 | P1 迁移到 SSE |
| 与现有 K 线服务冲突 | 低 | 高 | 复用 `KlineAppService`，不加锁 |
| 数据库连接泄漏 | 中 | 高 | 每个任务用独立 session |
