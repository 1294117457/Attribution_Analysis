# 01 · 回退硬编码清单

> 目标：把 D3 阶段引入的"动态化"（`collect_data_ports` 表 + 14 个声明式 task + 1 个 dynamic task + 5 装饰器链的 `DataGateway` + `XxxAdapter` 命名风格）**回退为显式硬编码**——23 个 task 类、`业务名+数据源+Fetcher` 命名、SDK 单独目录、`fetcher` 全部归 `collect/infrastructure/fetcher/`。

## 1. 现状：动态化 + 跨上下文 带来的复杂度

| 概念 | 引入动机 | 实际后果 |
|:--|:--|:--|
| `collect_data_ports` 表 | "新增数据源不用改代码" | 表字段和 `XxxPort` 类**完全重复** |
| 14 个 `DeclarativeCollectTask` | "一行注册一个 task" | 1 个类只多 `port = XxxPort` + `name = "xxx"`，**业务逻辑跑到 dynamic 里** |
| `DynamicCollectTask` | "通用 task，参数驱动" | `run` 内"参数校验 → 调 `gateway.query` → `raw_store.save_dynamic` → 列名推断 → 错误分类"——**写死在 1 个类** |
| `DataGateway` 5 装饰器链 | "集中管理选源/限流/缓存/校验/统计" | 跨 task 共享机制复杂（`ThrottleDecorator` + `RetryDecorator` + `MetricsDecorator` + `CacheDecorator`），**每次调 4 个类** |
| `XxxAdapter` 命名 + `data` 上下文 | "解耦" | 5 个上下文跨接口，**调用栈 6–8 层**：`route → service → gateway → adapter → client` |
| `market` / `realtime` / `quote` 3 个上下文 | "DDD 子域划分" | 采集（`collect`）和业务查询（`market`）**共享 fetcher**——分成 2 个上下文 = **重复持有 fetcher 引用** |

**结果**：要改"日 K 采集的逻辑"——**不知道改表、改 `DeclarativeCollectTask`、改 `DynamicCollectTask`、改 `XxxAdapter`、改 `stock_info_service`、改 `market_service` 还是改 `gateway` 装饰器链**。

## 2. 回退方向（5 条）

| # | 回退方向 | 说明 |
|:--|:--|:--|
| 1 | **23 个 task 类** | 每个是 `BaseCollectTask` 子类，`list_units` + `collect_one` 显式写 |
| 2 | **fetcher 重新命名 + 重新归位** | `TushareDailyKlineAdapter` → `KlineTushareFetcher`；移到 `collect/infrastructure/fetcher/` |
| 3 | **SDK 客户端单独目录** | `data/infrastructure/client/tushare.py` → `collect/infrastructure/sdk/tushare.py`（类名 `TushareClient`） |
| 4 | **去掉 `DataGateway`** | 不再有"集中选源"层；`source` 一传定 = 直接调对应 fetcher；多源切换彻底删除 |
| 5 | **去掉 5 装饰器链** | 限流在 task 内（`asyncio.Semaphore` + Redis token 桶）；缓存由业务 service 写 redis；统计 task 内 `logger` |

## 5. 实时 fetcher（**不**走 task）

下面这些 fetcher **没有对应 task**——只有 query service 调它们：

| 业务 | Fetcher 类 | 数据源 | 默认 TTL（业务 service 缓存） |
|:--|:--|:--|:--|
| 实时分 K | `MinuteKlineTushareFetcher` | tushare | 15s 交易 / 4h 盘后 |
| 实时资金流（沪深港通） | `MoneyflowHsgtRealtimeTushareFetcher` | tushare | 60s |
| 沪深通前 10 | `HsgtTop10RealtimeTushareFetcher` | tushare | 60s |
| 涨停板（盘中） | `LimitListDRealtimeTushareFetcher` | tushare | 30s |
| 实时新闻 | `NewsRealtimeAdataFetcher` | adata | 30s |

**业务 service 调这些 fetcher + 自己的 redis 缓存**——**不走 task，不入 `collect_jobs`，不限流**（HTTP 层 1 个请求 1 个调用）。

## 6. 1 个 task 类的样例

**以 `DailyKlineCollectTask` 为例**——它当前是声明式 + 调 `stock_info_service.collect`：

```python
# 现状（伪代码，混合 declarative + stock_info_service）
class DailyKlineCollectTask(DeclarativeCollectTask):
    name = "daily_kline"
    facet = "tech"; sub_facet = "kline"
    port = DailyKlinePort
    concurrency = 5
    # collect_one 委托给 stock_info_service.collect(...)
```

**回退后**（一个 Python 类搞定，不依赖声明式基类、不调 service、自己管限流并发、不调 gateway）：

```python
# collect/application/fetcher/tasks/daily_kline.py
from datetime import date, timedelta
from collect.application.fetcher.base import BaseCollectTask, UnitResult
from collect.infrastructure.fetcher.kline_tushare import KlineTushareFetcher
from collect.infrastructure.throttle.config import THROTTLE_GROUPS
from shared.infrastructure.cache.redis_cache import RedisCache
from collect.infrastructure.persistence.kline_repo import KlineRepo

class DailyKlineCollectTask(BaseCollectTask):
    name = "daily_kline"
    facet = "tech"
    sub_facet = "kline"
    label = "日 K 线"
    description = "单只股票日线 OHLCV（不复权）"
    sort_order = 10
    concurrency = 5                  # 1 task 内最多 5 个单元并发
    rate_limit = (200, 60.0)         # 200 次 / 60 秒（Tushare 全局配额，本 task 共享）
    default_params = {"days": 7, "source": "tushare"}
    full_params = {"days": None, "start_date": "2015-01-01"}

    def __init__(self, fetcher: KlineTushareFetcher, kline_repo: KlineRepo) -> None:
        super().__init__()
        self._fetcher = fetcher
        self._kline_repo = kline_repo

    async def list_units(self, params: dict) -> list[str]:
        if params.get("symbols"):
            return params["symbols"]
        symbols = await self.ctx.universe.list_symbols(exchange=params.get("exchange"))
        return symbols

    async def collect_one(self, unit: str, params: dict) -> UnitResult:
        end = date.fromisoformat(params["end_date"]) if params.get("end_date") else date.today()
        start = (
            date.fromisoformat(params["start_date"])
            if params.get("start_date")
            else end - timedelta(days=params.get("days", 7))
        )
        # 1) 限流（RedisCache.rate_limit 滑动窗口，跨 task + 跨进程共享 Tushare 配额）
        allowed, _ = await self.ctx.cache.rate_limit("throttle:tushare", 200, 60)
        if not allowed:
            raise RateLimited(retry_after=60.0)
        # 2) 调 fetcher（直接，无 gateway）
        klines = await self._fetcher.fetch(
                symbol=unit, start_date=start.isoformat(), end_date=end.isoformat(),
            )
        # 3) 写库（直接调 repo，不经过 stock_info_service）
        saved = await self._kline_repo.save_batch(klines)
        return UnitResult(success=True, detail=unit, saved_count=saved)
```

**关键变化**：

| 维度 | 现状 | 回退后 |
|:--|:--|:--|
| 基类 | `DeclarativeCollectTask` | `BaseCollectTask` |
| 调 fetcher 路径 | `DeclarativeCollectTask.run` → `stock_info_service.collect` → `gateway.fetch` → 装饰器链 → `TushareDailyKlineAdapter.fetch` | **task 直接调 `KlineTushareFetcher.fetch`** |
| 限流 | `ThrottleDecorator`（装饰在 adapter 链上） | **`RedisCache.rate_limit` 滑动窗口（task 内 `await cache.rate_limit(...)`）** |
| 并发 | `asyncio.gather(concurrency=5)` 单元并发 | **保留** + `Semaphore` 保护 |
| 入库 | `kline_repo.save_batch(BO)`（经过 service） | **`kline_repo.save_batch(BO)`**（直接） |

## 7. 1 个 fetcher 的样例

**现状**（`data/infrastructure/fetcher/kline.py`）：

```python
# 现状
class TushareDailyKlineAdapter(DailyKlinePort, TushareAdapterBase):
    origin = "tushare"
    priority = 1

    async def fetch(self, params: DailyKlineParams) -> list[KlineBO]:
        df = self._client.pro.daily(...)
        return [KlineBO.model_validate(row.to_dict()) for _, row in df.iterrows()]
```

**回退后**（`collect/infrastructure/fetcher/kline_tushare.py`）：

```python
# 命名：业务名 + 数据源 + Fetcher
class KlineTushareFetcher(BaseFetcher):
    """日 K 线 fetcher（Tushare 数据源）"""
    fetcher_type = "kline_tushare"     # 注册用
    source = "tushare"

    def __init__(self, client: TushareClient) -> None:
        self._client = client

    async def fetch(self, *, symbol: str, start_date: str, end_date: str) -> list[KlineBO]:
        df = self._client.pro.daily(
            ts_code=symbol,
            start_date=start_date.replace("-", ""),
            end_date=end_date.replace("-", ""),
        )
        return [KlineBO.model_validate(row.to_dict()) for _, row in df.iterrows()]
```

**SDK 客户端**（`collect/infrastructure/sdk/tushare.py`）：

```python
class TushareClient:
    """Tushare SDK 封装（init / 调用 / 限频参数）"""
    def __init__(self, token: str) -> None:
        import tushare as ts
        ts.set_token(token)
        self.pro = ts.pro_api()

    # 业务方法（如有特定初始化）放这里
```

**关键变化**：
- 类名 `KlineTushareFetcher`（不是 `TushareDailyKlineAdapter`）
- 文件名 `kline_tushare.py`（业务+源 1 文件 1 类）
- 移到 `collect/infrastructure/fetcher/`（不是 `data/infrastructure/fetcher/`）
- 继承 `BaseFetcher`（不是 `DailyKlinePort + TushareAdapterBase`）
- 没有 `port` 类了——`KlineBO` 直接 import 作为返回类型
- 没有 `priority` 了——**没有多源选择**——`source` 1:1 映射到 fetcher

## 8. SDK 与 fetcher 的关系

```
collect/infrastructure/
├── sdk/
│   ├── tushare.py      ← TushareClient（init / 配置 / 全局 pro）
│   ├── adata.py        ← AdataClient
│   └── tdx.py          ← TdxClient
├── fetcher/
│   ├── base.py         ← BaseFetcher（fetch 接口 + 错误类型 + FetchResult）
│   ├── kline_tushare.py       ← KlineTushareFetcher(client=TushareClient)
│   ├── kline_adata.py         ← KlineAdataFetcher(client=AdataClient)
│   ├── stock_basic_tushare.py
│   ├── concept_tushare.py
│   ├── concept_membership_adata.py
│   ├── concept_reason_adata.py
│   ├── minute_kline_tushare.py
│   └── ...
└── ...
```

**SDK 客户端是无业务语义的"纯 SDK 包装"**——**1 个 Tushare token 1 个 `TushareClient` 单例**。
**Fetcher 是有业务语义的"取数逻辑"**——**每个业务+源 1 个 fetcher**——**1 个 task 持有 1 个 fetcher**。

## 10. 与 `stock_info_service` 的关系

**回退前**：

```
DailyKlineCollectTask
  └─ DeclarativeCollectTask.run
       └─ stock_info_service.collect(req)        ← 业务入口
            └─ gateway.fetch(DailyKlinePort)     ← 取数
            └─ kline_repo.save_batch(...)         ← 入库
```

**回退后**：

```
DailyKlineCollectTask.collect_one
  ├─ allowed, _ = await self.ctx.cache.rate_limit("throttle:tushare", 200, 60)   ← 限流（滑动窗口）
  ├─ KlineTushareFetcher.fetch(symbol, start, end)    ← 取数
  └─ kline_repo.save_batch(BO)                        ← 入库
```

**`stock_info_service` 的 `collect` 方法**——**删除**。**HTTP 入口**（`POST /klines/collect`）——**改调** `job_service.run_one("daily_kline", symbol, params)`——**由 task 完成入库**。

**`stock_info_service` 保留的方法**（不删）：
- `get_klines(symbol, range)`：业务查询
- `get_stock_info(symbol)`：业务查询
- `list_stocks(filter)`：业务查询
- `upsert_stock_info(...)`：HTTP 入参同步股票基本信息（手动触发）

**这些方法**——**迁到** `collect/application/service/stock_query_service.py` 与 `collect/application/service/kline_query_service.py`（合并到 `collect` 上下文）。
