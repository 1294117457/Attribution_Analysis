## 1. 双数据源现状

### 1.1 配置

`attribution-app/src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    dynamic:
      primary: biz          # 默认 = 业务库
      strict: true          # ★ 漏标 @DS 立即报错，不静默连错库
      datasource:
        biz:
          url: ${SPRING_DATASOURCE_BIZ_URL:jdbc:postgresql://localhost:5432/attribution}
          username: ${DB_USERNAME:postgres}
          password: ${DB_PASSWORD:password}
        raw:
          url: ${SPRING_DATASOURCE_RAW_URL:jdbc:postgresql://localhost:5432/raw_data}
          username: ${DB_USERNAME:postgres}
          password: ${DB_PASSWORD:password}
      hikari:
        maximum-pool-size: ${DB_POOL_MAX_SIZE:10}
        minimum-idle: ${DB_POOL_MIN_IDLE:2}
        connection-timeout: ${DB_POOL_CONNECTION_TIMEOUT:30000}
        idle-timeout: ${DB_POOL_IDLE_TIMEOUT:600000}
        max-lifetime: ${DB_POOL_MAX_LIFETIME:1800000}
        leak-detection-threshold: ${DB_POOL_LEAK_DETECTION:60000}
        pool-pre-ping: true
```

> 📌 **旧的单数据源配置（`spring.datasource.url` / `.username` / `.password` / `.hikari`）已整体删除** ——
> 与 `dynamic` 段共存会导致行为不确定。
>
> 📌 **两库共用一份用户名密码**（`DB_USERNAME` / `DB_PASSWORD`）—— 同 host 同 owner，
> 避免「同一语义配多处」的历史问题（`基础设施规范.md` §7.2）。

**启动日志实测**：
```
dynamic-datasource initial loaded [2] datasource, primary datasource named [biz]
```

### 1.3 依赖落位（⚠️ 与旧规范不同）

| 模块 | 是否引入 `dynamic-datasource-spring-boot3-starter` | 说明 |

### 3.2 命名说明（⚠️ 与 step1 文档略有出入）

**实施时发现 Spring Bean 名冲突**（两个类的默认 bean 名都是 `poolMembershipQueryMapper`）：

```

for bean class [com.attribution.concept.mapper.PoolMembershipQueryMapper]
```

|---|---|---|
| market | `StockPoolMembershipQueryMapper` | `mapper/row/StockPoolMembershipRow` |

### 4.2 顺带修掉的 SQL 缺陷

| 缺陷 | 现象 | 修法 |
|---|---|---|
| `ROUND(double, int)` 不存在 | `function round(double precision, integer) does not exist` | `ROUND(((n_income / revenue) * 100)::numeric, 2)` |

> 📌 `fundamental_income.n_income` / `revenue` 都是 `double precision`，
> 而 PG 的 `round(numeric, int)` 只接受 `numeric` —— **必须显式转型**。
> 这个缺陷在表名错误时一直被掩盖着（表不存在 → 根本走不到这行 SQL）。

### 4.3 空集合防护

两个 `PoolMembershipQueryMapper.xml` 的 `<foreach>` 均加 `<choose>` 兜底
（`Mapper层规范.md` §2.3.3 双保险原则）：

```xml
WHERE m.symbol IN
<choose>
    <when test="symbols != null and symbols.size() > 0">
        <foreach collection="symbols" item="symbol" open="(" separator="," close=")">#{symbol}</foreach>
    </when>
    <otherwise>NULL</otherwise>
</choose>
```

`StockInfoMapper.xml` 的三处 `<foreach>`（`selectConceptBriefs` / `selectStockStats` 的 3 个 CTE）同样加了 `<choose>`。

## 5. PO / VO 字段类型修正记录

### 5.1 时间列类型（PG `timestamptz` vs naive `timestamp`）

> 📌 **铁律**：PG 的 `timestamp with time zone` 列**必须**用 `OffsetDateTime`；
> 用 `LocalDateTime` 读会被驱动直接拒绝 →
> `Cannot convert the column of type TIMESTAMPTZ to requested type java.time.LocalDateTime` → **接口 500**。

| PO | 列 | 表类型 | 修正前 | 修正后 |
|---|---|---|---|---|
| `ConceptPO` | `first_seen_at` | `timestamptz` | `LocalDateTime` | `OffsetDateTime` |
| `ConceptPO` | `last_synced_at` | `timestamptz` | `LocalDateTime` | `OffsetDateTime` |
| `ConceptMemberPO` | `joined_at` | `timestamptz` | `LocalDateTime` | `OffsetDateTime` |
| `ConceptMemberPO` | `synced_at` | `timestamptz` | `LocalDateTime` | `OffsetDateTime` |
| `ConceptIndexPO` | `captured_at` | `timestamptz` | `LocalDateTime` | `OffsetDateTime` |
| `ConceptSnapshotPO` | `captured_at` | `timestamptz` | `LocalDateTime` | `OffsetDateTime` |
| `ConceptSnapshotPO` | `trade_time` | `timestamp` (naive) | `LocalDateTime` | **保持** `LocalDateTime` |
| `CollectLogPO` | 全部时间列 | `timestamptz` | `OffsetDateTime` | **保持**（本来就是对的） |
| `NewsPO` | `published_at` | `timestamp` (naive) | `LocalDateTime` | **保持** |
| `UserPO` / `StockPoolPO` / `PoolOperationPO` | 全部时间列 | `timestamp` (naive) | `LocalDateTime` | **保持**（业务库，别混改） |

> 📌 `ConceptVO.lastSyncedAt` / `firstSeenAt` 随之从 `LocalDateTime` 改为 `OffsetDateTime`
> （`ConceptDetailVO` 继承 `ConceptVO`，自动跟随）。

### 5.2 非时间列类型错配

| PO | 字段 | 表类型 | 修正前 | 修正后 |
|---|---|---|---|---|
| `SuspendPO` | `suspend_timing` | `varchar(32)` | `LocalDate` | `String` |
| `SuspendEventVO` | `suspend_timing` | 同上 | `LocalDate` | `String` |
| `NewsPO` | `id` | `bigint` | `Integer` | `Long` |
| `NewsPO` | `sentiment` | `varchar(16)` | `BigDecimal` | `String` |
| `NewsPO` | `symbols` | `varchar(10)[]` | `String` | `@TableField(exist = false)`（PG 数组列，MP 默认 TypeHandler 处理不了） |
