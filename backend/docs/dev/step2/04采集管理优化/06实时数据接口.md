## 0. 需求

1. 概念实时行情（`get_market_concept_min_ths`）不需要定时，但它也是数据采集接口，要在采集管理里统一管理。
2. 已有的分钟 K 线接口（`/minute-klines`，通达信）也纳入采集管理。

## 2. 两类接口

| | 批量采集接口（已有） | 实时接口（本文新增） |
|---|---|---|
| 目的 | 把数据**存进库** | 给页面**当前看**的数据 |
| 触发 | 手动 / 采集方案（cron）/ 任务组 | 页面请求（打开、轮询） |
| 执行 | 后台任务，有进度、可取消 | 同步返回，毫秒到秒级 |
| 结果 | 业务表 + `sys_collect_tasks` 记录 | Redis 缓存，不入库，不写任务记录 |
| 采集管理里管什么 | 参数、方案、任务组、执行记录 | 数据源、缓存策略、试查、调用统计 |
| 代码 | `BaseCollectTask` 子类 | 🆕 `BaseRealtimeQuery` 子类 |

**不把实时接口塞进 `BaseCollectTask`**：它的进度、取消、防重、任务记录对实时查询都是负担；每次查询写一条任务记录会把 `sys_collect_tasks` 刷爆。两类接口共用**目录（catalog）和采集管理页面**，执行框架分开。

## 3. 实时接口框架

### 3.1 基类 `infrastructure/adapter/realtime/base.py`

```python
class BaseRealtimeQuery(ABC):
    # 元数据（与 BaseCollectTask 同名字段，进同一棵目录树）
    name: ClassVar[str]              # "concept_minute"
    facet: ClassVar[str]             # "fundamental" / "tech"
    sub_facet: ClassVar[str]
    label: ClassVar[str]
    description: ClassVar[str]
    source: ClassVar[str]            # "ths" / "tdx"，同源限流用
    sort_order: ClassVar[int] = 100

    # 缓存策略（秒）
    ttl_trading: ClassVar[int] = 15  # 交易时段，统一 15 秒
    # 非交易时段统一缓存到下一个开盘（09:25 / 13:00），不单独配置

    @abstractmethod
    def cache_key(self, params: dict) -> str: ...
    @abstractmethod
    async def fetch(self, params: dict) -> Any: ...        # 调数据源，可抛异常
    async def fallback(self, params: dict) -> Any | None:  # 失败降级，默认无
        return None
```

### 3.2 执行入口 `application/service/realtime_app_service.py`

```python
class RealtimeAppService:
    async def query(self, name: str, params: dict) -> RealtimeResult: ...
    async def query_many(self, name: str, params_list: list[dict]) -> list[RealtimeResult]: ...
```

`RealtimeResult = {data, cached: bool, stale: bool, fetched_at, latency_ms}`

统一处理（子类只写 `cache_key` / `fetch` / `fallback`）：

| 能力 | 做法 |
|---|---|
| 缓存 | Redis `rt:{name}:{cache_key}`，值为 JSON；TTL 见 §3.3 |
| 单飞 | `SET rt:lock:{name}:{key} NX EX 5`；抢到锁的请求去取数据，没抢到的等待（最多约 2 秒）后重读缓存 |
| 同源限流 | 按 `source` 共用 `asyncio.Semaphore`：`ths=5`、`tdx=1`（`tdx` 的线程安全由 fetcher 内部锁保证，见 §5.2） |
| 超时 | 单次 `fetch` 10 秒 |
| 降级 | 失败时调用 `fallback`，结果标 `stale=true`，**不缓存**；没有降级结果就返回错误 |
| 统计 | Redis `rt:stats:{name}:{yyyymmdd}` 哈希：`calls / hits / misses / errors / latency_sum / last_error / last_error_at`，保留 7 天 |

**单进程假设**：`Semaphore` 在进程内，与 04 方案一致；多 worker 部署时限流要改成 Redis 实现。

### 3.3 缓存时长（交易时段感知）

```python
def ttl_for(now, ttl_trading) -> int:
    # 工作日 09:25–11:30、13:00–15:00 → ttl_trading
    # 11:30–13:00 → 到 13:00
    # 其余 → 到下一个工作日 09:25
```

- 非交易时段数据不变，直接缓存到下次开盘，查多少次都只请求一次数据源。
- 节假日按工作日处理（与 04 方案一致），代价只是多请求几次。

### 3.4 注册与目录

- `main.py` lifespan 里注册实时接口（与 `setup_collect_task_registry` 并列）。
- `GET /collect/catalog` 的每个接口多一个 `kind: "batch" | "realtime"`，实时接口再带 `source`、`ttl_trading`，挂在同一棵四面树下。
- 🆕 `POST /collect/realtime/{name}/query`：body 是 `params`，返回 `RealtimeResult`。采集管理「试查」用，也是通用调用入口。
- 🆕 `GET /collect/realtime/{name}/stats?days=1`：返回调用统计。

业务路由保留原有路径，内部改为调用 `RealtimeAppService`（和 04 方案里业务路由调 `run_one` 是同一思路）。

## 4. 两个实时接口

### 4.1 `concept_minute` 概念分时 / 实时行情

| 项 | 值 |
|---|---|
| 目录 | 基本面 / 概念，排在 3 个批量接口之后 |
| 参数 | `{index_code}` |
| 数据 | 当日分时 241 条（`time, price, volume, amount`）+ 头部 `pre_close, price, change, change_pct, trade_time` |
| `ttl_trading` | 15 秒 |
| 实现 | `fetcher.fetch_minute(index_code)`，调用时 `delay=0`，控频交给 `source="ths"` 的并发限制；`pre_close = price - change` |
| 降级 | `concept_index_ths` 该概念最近一条收盘 → 只有头部字段，没有分时 |

业务路由（05 §4.3 调整为走本接口）：

| 端点 | 实现 |
|---|---|
| `GET /concepts/quotes?codes=...` | `query_many("concept_minute", ...)`，只返回头部字段（兼容前端 `ConceptSnapshot`：`pct_change / color / price / prev_close / trade_time / stale`） |
| `GET /concepts/{index_code}/minute` | `query("concept_minute", {index_code})`，返回整条数据 |
| `GET /concepts/tab-by-symbol/{symbol}` | 概念的 `snapshot` 由 `query_many` 填充 |

行情和分时共用同一条缓存：列表 / Tab 查过的概念，打开分时图时直接命中缓存。

### 4.2 `stock_minute_kline` 股票分 K

| 项 | 值 |
|---|---|
| 目录 | 技术面 / K 线（与 `daily_kline` 同组） |
| 参数 | `{symbol, interval, days}`；`interval ∈ 1min/5min/15min/30min/60min`；`days`：1 分钟周期固定 1，其他周期 1–5，默认 1 |
| `cache_key` | `{symbol}:{interval}:{days}` |
| `ttl_trading` | 15 秒 |
| 实现 | 现有 `PytdxFetcher.fetch_minute_klines`，`count = 每天根数 × days`（1min 240、5min 48、15min 16、30min 8、60min 4），最多 240 根 |

「当天」指最近一个交易日：盘前、收盘后、周末显示上一个交易日，通达信按「最近 N 根」返回，不需要额外处理。多日走势看日 K，分 K 不提供 10 / 20 天。

`/minute-klines/{symbol}` 兼容旧参数 `count`：传了 `count` 就按 `count` 取（上限仍为 1200），缓存键用 `count`；新前端只传 `days`。
| 降级 | 无（分钟数据不入库）；失败返回错误，前端保留上一次的图 |

`GET /minute-klines/{symbol}` 保留路径和响应，内部改为调 `query("stock_minute_kline", ...)`。

与 `planned.py` 里的 `minute_kline`（分钟 K **入库**，批量接口，占位）是两回事：本接口只做实时查看。两者都保留，目录里用「实时」标签区分。

## 5. 顺带修复（现有分钟 K 线的问题）

### 5.1 请求根数超限

`StockExpandRow.vue` 里 `count = 每天根数 × 天数`：1 分钟周期选 10 天或 20 天时是 2,400 或 4,800 根，超过后端 `count ≤ 1200`，返回 422，图显示「暂无数据」。

修复：按 §4.2 收敛天数。前端天数选项改为：1 分钟周期只有「当天」；其他周期「当天 / 3 日 / 5 日」，去掉 10 日、20 日。改为传 `days`，最多 240 根，后端上限不用放宽。

### 5.2 并发不安全（必须加锁）

`PytdxFetcher` 所有请求共用一个 `TdxHq_API` 长连接，`run_in_executor` 允许多个线程同时读写同一个 socket，多人同时展开不同股票时，响应可能串到别人的请求上，或者直接报错。

修复：fetcher 内加一把 `threading.Lock`，把「检查连接 → 断线重连 → 分页拉取」整段包进去：

```python
class PytdxFetcher(BaseCollector):
    def __init__(self):
        ...
        self._lock = threading.Lock()

    def _fetch_sync(self, symbol, interval, count, name):
        with self._lock:
            self._ensure_connected()
            ...                     # 原有拉取逻辑
```

- 锁放在 fetcher 里，而不是只靠上层 `Semaphore`：批量接口、脚本直接调用 fetcher 时也安全。
- 单次拉取几十毫秒，加上 15 秒缓存，串行足够。看板阶段如果排队明显，再改连接池（如 3 个连接轮流用），本期不做。

### 5.3 北交所代码

`symbol_to_market` 把 8、4、92 开头的代码都当成深圳（0），北交所股票查不到数据。本期先在接口层对北交所代码直接返回「暂不支持」，不去请求通达信。

## 6. 前端刷新策略

### 6.1 轮询还是推送

**现在用轮询，看板阶段用 SSE，不用 WebSocket。**

推送不会让数据更新鲜：数据源是分钟级，后端每 15 秒才取一次，无论哪种方式，用户最多每 15 秒拿到一次新数据，区别只在于谁来发起。

| | 轮询 | SSE | WebSocket |
|---|---|---|---|
| 方向 | 客户端定时请求 | 服务端单向推送 | 双向 |
| 成本 | 最低，现有 HTTP + 缓存 | 中：一个流式接口 + 按订阅刷新 | 高：连接管理、心跳、鉴权、订阅协议 |
| 断线重连 | 无此问题 | `EventSource` 自动重连 | 需要自己写 |
| 代理 | 无需配置 | nginx 关缓冲（`X-Accel-Buffering: no`） | 需要配置协议升级 |
| 适用 | 一两个图、15 秒刷新 | 看板：同屏几十个标的，服务端统一节奏推送 | 逐笔成交、下单等双向或高频交互 |

- **现在**：展开行一个分 K 图、详情 Tab 约 13 个概念，15 秒轮询一次，请求量很小。
- **看板阶段（SSE）**：新增 `GET /realtime/stream?subs=stock_minute_kline:600519:1min,concept_minute:885525`，服务端每 15 秒对订阅集合调用 `query_many`（读同一份缓存）后推送；改订阅就重新建立连接。`RealtimeAppService` 不用改，前端把 `useRealtimePoll` 换成 `EventSource`。多 worker 部署时需要 Redis 发布订阅，届时再做。
- **不用 WebSocket**：只需要服务端往下推，没有双向交互的需求。

### 6.2 通用组合式函数 `frontend/src/composables/useRealtimePoll.ts`

```ts
useRealtimePoll(loader: () => Promise<void>, options: {
  interval: Ref<number> | number,   // 毫秒
  enabled?: Ref<boolean>,           // 例如：展开行可见、抽屉打开
})
```

规则：

- 只在**交易时段**（工作日 09:25–11:30、13:00–15:00，按北京时间）轮询；非交易时段只在打开时加载一次。
- 只在 `document.visibilityState === 'visible'` 时轮询：切走标签页就暂停，切回来立即刷新一次。
- 组件卸载时停止（`onBeforeUnmount`）。
- 上一次请求还没返回时，跳过本轮。
- 刷新时**不显示 loading 遮罩**，只在首次加载时显示，避免图表闪烁。
- 连续失败 3 次后暂停，页面显示「实时更新已暂停 · 重试」。

### 6.3 各处的刷新间隔

| 位置 | 数据 | 间隔 |
|---|---|---|
| 股票列表展开行 · 分 K（`StockExpandRow.vue`） | `stock_minute_kline` | 15 秒 |
| 股票列表展开行 · 日 K | 库中日 K | 不轮询（收盘后才更新） |
| 详情抽屉 · 概念 Tab | `concept_minute` 头部字段（`/concepts/quotes`） | 15 秒 |
| 概念分时图（后续） | `concept_minute` 整条数据 | 15 秒 |
| 股票看板 / 概念看板（后续） | 同上 | 同上；同屏多个标的合并成一次 `query_many` |

`MiniKlineChart.vue` 是纯展示组件，不改。轮询加在调用它的 `StockExpandRow.vue` 里：展开行挂载时开始，折叠（组件卸载）时停止。

刷新时替换整组数据即可（1 天 5 分钟 K 线只有 48 根，1 分钟也只有 240 根），不做增量合并。

### 6.4 界面提示

- 分 K 工具栏显示「实时 · 15 秒」标记和最后更新时间。非交易时段显示「已收盘」。
- `stale=true` 时，数字用灰色显示，悬浮提示「行情源暂不可用，显示最近收盘」。

## 10. 不做的事

- 本期不做 SSE（看板阶段按 §6.1 实施）；不做 WebSocket。
- 不做 pytdx 连接池（先用单连接加锁）。
- 不做实时数据入库（历史分时、分钟 K 入库是另外的批量接口，按需实现）。
- 实时接口不支持采集方案 / 任务组 / 执行记录。
- 缓存时长不做页面可配置，写在代码里；试运行后再按统计数据调整。
- 不做跨进程限流（单进程假设，同 04 方案）。
