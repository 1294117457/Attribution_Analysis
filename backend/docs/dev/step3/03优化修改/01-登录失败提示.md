# 01 · 登录失败没有提示

## 1. 问题描述

**复现路径**：`http://localhost:3000/login` → 输入正确邮箱 + 错误密码 → 看到 spinner 闪一下，**没有任何红框/弹窗**提示"登录失败"，仅图形验证码刷一张。

**期望**：用户应当看到明确的失败原因（账号/密码错、图形验证码错、账号禁用等）。

---

## 2. 根因分析

### 2.1 前端代码 (`LoginPage.vue` L237-258)

```vue
async function handleLogin() {
  // ... 省略 validate ...
  loginLoading.value = true
  loginCaptchaError.value = false
  try {
    await authStore.login({
      email: loginForm.email,
      password: loginForm.password,
      captcha_id: loginForm.captcha.captcha_id,
      captcha_code: loginForm.captcha.captcha_code,
    })
    ElMessage.success('登录成功')   // ← 成功有提示
    const redirect = (router.currentRoute.value.query.redirect as string) || '/home/index'
    router.push(redirect)
  } catch (e: any) {
    // 登录失败(密码错 / 验证码错 / 账号禁用):后端会回 400,刷新图形验证码
    loginCaptchaError.value = true
    loginCaptchaRef.value?.refresh()
    console.warn('login failed', e)  // ← 仅打印到控制台,UI 无任何提示
  } finally {
    loginLoading.value = false
  }
}
```

**问题**：`catch` 里只做了 3 件事：
1. `loginCaptchaError.value = true` — 给图形验证码输入框加红色边框（弱提示）
2. `refresh()` — 换一张图形验证码
3. `console.warn(...)` — 只输出到浏览器 console，**用户看不到**

成功路径用了 `ElMessage.success('登录成功')`，但失败路径**漏掉了 `ElMessage.error(...)`**。

### 2.2 后端异常类型 (`auth_app_service.py`)

后端抛 3 种业务异常：

| 异常 | 场景 |
|------|------|
| `InvalidCredentialsError` | 邮箱不存在 / 密码错 |
| `UserInactiveError` | 账号禁用（`is_active=False`） |
| `InvalidCaptchaError` | 图形验证码错/过期 |

通过全局异常处理器转成 HTTP 400/401，前端只拿到 `axios` 的 reject，**无法直接区分**。

### 2.3 现有验证码相关

- `register` / `sendVerificationCode` 失败时也只 `console.warn`，**同样的问题**
- 修复时建议一并处理

## 3. 修复方案

### 3.1 推荐方案：前端 catch 增加 `ElMessage.error(...)`

**改动文件**：`frontend/src/views/auth/LoginPage.vue`、`frontend/src/views/auth/api.ts`（可选）

**LoginPage.vue L247 附近改动**：

```diff
- } catch (e: any) {
-    // 登录失败(密码错 / 验证码错 / 账号禁用):后端会回 400,刷新图形验证码
-    loginCaptchaError.value = true
-    loginCaptchaRef.value?.refresh()
-    console.warn('login failed', e)
- }
+ } catch (e: any) {
+    // 优先使用后端返回的 message(如 "邮箱或密码错误"),否则用兜底文案
+    const msg =
+      (e?.response?.data?.message as string) ||
+      (e?.message as string) ||
+      '登录失败，请重试'
+    ElMessage.error(msg)
+    // 刷新图形验证码,避免用户重复操作同一张失效的码
+    loginCaptchaError.value = true
+    loginCaptchaRef.value?.refresh()
+ }
```

**通用兜底**：axios 的 reject 对象在 `stores/auth.ts` 或 `common/utils/http.ts` 的响应拦截器里也应该把后端 message 挂到 `e.message` 上，使 catch 处可以拿到。

**检查 `http.ts`**（需要确认）：是否有响应拦截器提取 `response.data.message`？

如果当前拦截器没做，可以在这里加：

```ts
// common/utils/http.ts 响应拦截器 (伪代码)
http.interceptors.response.use(
  (r) => r,
  (err) => {
    const data = err?.response?.data
    const msg = data?.message || err.message
    err.message = msg  // 挂到 message 上,前端可直接读
    return Promise.reject(err)
  },
)
```

### 3.2 安全考虑：是否要区分异常

`★ 不确定点 Q1 ─────────────────────────────────────`
- 用户可能希望区分"账号不存在 / 密码错 / 图形验证码错"，但**会泄露账号是否存在**（账号枚举攻击）
- 后端特意把"邮箱不存在"和"密码错"合并为同一种异常（`InvalidCredentialsError`）
- 建议：**前端统一文案** `"邮箱或密码错误，或图形验证码错误，请重试"`
- **可选优化**：账号禁用是独立异常，可以单独提示 `"账号已被禁用，请联系管理员"`
- `──────────────────────────────────────────────────`
