### 1.3 Port 草案（query.py）

```python
# src/contexts/news/application/port/query.py（草案，阶段 1 占位）

"""新闻读 Port 草案

阶段 2 实施时：
- NewsQueryPort 实现由 NewsReadService 承担
- 数据来源：news_raw（原始数据）+ news_classified（分类后）
- 跨 context 调用：通过这个 port 暴露
"""
from __future__ import annotations
from datetime import datetime
from typing import Optional, Protocol, runtime_checkable


@dataclass(frozen=True)
class NewsItemVO:
    """新闻 VO（最小可序列化视图）"""
    news_id: int
    title: str
    summary: str
    content: str
    source: str
    url: str
    published_at: datetime
    captured_at: datetime
    # 分类标签（阶段 2 才填）
    impact_scope: Optional[str] = None       # market / industry / stock
    content_nature: Optional[str] = None     # policy / financial / operation / governance / risk / international
    time_sensitivity: Optional[str] = None   # breaking / scheduled / in-depth / rumor
    sentiment: Optional[str] = None         # positive / negative / neutral / mixed
    source_credibility: Optional[str] = None # official / mainstream / institutional / community
    causality: Optional[str] = None          # driving / reflective / retrospective
    duration: Optional[str] = None           # pulse / trend / noise
    subject: Optional[str] = None            # self / supply_chain / regulator / macro
    related_symbols: list[str] = field(default_factory=list)
    related_concepts: list[int] = field(default_factory=list)


@runtime_checkable
class NewsQueryPort(Protocol):
    """新闻读 Port（其他 context 想知道"新闻"就调这个）"""
    
    async def get_by_id(self, news_id: int) -> Optional[NewsItemVO]:
        """单条新闻"""
        ...
    
    async def list_by_time(
        self, start: datetime, end: datetime,
        *, categories: Optional[list[str]] = None,
        symbols: Optional[list[str]] = None,
        concept_ids: Optional[list[int]] = None,
        limit: int = 100,
        offset: int = 0,
    ) -> list[NewsItemVO]:
        """按时间窗口 + 多维筛选"""
        ...
    
    async def list_for_symbol(
        self, symbol: str, *,
        start: Optional[datetime] = None,
        end: Optional[datetime] = None,
        limit: int = 50,
    ) -> list[NewsItemVO]:
        """某只股票相关新闻"""
        ...
    
    async def list_for_concept(
        self, concept_id: int, *,
        start: Optional[datetime] = None,
        end: Optional[datetime] = None,
        limit: int = 50,
    ) -> list[NewsItemVO]:
        """某概念相关新闻"""
        ...
    
    async def search(
        self, keyword: str, *,
        start: Optional[datetime] = None,
        end: Optional[datetime] = None,
        limit: int = 50,
    ) -> list[NewsItemVO]:
        """关键词搜索（标题 + 摘要）"""
        ...
```

### 1.8 数据库表（阶段 2 才建）

```sql
-- news_raw：原始新闻（每条一行）
CREATE TABLE news_raw (
    id BIGSERIAL PRIMARY KEY,
    source TEXT NOT NULL,                -- cailianpress / sina / eastmoney / ths
    external_id TEXT NOT NULL,           -- 源站的 ID
    title TEXT NOT NULL,
    summary TEXT,
    content TEXT,
    url TEXT,
    published_at TIMESTAMPTZ NOT NULL,
    captured_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    raw_payload JSONB,                   -- 原始 payload（备用）
    UNIQUE (source, external_id)
);

-- news_classified：分类后新闻
CREATE TABLE news_classified (
    news_id BIGINT PRIMARY KEY REFERENCES news_raw(id) ON DELETE CASCADE,
    impact_scope TEXT,
    content_nature TEXT,
    time_sensitivity TEXT,
    sentiment TEXT,
    source_credibility TEXT,
    causality TEXT,
    duration TEXT,
    subject TEXT,
    classified_at TIMESTAMPTZ,
    classifier_version TEXT              -- 'rule-v1' / 'llm-v1' / 'hybrid-v1'
);

-- news_symbol_rel：新闻-股票关联
CREATE TABLE news_symbol_rel (
    news_id BIGINT REFERENCES news_raw(id) ON DELETE CASCADE,
    symbol TEXT NOT NULL,
    mention_type TEXT NOT NULL,          -- primary / secondary / mentioned
    PRIMARY KEY (news_id, symbol)
);

-- news_concept_rel：新闻-概念关联
CREATE TABLE news_concept_rel (
    news_id BIGINT REFERENCES news_raw(id) ON DELETE CASCADE,
    concept_id INT NOT NULL,
    confidence REAL,
    PRIMARY KEY (news_id, concept_id)
);
```

### 2.4 与 news context 的关系

```
news 和 sentiment 的边界：
- news：事实性内容（发生了什么）
- sentiment：观点性内容（大家怎么看）

news 的"sentiment"标签是 news 自己分类的一部分
sentiment 的"舆情样本"来源可以包括 news 评论 + 股吧 + 雪球

建议：
- news 自己不做情绪打分（让 sentiment 去做）
- sentiment 阶段 2 可以订阅 news 事件，自动分析新增新闻
- 阶段 2 早期：先做"股吧 + 雪球"的情绪
- 阶段 2 后期：把"新闻情绪"纳入 sentiment 数据源
```

### 3.3 各占位子模块的契约

#### 3.3.1 portfolio（投资组合 = 持仓）

```
职责：记录用户的"实际持仓"（区别于 stock_pool 的"关注股"）
核心实体：
  - Portfolio：组合（id / name / currency / cash / created_at）
  - Holding：持仓（portfolio_id / symbol / shares / cost_price / market_price / pnl）
  - Trade：交易记录（portfolio_id / symbol / side / shares / price / fee / executed_at）

Port 草案（阶段 2 实施）：
  PortfolioQueryPort:
    - get_portfolio(user_id, portfolio_id)
    - list_holdings(portfolio_id)
    - get_pnl_summary(portfolio_id, start, end)
  PortfolioCommandPort:
    - create_portfolio(...)
    - add_holding(...)
    - remove_holding(...)
    - record_trade(...)
```

#### 3.3.2 notes（投资笔记）

```
职责：用户的复盘 / 学习笔记
核心实体：
  - Note：笔记（id / user_id / title / content / symbol / tags / created_at）
  - NoteAttachment：附件（图片 / 文件）
  - NoteTag：标签

Port 草案：
  NoteQueryPort:
    - list_notes(user_id, *, symbol, tag, keyword, page)
    - get_note(note_id)
    - search_notes(keyword, *, user_id)
  NoteCommandPort:
    - create_note(...)
    - update_note(...)
    - delete_note(...)
```

#### 3.3.3 watchlist_preferences（看板自定义）

```
职责：用户对"股票信息"页面布局的个性化设置
核心实体：
  - PanelLayout：用户保存的面板布局（user_id / name / layout_json / is_default）
  - DensityPreference：密度偏好（user_id / page_density / top_density / table_density / bottom_density）
  - ColumnPreference：列偏好（user_id / page / column_name / visible / width / order）

Port 草案：
  PanelPrefQueryPort:
    - get_layout(user_id, name)
    - list_layouts(user_id)
  PanelPrefCommandPort:
    - save_layout(user_id, name, layout_json)
    - delete_layout(user_id, name)
```

### 4.2 必填的元数据（每个 README 必含）

| 字段 | 说明 |
| :-- | :-- |
| 职责 | 一句话说清这个 context 干什么 |
| 数据源 | 用哪些数据（外部 + 内部） |
| 主要用户 | 谁会调（前端 / 其他 context / 调度任务） |
| 阶段 | 阶段 1（已实现）/ 阶段 2（占位） |
| 与 data context 边界 | 哪些走 data、哪些自己采集 |
| 跨 context 依赖 | 依赖谁（必须用 port 形态） |
| 实施计划 | 阶段 2 实施时的 checklist |

### 4.3 阶段 1 写什么 / 不写什么

**写**：
- README.md（完整）
- `application/port/query.py` 的 Protocol 草案（哪怕只是类型签名）
- `bootstrap.py`（noop + 注释）
- 必要的 `__init__.py` 和 `.gitkeep`

**不写**：
- entity / vo / repository（阶段 2 才建）
- service 实现
- ORM 模型
- 适配器
- 路由
- schema

### 4.4 占位阶段如何"被依赖"

**重要**：其他 context **不应** import 占位 context（即使它的 Port 草案已写好）。

原因：
- Port 草案是"未来形态"，没实现
- 如果其他 context 提前 import，未来改动会破坏现有代码
- 等阶段 2 实施时，再"正式"开放 Port

**例外**：可以在文档/讨论中"按 port 草案"规划依赖，但代码里**不写 import**。
