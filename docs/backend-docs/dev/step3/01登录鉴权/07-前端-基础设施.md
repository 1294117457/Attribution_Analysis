## 2. `utils/request.ts` — axios 实例 + 拦截器

### 2.1 职责

1. 创建 axios 实例（baseURL = `/api/v1`）
2. **请求拦截器**：自动加 `Authorization: Bearer <access_token>`
3. **响应拦截器**：
   - 解析 `{code, message, data}` 格式
   - 业务码非 200/201 → 弹错 + reject
   - **401 → 用 refresh_token 自动换新 + 重放原请求**
4. 并发 refresh 保护（多个 401 同时到达 → 只发一次 refresh 请求）

### 2.2 关键代码骨架

```typescript
// frontend/src/utils/request.ts
import axios, { AxiosError, InternalAxiosRequestConfig } from 'axios'
import { ElMessage } from 'element-plus'

const service = axios.create({
  baseURL: '/api/v1',
  timeout: 30000,
})

// ── 请求拦截器：自动带 token ──
service.interceptors.request.use(
  (config: InternalAxiosRequestConfig) => {
    const token = localStorage.getItem('access_token')
    if (token && config.headers) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  },
  (error) => Promise.reject(error),
)

// ── 响应拦截器：自动刷新 + 业务码处理 ──
let isRefreshing = false
let pendingRequests: Array<(token: string) => void> = []

service.interceptors.response.use(
  (response) => {
    const { code, message, data } = response.data
    if (code === 200 || code === 201) {
      return data   // 直接返数据，路由里 `await request.post(...)` 就拿到 data
    }
    ElMessage.error(message || '请求失败')
    return Promise.reject(new Error(message || '请求失败'))
  },
  async (error: AxiosError) => {
    const originalRequest: any = error.config
    const status = error.response?.status

    if (status === 401 && !originalRequest._retry) {
      const refreshToken = localStorage.getItem('refresh_token')
      if (!refreshToken) {
        localStorage.clear()
        window.location.href = '/login'
        return Promise.reject(error)
      }

      // 防止并发 refresh
      if (isRefreshing) {
        return new Promise((resolve) => {
          pendingRequests.push((token: string) => {
            originalRequest.headers.Authorization = `Bearer ${token}`
            resolve(service(request))
          })
        })
      }

      originalRequest._retry = true
      isRefreshing = true

      try {
        const { data } = await axios.post('/api/v1/auth/refresh', {
          refresh_token: refreshToken,
        })

        localStorage.setItem('access_token', data.access_token)
        localStorage.setItem('refresh_token', data.refresh_token)

        isRefreshing = false
        pendingRequests.forEach((cb) => cb(data.access_token))
        pendingRequests = []

        originalRequest.headers.Authorization = `Bearer ${data.access_token}`
        return service(request)
      } catch (refreshError) {
        isRefreshing = false
        localStorage.clear()
        window.location.href = '/login'
        return Promise.reject(refreshError)
      }
    }

    ElMessage.error((error.response?.data as any)?.message || '网络错误')
    return Promise.reject(error)
  },
)

export default service
```

### 2.3 关键设计

| 项 | 选型 | Why |
|---|---|---|
| `baseURL: '/api/v1'` | 与 vite proxy 对应 | 开发时 `/api/v1` → `http://localhost:8000/api/v1`（看 vite.config.ts）|
| 响应直接返 `data` | 业务码 200/201 透传 | 路由写 `const data = await request.post(...)` 不需要再 `data.data` |
| 401 自动 refresh | 拦截器 | 用户无感；axios 内部用 fetch_token 也能看到 retry 标志 |
| 并发 refresh 保护 | `isRefreshing + pendingRequests` | 多个请求同时 401 → 只调一次 /auth/refresh |
| refresh 失败 → 跳登录 | `localStorage.clear()` + 跳转 | 用户被禁用或 refresh 过期，强制重登 |
| 业务错用 `ElMessage` | element-plus 集成 | 与现有项目 UI 一致 |

### 3.3 关键代码骨架

```typescript
// frontend/src/api/auth.ts
import request from '@/utils/request'

export interface LoginData {
  email: string
  password: string
}

export interface RegisterData {
  email: string
  username: string
  password: string
  nickname?: string
}

export interface TokenResponse {
  access_token: string
  refresh_token: string
  token_type: string
  expires_in: number
  user_info?: {
    id: number
    email: string
    username: string
    nickname: string
    roles: Array<{ id: number; code: string; name: string }>
    permissions: string[]
  }
}

export const authApi = {
  register: (data: RegisterData) => request.post('/auth/register', data),
  login: (data: LoginData) =>
    request.post<any, TokenResponse>('/auth/login', data),
  refresh: (refresh_token: string) =>
    request.post<any, TokenResponse>('/auth/refresh', { refresh_token }),
  logout: () => request.post('/auth/logout'),
  getMe: () => request.get<any, any>('/auth/me'),
}

export const userApi = {
  listUsers: (params: {
    page: number
    page_size: number
    keyword?: string
    is_active?: boolean
  }) => request.get('/users/', { params }),
  updateStatus: (userId: number, isActive: boolean) =>
    request.patch(`/users/${userId}/status`, { is_active: isActive }),
  resetPassword: (userId: number, newPassword: string) =>
    request.post(`/users/${userId}/reset-password`, { new_password: newPassword }),
  assignRole: (userId: number, roleId: number) =>
    request.post(`/users/${userId}/roles`, { role_id: roleId }),
  removeRole: (userId: number, roleId: number) =>
    request.delete(`/users/${userId}/roles/${roleId}`),
}

export const roleApi = {
  listRoles: () => request.get<any, Array<{ id: number; code: string; name: string }>>('/roles/'),
}

export const permissionApi = {
  listPermissions: () => request.get('/permissions/'),
}
```

### 3.4 关键设计

| 项 | 选型 | Why |
|---|---|---|
| `request<T, R>` 两泛型 | T=request body，R=response data | axios 默认 `request<T = any, D = any>` 顺序容易混 |
| 通用入参/返回 TS 类型 | 与后端 DTO 对齐 | IDE 自动补全 |
| 错误由拦截器处理 | 业务码非 200 → ElMessage.error | 路由代码不用 try/catch 每个调用 |

## 4. `stores/auth.ts` — Pinia store

### 4.1 文件位置

`frontend/src/stores/auth.ts`（新文件）

### 4.2 状态

| ref | 类型 | 来源 | 用途 |
|---|---|---|---|
| `accessToken` | `string` | localStorage | 接口调用 |
| `refreshToken` | `string` | localStorage | 刷新 token |
| `userInfo` | `UserInfo | null` | 后端 `/auth/me` | 展示/判断权限 |

### 4.3 computed / 方法

| 名称 | 类型 | 用途 |
|---|---|---|
| `isLoggedIn` | `computed` | 是否已登录（有 token）|
| `roles` | `computed` | `['admin', 'member']` 等 |
| `isAdmin` | `computed` | 快速判断 admin |
| `hasRole(role)` | `function` | 是否拥有某角色 |
| `hasPermission(perm)` | `function` | 是否拥有某权限 |
| `login(email, password)` | `function` | 调 `/auth/login` + 存 token + fetchMe |
| `register(data)` | `function` | 调 `/auth/register` |
| `logout()` | `function` | 调 `/auth/logout` + 清 token |
| `clear()` | `function` | 仅清本地，不调后端 |
| `fetchMe()` | `function` | 调 `/auth/me` 拉用户信息 |

### 4.4 关键代码骨架

```typescript
// frontend/src/stores/auth.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { authApi } from '@/api/auth'

export interface UserInfo {
  id: number
  email: string
  username: string
  nickname: string
  avatar_url?: string
  is_active: boolean
  roles: Array<{ id: number; code: string; name: string }>
  permissions: string[]
}

export const useAuthStore = defineStore('auth', () => {
  // ── state ──
  const accessToken = ref(localStorage.getItem('access_token') || '')
  const refreshToken = ref(localStorage.getItem('refresh_token') || '')
  const userInfo = ref<UserInfo | null>(null)

  // ── getters ──
  const isLoggedIn = computed(() => !!accessToken.value)
  const roles = computed(() => userInfo.value?.roles.map((r) => r.code) || [])
  const isAdmin = computed(() => roles.value.includes('admin'))

  function hasPermission(perm: string): boolean {
    return userInfo.value?.permissions.includes(perm) || false
  }
  function hasRole(role: string): boolean {
    return roles.value.includes(role)
  }

  // ── actions ──
  async function login(email: string, password: string) {
    const result = await authApi.login({ email, password })
    accessToken.value = result.access_token
    refreshToken.value = result.refresh_token
    localStorage.setItem('access_token', result.access_token)
    localStorage.setItem('refresh_token', result.refresh_token)
    // 用 user_info 里的 store（后端已返），省一次 /me
    if (result.user_info) {
      userInfo.value = {
        ...result.user_info,
        is_active: true,
      }
    } else {
      await fetchMe()
    }
  }

  async function register(data: {
    email: string
    username: string
    password: string
    nickname?: string
  }) {
    await authApi.register(data)
  }

  async function logout() {
    try {
      await authApi.logout()
    } catch {
      // 即使后端失败也清前端
    }
    clear()
  }

  function clear() {
    accessToken.value = ''
    refreshToken.value = ''
    userInfo.value = null
    localStorage.removeItem('access_token')
    localStorage.removeItem('refresh_token')
  }

  async function fetchMe() {
    const data = await authApi.getMe()
    userInfo.value = data
  }

  return {
    accessToken,
    refreshToken,
    userInfo,
    isLoggedIn,
    roles,
    isAdmin,
    hasPermission,
    hasRole,
    login,
    register,
    logout,
    fetchMe,
    clear,
  }
})
```

### 4.5 关键设计

| 项 | 选型 | Why |
|---|---|---|
| 登录后用 `user_info` 缓存 | 后端 login 响应已包含 | UX 快 200ms |
| `clear()` 与 `logout()` 分离 | 清理本地 / 通知服务端 | 401 自动跳转时用 `clear()` |
| `hasRole/Permission` 函数 | 不用 computed | 调用时即时判断 |
| token 存 localStorage | 简单 | 当前 SPA 无 CSRF 担忧 |
| `userInfo` 不持久化 | 每次启动拉 `/auth/me` | 数据最新；token 单独存 |
