## 0. 问题澄清（先看这一段）

用户问的 3 个核心问题，逐一回答：

### Q1: 底层 Protocol + 上层编排的关系，对吗？

**对**。两层职责分明：

| 层 | 是什么 | 回答什么问题 |
| :- | :- | :- |
| **L1 数据源 API 抽象** | 1 个统一 `DataSourceAPI` Protocol + 3 个实现类（Tushare/Adata/Pytdx） | "这个数据源能做什么、用什么方法名调用" |
| **L2 编排调度** | `Pipeline` 声明式配置（steps + schedule） | "采什么数据、何时采、按什么顺序" |

**关键约束**：L2 pipeline 配置里的 `step.method` 必须是 L1 Protocol 暴露的方法名（**字符串引用，运行时 dispatch**）。改 L1 方法名 → L2 配置同步改（启动期校验）。

### Q2: 调用时是否需要传参数？

**需要传**。**参数处理在编排层（L2）完成**，底层（L1）方法签名保持裸方法 + 原始参数。

```python
# L1 Protocol 方法（裸方法 + 原始参数）
async def fetch_kline(self, symbol: str, days: int) -> list[KlineBO]
async def fetch_daily_basic(self, trade_date: str) -> list[FinDailyBasicBO]
async def fetch_income(self, ts_code: str, start_date: str | None) -> list[FinReportBO]

# L2 Pipeline 处理参数（UnitResolver 生成 unit + 模板渲染）
Pipeline(
    unit=UnitSpec(unit_source="stock_infos", ...),  # 生成 {"label": "600519", "symbol": "600519"}
    steps=(APIStep(
        method="fetch_kline",
        args_template={
            "symbol": "{{symbol}}",                          # ← 从 unit 取
            "days": "{{params.days|default(7)}}",           # ← 从外部 params 取
        },
    ),),
)
```

**为什么这样分工**：
- L1 保持"做什么"的语义（symbol / trade_date / ts_code），看方法名就知道传什么
- L2 处理"从哪里来"（DB 拉单元 / 模板渲染 / 默认值 / 类型转换）
- 加新数据源 = 实现 L1 即可，不用碰 L2；加新采集任务 = 改 L2 配置即可，不用碰 L1

### Q3: 兼容性怎么处理？

**不考虑兼容**（已确认）。具体动作：

| 现状 | 重构后 |
| :- | :- |
| 6 个小 Protocol（KlineFetcher / DailyBasicFetcher / StockBasicFetcher / FinReportFetcher / MinuteKlineFetcher / ConceptFetcher） | **全部删除**，合并为 1 个 `DataSourceAPI` |
| 老路由层调用 `get_registry().get(KlineFetcher)` | 改为 `data_source_registry.get("Tushare").fetch_kline(...)` |
| `BaseCollectTask` 8 个 ready 子类 | **P0 阶段保留**（不重写）；新 pipeline 配置并存 |
| `BaseCollectTask` 15 个 planned 空壳 | **P0 阶段删除**，由 pipeline 配置完全替代 |

## 0.5 TL;DR

**两层重构**（解耦方向相反，**只做这两件事就够了**）：

| 层 | 现状 | 重构后 |
| :- | :- | :- |
| **L1 数据源 API 抽象** | 6 个 Protocol 按"数据类型"切分 | **1 个统一 Protocol** `DataSourceAPI`，**所有方法统一 async，统一返回 `CallResult(ok, data, error)`** |
| **L2 编排调度层** | 每个 task 类自己写流程 | **`Pipeline` 声明式配置**，1 个或 N 个 step 自由组合，可工作流可单步 |

**核心成果**：
- 加新数据源（Wind）实现 `WindAPI` 类 + 注册一行（≤ 50 行）
- 加新采集任务（cap_moneyflow）= 1 段 ~20 行 pipeline 配置，**不写 Python 类**
- 多 API 工作流（盘后同步 = 3 步）= 同 1 个 pipeline 内 step1 → step2 → step3
- **不考虑兼容**：P0 阶段直接删除 6 个老 Protocol，改写路由调用方

**核心抽象对应**：

```
L1 底层 = 1 个 DataSourceAPI Protocol（统一形态）+ 6 个细粒度 Protocol（按业务切）
       + 3 个实现类（TushareAPI / AdataAPI / PytdxAPI）
L2 编排 = Pipeline（1 个或 N 个 APIStep）+ UnitResolver（生成单元）+ PipelineRunner（执行）
```

## 1. 现状盘点（精简）

### 1.1 底层 fetcher 现状（6 个小 Protocol）

```
application/port/collector_port.py

├── MinuteKlineFetcher   fetch_minute_klines(symbol, interval, count, name) → [MinuteKlineBO]
├── StockBasicFetcher    fetch_stock_basic(params) → [StockInfoBO]
├── DailyBasicFetcher    fetch_daily_basic(trade_date) → [FinDailyBasicBO]
├── FinReportFetcher     fetch_income(ts_code, start_date, end_date) → [FinReportBO]
└── ConceptFetcher       fetch_concept_list / fetch_constituents / ... (5 个方法)

infrastructure/adapter/
├── base.py                    BaseCollector (基类，只有 logger/source_name)
├── tushare/fetcher.py         TushareFetcher (实现 Kline/StockBasic/DailyBasic/FinReport)
```

**痛点**：
- 6 个 Protocol 各自方法签名不同，**调用方必须先知道 Protocol 类型**才能 `registry.get(XxxFetcher)`
- `TushareFetcher` 一个类实现 4 个 Protocol，签名散落
- 新数据源要写 1 个 fetcher 类 + 1 个 Protocol + 在 registry 注册 3 步

### 1.2 任务层现状（8 个 ready + 15 个 planned）

| 维度 | 数量 | 备注 |
| :- | :- | :- |
| ready 任务 | 8 | daily_kline / daily_basic / stock_basic / fin_report / concept / concept_membership / concept_index_th / concept_snapshot |
| planned 占位 | 15 | 大多 ORM 表已建，只差 fetcher + task 类 |
| 重复样板 | ~70% | 每个 task 类都有"拉列表 → 调 fetcher → 写库 → 上报进度" |
| 调度 | **无** | 全靠用户手动点 UI，没有 cron |

## 2. 重构后的两层架构

### 2.1 总览图

```
┌─────────────────────────────────────────────────────────────────────┐
│  L2 编排调度层 (Collection Pipeline)                                 │
│  回答："要做什么 + 何时做"                                            │
│  = Pipeline (JSON 配置) = [APIStep 1, APIStep 2, ...] + ScheduleSpec │
│  例：                                                               │
│    pipeline "daily_kline":  [step(tushare.fetch_kline)]            │
│                              + cron "0 17 * * 1-5"                 │
│    pipeline "sync_morning": [step(adata.fetch_concept_list),       │
│                              step(tushare.fetch_stock_basic),      │
│                              step(tushare.fetch_daily_basic)]      │
│                              + cron "0 9 * * 1-5"                  │
├─────────────────────────────────────────────────────────────────────┤
│  L1 数据源 API 抽象层 (DataSourceAPI)                                │
│  回答："怎么调数据源"                                                │
│  = 1 个统一 Protocol: call(method_name, **kwargs) → BO[]           │
│  实现：TushareAPI / AdataAPI / PytdxAPI / AkShareAPI / ...          │
└─────────────────────────────────────────────────────────────────────┘
                          │
                          ▼
                  PostgreSQL + Redis
```

### 2.2 关键设计原则

1. **L1 只解决"怎么调"**：1 个 Protocol、1 个调用形态、所有数据源一致
2. **L2 只解决"调什么 + 何时调"**：声明式 JSON 配置，不写代码
3. **L2 是 L1 的消费方**：编排层用 `DataSourceAPI.call()` 而不是直接调 fetcher 方法
4. **存量代码不动 L1 的方法名**：TushareFetcher 的 `fetch_kline / fetch_daily_basic` 等方法名就是 L2 配置里的 `method_name`，**0 改名**

## 3. L1 数据源 API 抽象层

### 3.1 统一 Protocol（**真实方法名 + 统一 async + CallResult**）

```python
# application/port/data_source_api.py（新）

from typing import Protocol, runtime_checkable, Any
from dataclasses import dataclass


@dataclass(frozen=True)
class CallResult:
    """统一返回：成功/失败 + 数据 + 元信息

    编排层统一检查 ok 字段；失败不靠 raise。
    """
    ok: bool
    data: Any = None                # BO 列表 / dict / 单值
    error: str | None = None
    elapsed_ms: int = 0
    source: str = ""                # "Tushare" / "Adata" / ...


@runtime_checkable
class DataSourceAPI(Protocol):
    """统一数据源 API 协议

    设计原则：
      - **方法名 = 真实业务方法名**（fetch_kline / fetch_daily_basic / fetch_income...）
        不是 call(method_name) 形式，方便 IDE 跳转、静态类型检查
      - **所有方法 async def**（同步阻塞实现内部 asyncio.to_thread）
      - **所有方法返回 CallResult**（不靠 raise 表达错误，编排层统一处理）
      - **方法签名 = 业务参数**（symbol / trade_date / ts_code），不传 BO / 不传请求对象
        参数处理由编排层 Pipeline + UnitResolver 负责

    任何数据源（Tushare / Adata / Pytdx / Wind / Choice...）
    只要实现这个 Protocol，就能被编排调度层无差别调用。
    """

    @property
    def source_name(self) -> str: ...

    @property
    def available_methods(self) -> list[str]:
        """返回该数据源支持的方法列表（启动期校验用）"""
        ...


# ── 具体的"业务方法协议"（用 Protocol 描述，跨数据源实现） ────────

class KlineAPI(Protocol):
    """日 K 线协议（任何数据源实现此协议即支持）"""
    async def fetch_kline(self, symbol: str, days: int) -> CallResult: ...


class DailyBasicAPI(Protocol):
    """日频估值协议"""
    async def fetch_daily_basic(self, trade_date: str) -> CallResult: ...


class StockBasicAPI(Protocol):
    """股票基本信息协议"""
    async def fetch_stock_basic(self, list_status: str = "L") -> CallResult: ...


class FinReportAPI(Protocol):
    """财务报告协议"""
    async def fetch_income(self, ts_code: str, start_date: str | None = None) -> CallResult: ...


class ConceptAPI(Protocol):
    """概念协议（多个方法）"""
    async def fetch_concept_list(self) -> CallResult: ...
    async def fetch_constituents(self, index_code: str) -> CallResult: ...
    async def fetch_concepts_by_stock(self, symbol: str) -> CallResult: ...
    async def fetch_index_daily(self, index_code: str, start_date: str, end_date: str) -> CallResult: ...
    async def fetch_current(self, index_code: str) -> CallResult: ...


class MinuteKlineAPI(Protocol):
    """分钟 K 线协议（Pytdx 专用）"""
    async def fetch_minute_klines(self, symbol: str, interval: int, count: int) -> CallResult: ...
```

### 3.2 数据源实现类（一个数据源实现多个 Protocol）

```python
# infrastructure/adapter/data_source/tushare_api.py（新）

from infrastructure.adapter.tushare.fetcher import TushareFetcher
from application.port.data_source_api import (
    DataSourceAPI, CallResult, KlineAPI, DailyBasicAPI, StockBasicAPI, FinReportAPI,
)


class TushareAPI(DataSourceAPI):
    """Tushare 数据源实现

    实现 KlineAPI / DailyBasicAPI / StockBasicAPI / FinReportAPI 4 个业务协议
    所有方法 async def，内部用 asyncio.to_thread 包同步阻塞调用
    所有方法返回 CallResult，不 raise
    """

    source_name = "Tushare"

    def __init__(self, fetcher: TushareFetcher | None = None) -> None:
        self._fetcher = fetcher or TushareFetcher(KlineBO)

    @property
    def available_methods(self) -> list[str]:
        return [
            "fetch_kline",
            "fetch_stock_basic",
            "fetch_daily_basic",
            "fetch_income",
            # ... 未来 10+ 个
        ]

    # ── KlineAPI 实现 ──
    async def fetch_kline(self, symbol: str, days: int) -> CallResult:
        import time
        try:
            t0 = time.time()
            params = CollectParams(symbol=symbol, days=days)
            bos = await asyncio.to_thread(self._fetcher.fetch, params)
            return CallResult(
                ok=True, data=bos,
                elapsed_ms=int((time.time() - t0) * 1000),
                source=self.source_name,
            )
        except Exception as e:
            return CallResult(ok=False, error=str(e), source=self.source_name)

    # ── DailyBasicAPI 实现 ──
    async def fetch_daily_basic(self, trade_date: str) -> CallResult:
        import time
        try:
            t0 = time.time()
            bos = await asyncio.to_thread(self._fetcher.fetch_daily_basic, trade_date)
            return CallResult(
                ok=True, data=bos,
                elapsed_ms=int((time.time() - t0) * 1000),
                source=self.source_name,
            )
        except Exception as e:
            return CallResult(ok=False, error=str(e), source=self.source_name)

    # ── StockBasicAPI 实现 ──
    async def fetch_stock_basic(self, list_status: str = "L") -> CallResult:
        import time
        try:
            t0 = time.time()
            params = CollectParams(list_status=list_status)
            bos = await asyncio.to_thread(self._fetcher.fetch_stock_basic, params)
            return CallResult(
                ok=True, data=bos,
                elapsed_ms=int((time.time() - t0) * 1000),
                source=self.source_name,
            )
        except Exception as e:
            return CallResult(ok=False, error=str(e), source=self.source_name)

    # ── FinReportAPI 实现 ──
    async def fetch_income(self, ts_code: str, start_date: str | None = None) -> CallResult:
        import time
        try:
            t0 = time.time()
            bos = await asyncio.to_thread(self._fetcher.fetch_income, ts_code, start_date)
            return CallResult(
                ok=True, data=bos,
                elapsed_ms=int((time.time() - t0) * 1000),
                source=self.source_name,
            )
        except Exception as e:
            return CallResult(ok=False, error=str(e), source=self.source_name)

    # ── 其他 10+ 个方法（adj_factor / suspend / margin / moneyflow / top_list ...） ──
```

### 3.4 旧 Protocol 的处理

**保留**（向后兼容）：
- `KlineFetcher / DailyBasicFetcher / ...` 这些 Protocol 继续存在
- `TushareFetcher` 继续实现它们（路由层和现有 service 层照旧工作）

**新增**：
- `DataSourceAPI` Protocol（编排层专用）
- `TushareAPI / AdataAPI / PytdxAPI` 3 个适配器类（包装 fetcher，调 call()）

**结论**：**L1 重构是叠加式、不破坏现有代码**。路由层代码不动，只有"新采集任务"走 L2。

## 4. L2 编排调度层

### 4.1 三个核心概念

```
Pipeline        一个采集任务/工作流的完整定义（声明式配置）
APIStep         Pipeline 里的一个原子步骤 = "调一次数据源 API"
ScheduleSpec    "何时跑"——cron / interval / manual
```

### 4.2 Pipeline 数据结构

```python
# infrastructure/adapter/pipeline/pipeline.py（新）

from dataclasses import dataclass, field
from typing import Any


@dataclass(frozen=True)
class APIStep:
    """Pipeline 中的一个原子步骤

    调用一次数据源 API。可选地包含后续处理（落库 / 转换）。
    """
    name: str                                # "fetch_kline" / "upsert_tech_kline"
    source: str                              # 数据源名："Tushare" / "Adata"
    method: str                              # 数据源方法名："fetch_kline"
    args_template: dict[str, Any] = field(default_factory=dict)
    # ↑ 调用参数模板，支持 Jinja 占位：
    #   {"params": {"symbol": "{{unit.symbol}}", "days": 7}}
    #   {"trade_date": "{{unit.date}}"}

    save_to: str | None = None               # 可选：调用结果写表名（约定路由）
    # ↑ 旧版逻辑保留为可选 hook；新 pipeline 默认不写库，由 transform 处理

    depends_on: tuple[str, ...] = ()         # 上游步骤名（用于工作流依赖）
    skip_if: str | None = None               # Jinja 条件表达式，True 则跳过
    on_error: str = "fail"                   # fail / continue / retry


@dataclass(frozen=True)
class UnitSpec:
    """单元定义：决定一次 pipeline 跑多少个 unit

    3 种风格：
    - per_unit:    拉一组 unit（如所有 symbol / 所有日期 / 所有概念），对每个 unit 跑 1 次 steps
    - one_shot:    steps 整体只跑 1 次（unit 数=1）
    - streaming:   不分 unit，steps 内部自行迭代（适合 adata.concept_list 等一次拿全）
    """
    style: str                                # per_unit | one_shot | streaming
    # per_unit 风格：
    unit_source: str = ""                     # "stock_infos" / "trading_dates" / "concepts"
    unit_filter: dict = field(default_factory=dict)   # {"list_status": "L"}
    unit_template: dict = field(default_factory=dict) # 单元数据模板：{"label": "{{symbol}}", "args": {"symbol": "{{symbol}}"}}


@dataclass(frozen=True)
class Pipeline:
    """采集编排 Pipeline（声明式配置）

    一个 pipeline = 1 个采集任务或 1 个工作流。
    多 step 时按顺序执行，形成"多 API 工作流"。
    """
    pipeline_id: str                          # "daily_kline" / "sync_morning"
    name: str                                 # UI 显示名
    description: str = ""

    facet: str = ""                           # "tech" / "fundamental" / ...
    sub_facet: str = ""                       # "kline" / "valuation" / ...

    # ── 核心：步骤序列 ──
    unit: UnitSpec = field(default_factory=lambda: UnitSpec(style="one_shot"))
    steps: tuple[APIStep, ...] = ()

    # ── 调度（可选）──
    schedule: ScheduleSpec | None = None      # None = 仅手动触发

    # ── 运行参数 ──
    rate_limit: RateLimitConfig = field(default_factory=RateLimitConfig)
    retry: RetryConfig = field(default_factory=RetryConfig)
    timeout_sec: int = 7200

    # ── 元信息 ──
    enabled: bool = True
    tags: tuple[str, ...] = ()                # 用于归类，如 ["盘后", "Tushare", "全市场"]
```

### 4.3 Pipeline 注册（声明式）

```python
# infrastructure/adapter/pipeline/registry.py（新）

from infrastructure.adapter.pipeline.pipeline import Pipeline, APIStep, UnitSpec
from infrastructure.adapter.pipeline.schedule import ScheduleSpec

# ── 8 个 ready 任务的 pipeline 配置 ──────────────────────────────

PIPELINES: list[Pipeline] = [
    # ── 单步骤：日 K 线 ──
    Pipeline(
        pipeline_id="daily_kline",
        name="日 K 线",
        facet="tech", sub_facet="kline",
        unit=UnitSpec(
            style="per_unit",
            unit_source="stock_infos",
            unit_filter={"list_status": "L"},
            unit_template={"label": "{{symbol}}", "symbol": "{{symbol}}"},
        ),
        steps=(
            APIStep(
                name="fetch_kline",
                source="Tushare",
                method="fetch_kline",
                # args 模板只做 {{var}} 替换，**无 filter**
                # 默认值（如 days=7）在 UnitResolver 阶段处理

            ),
        ),
        schedule=ScheduleSpec(kind="cron", cron="0 17 * * 1-5", trading_day_only=True),
        rate_limit=RateLimitConfig(per_request_delay=0.15, concurrency=3),
        tags=("Tushare", "全市场", "盘后"),
    ),

    # ── 单步骤：日频估值 ──
    Pipeline(
        pipeline_id="daily_basic",
        name="日频估值",
        facet="fundamental", sub_facet="valuation",
        unit=UnitSpec(style="per_unit", unit_source="trading_dates"),
        steps=(
```

### 4.4 Pipeline 执行器

```python
# infrastructure/adapter/pipeline/runner.py（新）

class PipelineRunner:
    """执行一个 Pipeline 的核心

    不依赖具体的 fetcher / task 类，只依赖 DataSourceAPI 和极简模板。
    """

    def __init__(
        self,
        registry: DataSourceRegistry,
        pipeline: Pipeline,
        task_id: int,
    ):
        self._registry = registry
        self._pipeline = pipeline
        self._task_id = task_id

    async def run(self, params: dict, on_unit_done) -> TaskSummary:
        """执行一个 pipeline

        流程：
          1. resolve_units() → 生成 unit 列表
          2. 对每个 unit：
             a. 渲染所有 step 的 args_template（仅 {{var}} 替换）
             b. 按顺序执行 step
             c. 每个 step 调 data_source.method(**args)（按 method 名字符串 dispatch）
             d. 检查 CallResult.ok；False → 单元失败
             e. on_unit_done 上报
        """
        units = await self._resolve_units(params)
        sem = asyncio.Semaphore(self._pipeline.rate_limit.concurrency)

        success = fail = 0
        for unit in units:
            if is_cancelled(self._task_id):
                raise Cancelled()
            async with sem:
                try:
                    for step in self._pipeline.steps:
                        # 渲染 args 模板（仅替换 {{var}}）
                        ctx = {**unit, **params}
                        args = render(step.args_template, ctx)
                        # 取数据源实例 + 调方法（按 method 名字符串 dispatch）
                        source = self._registry.get(step.source)
                        method = getattr(source, step.method)
                        result: CallResult = await method(**args)
                        if not result.ok:
                            raise RuntimeError(result.error)
                    await on_unit_done(UnitResult(success=True, detail=unit["label"]), unit["label"])
                    success += 1
                except Exception as e:
                    await on_unit_done(UnitResult(success=False, error=str(e)), unit["label"])
                    fail += 1
            await asyncio.sleep(self._pipeline.rate_limit.per_request_delay)

        return TaskSummary(success=success, fail=fail, total_count=len(units))
```

### 4.5 Jinja 模板 + Unit 解析

```python
# infrastructure/adapter/pipeline/template.py（新）
# 极简版：只支持 {{var}} 和 {{var.attr}}，不引入 jinja2 库

import re
from typing import Any

_VAR_RE = re.compile(r"\{\{\s*([^}]+?)\s*\}\}")

def render(template: Any, ctx: dict) -> Any:
    """递归渲染：dict / list / str 都处理；str 里的 {{var}} 替换"""
    if isinstance(template, str):
        return _VAR_RE.sub(lambda m: str(_lookup(ctx, m.group(1).strip())), template)
    if isinstance(template, dict):
        return {k: render(v, ctx) for k, v in template.items()}
    if isinstance(template, list):
        return [render(x, ctx) for x in template]
    if isinstance(template, tuple):
        return tuple(render(x, ctx) for x in template)
    return template

def _lookup(ctx: dict, path: str) -> Any:
    """支持 a.b.c 和 a.b[0]；找不到返回 ''"""
    cur = ctx
    for part in path.split("."):
        if isinstance(cur, dict):
            cur = cur.get(part, "")
        else:
            cur = ""
    return cur
```

### 4.6 Unit 解析器

```python
# infrastructure/adapter/pipeline/unit_resolver.py（新）

class UnitResolver:
    """把 UnitSpec 翻译成实际的 unit 列表

    支持的 unit_source:
    - "stock_infos":   从 stock_infos 表拉所有 in 市股票
    - "trading_dates": 从 mkt_calendars 拉交易日（或按 days 回算）
    - "concepts":      从 concepts 表拉所有激活概念
    - 自定义：继承 UnitResolver 写
    """

    async def resolve(self, spec: UnitSpec, params: dict) -> AsyncIterator[dict]:
        if spec.style == "one_shot":
            yield {"label": spec.unit_source or "once"}
            return
        if spec.style == "streaming":
            yield {"label": "stream"}
            return
        # per_unit
        if spec.unit_source == "stock_infos":
            async for unit in self._resolve_stocks(spec, params):
                yield unit
        elif spec.unit_source == "trading_dates":
            async for unit in self._resolve_dates(spec, params):
                yield unit
        elif spec.unit_source == "concepts":
            async for unit in self._resolve_concepts(spec, params):
                yield unit
```

```python
    与现有 CollectScheduler 并存（不冲突）：
    - CollectScheduler 触发 BaseCollectTask 子类（8 个 ready）

                    self._trigger,

                    kwargs={"pipeline_id": p.pipeline_id},
                    id=f"pipeline:{p.pipeline_id}",
```

### 11.1 架构层决策（早期）

| 决定 | 取值 | 原因 |
| :- | :- | :- |
| 两层抽象还是三层 | **两层**（数据源 + 编排） | 用户原话明确"底层 API 抽象 + 上层编排调度" |

| Template 引擎 | **自写极简版（仅 `{{var}}` 和 `{{var.attr}}`，无 filter）** | 不引入 jinja2，减少依赖 |
| 老代码 8 个 ready 子类 | **P0 阶段保留**，与新 pipeline 并存 | 路由层、Service 层全部不动 |
| 老 15 个 planned 空壳 | **P0 阶段删除**，由 pipeline 配置完全替代 | 用户明确"不考虑兼容性" |

### 11.2 用户确认的关键决策（2026-09-29 会话）

| # | 决策点 | 取值 | 影响 |
| :- | :- | :- | :- |
| **Q1** | L1 DataSourceAPI 方法同步/异步 | **所有方法统一 async**（即使 Tushare 同步阻塞也用 `async def`，内部 `asyncio.to_thread`） | 编排层不用判断 sync/async，调用一致 |
| **Q2** | L1 方法返回值 | **统一返回 `CallResult(ok: bool, data: Any, error: str \| None)`** | 编排层统一处理失败/重试，**不靠 raise 表达错误** |
| **Q3** | Pipeline 模板引擎 | **自写极简版**（只支持 `{{var}}` 和 `{{var.attr}}`，**不支持 filter 如 `\|default(7)`**） | 默认值在 UnitResolver 阶段处理（如 days 不传 → 7），模板只做替换 |
| **Q4** | Pipeline 引用底层方法的形式 | **字符串 `method="fetch_kline"`**（运行时 dispatch） | 配置可读、可序列化；启动期校验方法存在 |
| **Q5** | P0 接入数据源数量 | **3 个全做**（Tushare + Adata + Pytdx） | 一次跑通所有数据源，验证框架通用性 |

| 原话 | 落地 |
| :- | :- |
