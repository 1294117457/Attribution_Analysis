## 一、为什么需要"适配性"专项

### 1.1 当前痛点（2026-09 复盘）

- 表格每行占用 ~50px，同屏可见行数少
- Element Plus 默认字号 14px、间距偏松，1920 屏看着"留白过多"
- 13 寸笔记本（1366×768）下，表格只能看到 4-5 列固定列 + 触发横向滚动
- 用户系统缩放（Win 的"更改文本大小"125% / 150%）不会自动跟随

### 1.2 设计目标

1. **一键调整全局密度**：改一处 `:root` 字号，全站元素等比缩放
2. **不破坏现有布局结构**：Shell + PageWrapper + 路由结构保持不变
3. **不引入第三方 rem 库**：避免与 Tailwind v4 / Element Plus 冲突
4. **跟随用户系统偏好**：尊重操作系统的"文本大小"设置
5. **适配多档屏幕**：1366 / 1920 / 2560 三档可视效果一致

### 1.3 命名约定

- **根字号**：`html { font-size }` 控制的基准值
- **密度档位**：Compact / Default / Comfortable，对应根字号 13 / 14 / 15
- **CSS 变量**：所有可调尺寸集中在 `:root` 顶层声明，业务样式只引用变量

## 二、方案选择矩阵

| 方案 | 依赖 | 复杂度 | 适配广度 | 推荐度 | 文档 |
|------|------|--------|---------|--------|------|
| 纯 CSS：`font-size: clamp()` | 无 | ⭐ | 1280-2560 屏 + 系统缩放 | ⭐⭐⭐⭐⭐ | [01](./01-rem全局密度方案.md) |
| 纯 CSS：固定 `:root { font-size }` | 无 | ⭐ | 系统缩放 | ⭐⭐⭐⭐ | [01](./01-rem全局密度方案.md) |
| `postcss-pxtorem` | npm 包 + PostCSS 配置 | ⭐⭐⭐ | 仅 px 自动转换 | ⭐⭐ | ❌ 不推荐 |
| `amfe-flexible` + JS 动态根字号 | npm 包 + 入口 JS | ⭐⭐ | 移动端为主 | ⭐ | ❌ 不适合本项目 |

**结论**：本项目采用 **方案 01 的纯 CSS 路径**，零依赖、零构建改动、可控性最强。

## 三、不做什么

> 这些是讨论过的"反面选项"，明确不采纳，避免反复回头讨论。

| 方案 | 不采纳的理由 |
|------|-------------|
| `postcss-pxtorem` | 与 Tailwind v4 的 `@theme` 配置冲突；与 Element Plus 的 `el-` 前缀类 CSS 变量会冲突，需要写一长串 `selectorBlackList` 排除；项目目前写死的 `px` 数量可控，手写 rem 成本更低 |
| `amfe-flexible` | 面向移动端，通过 JS 设置根字号会**覆盖**用户 Win 系统"更改文本大小"的偏好；本项目是 PC 后台，不需要跟随手机分辨率 |
| 全量手写 rem | 现有 `px` 多为合理绝对单位（边框 1px、阴影偏移 4px），强转 rem 会破坏 EP 内部组件；只在"密度控制器"那一层用 rem 即可 |
| 全局缩放（`zoom` / `transform: scale`） | 破坏布局上下文、导致字体抗锯齿下降、不被现代浏览器推荐 |
