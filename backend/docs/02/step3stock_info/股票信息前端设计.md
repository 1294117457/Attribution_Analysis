## 2. 关键设计决策

### 2.1 搜索是否需要防抖？ ✅ **需要，建议 300ms**

**理由**：

| 维度 | 分析 |
|------|------|
| 后端查询成本 | `ILIKE '%xxx%'` 是全表扫描，5000+ 行下明显慢（实测 50~150ms） |
| 用户输入速度 | 中英文混合输入平均 2~5 字/秒，慢速 1~2 字/秒 |
| 请求浪费 | 不防抖时，每输入一个字都触发一次 HTTP 请求 |
| 用户体验 | 加载指示器会闪烁，结果列表跳动，焦点错乱 |
| 后端限流 | 当前是本地 PG 不会触发限流，但 5000+ 行的 ILIKE 已经够慢 |

**推荐方案**：
- **debounce 300ms**（主流推荐值，平衡"响应感"和"请求量"）
- 立即显示 loading state，300ms 内若有新输入则重置计时器
- 配合 `AbortController`，上一次未完成的请求要能取消，避免竞态

```js
// 伪代码
const search = debounce(async (keyword) => {
  if (controller) controller.abort()
  controller = new AbortController()
  const res = await fetchStocks({ q: keyword, signal: controller.signal })
  setStocks(res.items)
}, 300)
```

### 2.2 搜索字段 - 三合一：代码 / 名称 / 拼音

文档中 Tushare 返回的字段包含：
- `symbol`：6 位代码（000001）
- `name`：中文名称（平安银行）
- `cnspell`：拼音缩写（PAYH）

**建议**：搜索框统一为「代码 / 名称 / 拼音」模糊匹配，后端 SQL 类似：

```sql
WHERE symbol ILIKE '%q%' OR name ILIKE '%q%' OR cnspell ILIKE '%q%'
```

输入示例：
- `000001` → 命中代码
- `平安` → 命中名称
- `payh` → 命中拼音

**理由**：拼音搜索是中国股票场景的强需求，但仅靠前端切换会让用户困惑；后端 union 后由前端统一输入即可。

### 2.3 分类维度有哪些？

依据 `stock_infos` 表的可用字段：

| 维度 | 字段 | 取值（文档） | 来源 |
|------|------|---------------|------|
| 行业 | `industry` | 银行、医药生物、软件开发……（**动态**） | `/api/stocks/meta` |
| 市场 | `market` | 主板 / 创业板 / 科创板 / CDR / 北交所 | `/api/stocks/meta` |
| 交易所 | `exchange` | SSE / SZSE / BSE | `/api/stocks/meta` |
| 地域 | `area` | 深圳、北京、上海……（**动态**） | `/api/stocks/meta` |
| 沪深港通 | `is_hs` | N / H / S（否/沪股通/深股通） | 静态枚举 |
| 上市状态 | `list_status` | L 上市 / D 退市 / P 暂停 / G 待交易 / UN 未上市 | 静态枚举 |

**注意事项**：
1. **行业 + 地域必须从 `/api/stocks/meta` 动态获取**——不能硬编码，因为 Tushare 的行业分类会变化。
2. **市场 / 交易所 / 沪深港通 / 上市状态** 是固定枚举，可硬编码：
   ```js
   const MARKETS = ['主板', '创业板', '科创板', 'CDR', '北交所']
   const EXCHANGES = [{label:'上交所', value:'SSE'}, ...]
   const IS_HS = [{label:'否', value:'N'}, {label:'沪股通', value:'H'}, {label:'深股通', value:'S'}]
   const LIST_STATUS = [{label:'上市', value:'L'}, {label:'退市', value:'D'}, ...]
   ```

### 2.4 推荐分类布局（按使用频率排序）

| 层级 | 维度 | 控件 | 说明 |
|------|------|------|------|
| 第 1 行 | 搜索框 | Input + 搜索图标 + 清空按钮 | 占满整行 |

### 2.5 性能：5000+ 条数据的渲染

**问题**：直接 `v-for` 渲染 5000 行会卡顿（每行 6~8 列 + hover 效果）。

**推荐方案**：**虚拟滚动**（virtual scroll）
- 使用 `vue-virtual-scroller` 或 `vueuc` 的 `<VirtualList>`
- 只渲染视口内的 ~20 行
- 支持滚动到顶部 / 底部时按需分页（前端分页 + 滚动加载混用）

**两种分页策略对比**：

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **传统分页**（每页 20） | 简单、URL 友好 | 翻页不流畅 | 数据少（< 1000） |
| **滚动加载 + 虚拟滚动** | 流畅、体验好 | 实现稍复杂 | ✅ 推荐，5000+ 行 |

**建议**：用虚拟滚动 + 服务端 OFFSET/LIMIT。后端一次返回 20 条，滚到底部再请求下一页。

- 悬停 → 高亮 + 显示 tooltip（市场+地域+沪深港通）

### 2.7 URL 状态同步（重要！）

所有搜索/筛选条件应该 **同步到 URL query**，这样：
- 浏览器刷新可恢复状态
- 可分享链接给他人
- 浏览器前进/后退正常工作

```js
// 路由示例
/stocks?q=平安&industry=银行&market=主板&page=2

// Vue Router 配置
watch(filters, (newFilters) => {
  router.replace({ query: { q: newFilters.q, industry: newFilters.industry, ... } })
})
```

### 2.8 加载 & 错误状态

| 场景 | UI 表现 |
|------|---------|
| 初次加载 | 骨架屏（骨架行 × 10） |
| 搜索中 | 列表区域半透明 + loading spinner，输入框右侧 spinner |
| 加载更多 | 列表底部小 spinner |
| 网络错误 | 顶部 Toast："加载失败，[重试]" |
| 空结果 | 空状态插画 + "没有匹配的股票，[清空筛选]" |
| 同步中（点击⟳按钮） | 按钮变 loading，禁用其他操作，2~5 秒后弹 Toast："同步成功 X 条" |

## 4. 数据流时序

```
用户输入"平安"
    ↓ (input 事件, 防抖 300ms)
useStockSearch.search('平安')
    ↓ (取消上一次请求)
GET /api/stocks/?q=平安&page=1&page_size=20
    ↓ (后端 ILIKE 查询)
返回 {total: 412, items: [...]}
    ↓
更新 stockList + totalCount
    ↓
虚拟滚动渲染视口内的 20 行
```

## 7. 附录：API 依赖

前端用到的接口（无需新增，全部由文档里的设计支持）：

| 接口 | 方法 | 用途 |
|------|------|------|
| `/api/stocks/` | GET | 列表查询（搜索 + 筛选 + 分页） |
| `/api/stocks/meta` | GET | 获取行业 / 市场 / 交易所 / 地域的去重列表 |
| `/api/stocks/sync` | POST | 触发同步（全量拉取 Tushare） |

返回的响应统一是 `{code, message, data}` 结构（看现有 `main.py` 的全局异常处理器），前端封装 `http.js` 时统一解包。
