## 3. 日 K（daily_kline）

| 现在 | 改造后 |
| :-- | :-- |
| `list_units`：`select(StockInfoDB.symbol)` + exchange 过滤 | `ctx.stocks.list_symbols("L", exchanges=params.get("exchange"))` |
| `pending_units`：两段 SQL 查覆盖区间和上市日 + 窗口裁剪循环 | `ctx.stocks.kline_coverage(symbols)` + `ctx.stocks.list_dates(symbols)`，裁剪循环抽成纯函数 `compute_windows(...)` |
| `_collect_symbol`：`AsyncSessionLocal` + `di.build_stock_info_service` 反向 import + 手动 commit | `async with ctx.stock_info() as svc:`（03 §2） |
| `__init__` 读 `get_settings()` | `pre_execute` 用 `ctx.concurrency` / `ctx.max_concurrency` |

窗口裁剪抽成同文件内的纯函数，便于单测（不放 domain：它是"采集多少"的编排策略，不是业务规则，见 README §2）：

```python
def compute_windows(
    symbols: list[str],
    mode: str,
    req_start: date,
    req_end: date,
    today: date,
    coverage: dict[str, tuple[date, date]],
    list_dates: dict[str, date | None],
) -> dict[str, tuple[date, date]]:
    """返回需要采集的股票及其窗口；已覆盖的股票不出现在结果里（逻辑与现在 pending_units 循环完全相同）"""
```

不变：`UNIT_TIMEOUT=300`、`FULL_START=2015-01-01`、异常分类（超时 / `CollectionError` / 其它）、`UnitResult.data=resp.model_dump()`、汇总文案。

## 5. 概念任务（5 个）

全部改用 `ctx.gateway` + `ctx.concepts`。`ConceptCollectionPolicy`（domain）与常量 `LIST_SHRINK_GUARD` 等不变。

### 5.1 "先查后写"拆分

现在这些调用在同一个 `async with AsyncSessionLocal()` 里，改造后是多次独立端口调用。`ConceptRepoImpl` 的写方法本来就各自 `commit`，事务边界其实没变：

| 任务 | 现在同 session 内的调用 | 改造后 | 影响 |
| :-- | :-- | :-- | :-- |
| `concept` | `count_active` → `upsert_concepts` → `deactivate_missing` | 三次端口调用 | 无：三个方法原本就各自提交 |
| `concept_membership` | `count_members` → `replace_members` | 两次端口调用 | 无：同上；同一概念不会被并发写（`TaskConflict` 防重） |
| `concept_index_th` | `get_max_trade_dates`；每单元 `upsert_index_th` | 不变（本来就是两个 session） | 无 |

### 5.2 逐个说明

| task_type | 改动 |
| :-- | :-- |
| `concept` | `get_data_gateway()` → `self.ctx.gateway`；`ConceptRepoImpl(session).xxx` → `self.ctx.concepts.xxx`。重试 2 次、缩量保护、汇总文案不变 |
| `concept_membership` | `_active_concepts` → `ctx.concepts.list_active_concepts()`；`_collect_concept` 中的两次 repo 调用 → `ctx.concepts`。`collect_one` 按 `index_code` 找概念、返回 `(结果, 新增, 移除)` 的结构不变 |
| `concept_index_th` | 同上；`INDEX_TH_OVERLAP_DAYS` 增量裁剪留在任务里 |
| `concept_reason` | `list_units` 两段直写 SQL → `ctx.concepts.member_symbols(only_missing_reason=params.get("only_missing"))`；`collect_one` 中的匹配更新 → `ctx.concepts.update_reasons(unit, items)` |
| `concept_snapshot` | `list_units` 直写 SQL → `ctx.concepts.active_index_codes()`；写入 → `ctx.concepts.add_snapshot(unit, snap, market_now())`。时区处理在实现里（02 §2.3） |

`concept.py` 里模块级的 `_active_concepts` / `_run_units` 改为接收 `ctx`（或改成任务基类上的方法），不再 import `AsyncSessionLocal`。
