依赖方向：`application/port/data` 不依赖 infrastructure，也不依赖 route；`adapter/data/*` 实现它。和现在 `collector_port.py` 的位置一致。

## 2. 三层继承关系

```
application 层                                infrastructure 层
DataPort                第一层：根约束（抽象）
  └── MoneyflowPort     第二层：接口约束（抽象）    AdapterBase   实现方属性
        └── TushareMoneyflowAdapter(MoneyflowPort, AdapterBase)   第三层：底层实现（唯一的具体类）
        └── AkshareMoneyflowAdapter(MoneyflowPort, AdapterBase)   （后续接入，同一个 Port 的另一个实现）
```

- 只有最底层是具体类，上两层都是抽象约束，不放业务逻辑，所以不算"深继承"。
- Adapter 通过继承自动拿到 Port 的元数据和参数模型，不用再写 `port = MoneyflowPort` 之类的引用。
- **Port 只描述"取什么"，`AdapterBase` 描述"谁来取、怎么限流"**。前者在 application，后者在 infrastructure，application 层看不到任何数据源相关的字段（DDD.md §2.2 "port 的组成"）。

## 3. DataPort（第一层：根约束）

```python
# application/port/data/base.py
P = TypeVar("P", bound=BaseModel)
R = TypeVar("R", bound=BaseModel)

class DataPort(Generic[P, R], ABC):
    # 以下全部由第二层 XxxPort 填写；第三层 Adapter 不允许覆盖
    name: ClassVar[str]                     # 全局唯一，如 "moneyflow"
    label: ClassVar[str]                    # "个股资金流向"
    facet: ClassVar[str]                    # tech / capital / fundamental / news
    sub_facet: ClassVar[str] = ""
    description: ClassVar[str] = ""
    Params: ClassVar[type[BaseModel]]       # 参数模型：校验 + JSON Schema
    Item: ClassVar[type[BaseModel]]         # 返回的 BO 类型（缓存反序列化、目录展示用）
    unit: ClassVar[str] = "none"            # 采集时的单元维度：symbol / trade_date / index_code / none
    cache: ClassVar[CachePolicy | None] = None   # 声明后可作为实时接口（见 05）
    sample_params: ClassVar[dict] = {}      # 采集管理"试查"的默认参数

    def supports(self, params: P) -> bool:
        """该实现不支持这组参数时返回 False（Gateway 跳过，不算失败）"""
        return True

    @abstractmethod
    async def fetch(self, params: P) -> list[R]: ...
```

### 3.1 AdapterBase（实现方属性，infrastructure）

```python
# infrastructure/adapter/data/core/base.py
class AdapterBase:
    tool: ClassVar[str]                     # 采集工具：tushare / adata / pytdx / akshare
    origin: ClassVar[str]                   # 数据源：tushare / ths / tdx / eastmoney
    priority: ClassVar[int] = 100           # 越小越优先
    throttle_group: ClassVar[str] = ""      # 限流分组，同组共享配额（见 03）
```

- 每个 Adapter 写成 `class XxxAdapter(XxxPort, AdapterBase)`。
- Registry、Gateway、装饰器、目录接口（`catalog` 里的 `adapters` 字段）都在 infrastructure，可以直接读这些属性；application 层只看到 `DataResult.source`（字符串）。

## 4. XxxPort（第二层：接口约束）

每份数据一个抽象类，只声明，不实现 `fetch`。

```python
# application/port/data/capital.py
class CapMoneyflowBO(BaseModel): ...       # 原 route/dto/request/cap_moneyflow.py，字段不变（§4.3）

class MoneyflowParams(BaseModel):
    model_config = ConfigDict(extra="forbid")
    trade_date: TradeDate
    symbols: list[Symbol] | None = None

class MoneyflowPort(DataPort[MoneyflowParams, CapMoneyflowBO]):
    name, label = "moneyflow", "个股资金流向"
    facet, sub_facet = "capital", "moneyflow"
    description = "大小单净额、净流入"
    Params, Item = MoneyflowParams, CapMoneyflowBO
    unit = "trade_date"
```

约定：

- `name` 表示"取什么"，不带面前缀（`moneyflow` 而不是 `cap_moneyflow`）。`task_type` 表示"采什么入哪张表"，两者分开；`task_type` 不改名，保证历史任务和采集方案兼容。
- 例外：两个实时接口的 Port 沿用现有名称 `stock_minute_kline`、`concept_minute`。这样 `collect_fetchers` 表、前端"试查"、统计接口都不用改（见 05）。
- 一个 Port 只描述一种数据。现在的 `ConceptFetcher` 要拆成 6 个 Port（见 02）。

### 4.1 参数模型约定

| 约定 | 做法 |
| :-- | :-- |
| 业务语义 | `symbol` 是 6 位代码、日期用 `date`。`ts_code`、`"20261013"`、"最近 N 根"这类数据源细节放到 Adapter 里转换 |
| 公共类型复用 | `types.py` 定义 `Symbol`（6 位数字）、`TradeDate`（`date`，同时接受 `"YYYYMMDD"`，兼容采集任务的单元格式）、`IndexCode`，各 Port 不重复写校验 |
| 可选值用枚举 | 周期、市场、上市状态等用 `StrEnum` / `Literal`，不用裸 `str` |
| 范围声明式 | `Field(ge=, le=, pattern=)`；只有跨字段规则才写 `model_validator` |
| 禁止多余字段 | 所有 Params 设 `extra="forbid"`，拼错或多传的字段直接报 `InvalidParams`，不会被静默忽略 |

```python
# application/port/data/types.py
Symbol = Annotated[str, StringConstraints(pattern=r"^\d{6}$")]
IndexCode = Annotated[str, StringConstraints(pattern=r"^\d{6}$")]
TradeDate = Annotated[date, BeforeValidator(_parse_yyyymmdd)]   # date / "YYYY-MM-DD" / "YYYYMMDD"
```

### 4.2 时间参数

时间有两个互相独立的维度，不要混用：

| 维度 | 含义 | 字段 |
| :-- | :-- | :-- |
| 范围 | 取哪一段时间 | 单日 `trade_date`；区间 `start_date` / `end_date` |
| 粒度 | 一条数据代表多长时间 | 只有分 K 有：`interval: MinuteInterval`（见 05 §2） |

- **Port 里只放绝对日期**。`days=1`、`years=3`、`mode=full` 这类相对写法由调用方（采集任务的 `build_params`、路由）换算成绝对日期后再调 Port。
- 例外：实时分 K 的"最近 N 个交易日"（`days`）本身就是相对"现在"的语义，保留。
- 日 K 只是日期范围 + 日粒度，用 `DailyKlinePort`；分 K 的 `interval` 里没有"日"。

### 4.3 返回类型（BO）的位置

各 Port 的 `Item`（BO）现在放在 `route/dto/request/*.py`，Port 定义在 application，如果直接引用就成了 application 反向依赖 route（DDD.md §4）。P1 一并搬迁：

- BO 搬到对应的 `application/port/data/<面>.py`，和 Port、Params 放在一起，作为 Port 契约的一部分。
- **不放 domain**：BO 是 pydantic 模型，跟着数据源字段走，而 domain 要求零外部依赖（现有 `domain/entitys/*/vo.py` 都是纯 `dataclass`）。BO 通过 `to_entity()` 转成 domain 实体，这个方法原样保留。
- 原 `route/dto/request/*.py` 保留一行 re-export（`from application.port.data.capital import CapMoneyflowBO`），P4 删除旧 fetcher 时一起清掉。
- 涉及 21 个 BO：tushare 系 16 个、概念 4 个（`ConceptListBO` / `ConceptOfStockBO` / `ConceptIndexTHBO` / `ConceptMinuteBO`）、`MinuteKlineBO`（从 `fetcher/pytdx.py` 搬出）。成分股、快照沿用现有返回结构，拆分时如无独立 BO 则补一个。

## 5. DataCommand / DataResult（命令与结果）

```python
class CallPolicy(StrEnum):
    COLLECT = "collect"     # 采集：限频时等待重试，不走缓存
    QUERY = "query"         # 查询：限频不等待；Port 声明了 cache 时走缓存

@dataclass(frozen=True)
class DataCommand:
    name: str                          # XxxPort.name
    params: dict
    source: str | None = None          # 指定 Adapter.tool，可选
    policy: CallPolicy = CallPolicy.COLLECT

@dataclass
class DataResult(Generic[R]):
    items: list[R]
    source: str                        # 实际返回数据的实现，如 "tushare"；缓存命中时为写缓存时的来源
    latency_ms: int
    cached: bool = False
    fetched_at: datetime | None = None
    attempts: list[tuple[str, str]] = field(default_factory=list)  # 换源前失败的 (source, error)
```

`DataCommand` 是纯数据，可以来自业务 Service、采集任务、HTTP、Agent，也可以写进数据库重放。

## 6. 错误分类

底层实现只抛下面几种异常，Gateway 按类型决定是否换源。

| 异常 | 含义 | RetryDecorator | Gateway 换源 |
| :-- | :-- | :-- | :-- |
| `InvalidParams` | 参数不合法（Params 校验失败 / 业务规则） | 不重试 | 不换源，直接抛 |
| `RateLimited(retry_after)` | 数据源限频（tushare 限频、adata 返回 Exception） | COLLECT 等待后重试；QUERY 不重试 | 重试仍失败则换源 |
| `SourceUnavailable` | 网络错误、超时、SDK 异常 | 短退避重试 | 换源 |
| `NotSupported` | 该实现不支持这组参数（如 pytdx 不支持北交所） | 不重试 | 跳过，试下一个 |

"接口正常但无数据"不是异常，返回空列表。adata 现在已经区分了这两种情况（成分股任务依赖它决定是否删除旧关系），拆分时保留。

现有 `collector_port.RateLimitError` 在过渡期保留为 `RateLimited` 的别名，P4 删除。

## 7. DataPortRegistry（注册表式工厂）

```python
class DataPortRegistry:
    def register(self, adapter: DataPort, *, wrap: Callable[[DataPort], DataPort]) -> None
    def port(self, name: str) -> type[DataPort]              # 未注册抛 KeyError
    def adapters(self, port: type[DataPort]) -> list[DataPort]  # 按 priority 升序，已过滤禁用
    def ports(self) -> list[type[DataPort]]
```

- **自动归类**：`register` 时沿 MRO 找到 `DataPort` 的直接子类，即为该 Adapter 所属的 Port，不需要手写对应关系。
- `wrap` 套好横向装饰器（见 03），注册表里存的是包装后的实例。
- 启动期校验：
  - Adapter 必须同时继承某个 XxxPort 和 `AdapterBase`，且填了 `tool` / `origin`；
  - Adapter 不允许覆盖 Port 的元数据字段（`name` / `label` / `facet` / `Params` / `Item` / `unit` / `cache`）；
  - 同一 Port 下 `tool` 不重复；
  - `throttle_group` 已在装饰器配置中定义。
- 禁用某个数据源：配置 `DATA_SOURCE_DISABLED=akshare,pytdx`（放 `backend/.env`，非敏感），`adapters()` 过滤掉这些。

## 8. DataGateway（门面 + 选源）

```python
class DataGateway:
    async def fetch(self, port: type[DataPort[P, R]], params: P | dict, *,
                    source: str | None = None, policy: CallPolicy = CallPolicy.COLLECT) -> DataResult[R]
    async def fetch_many(self, port: type[DataPort[P, R]], params_list: list[P], *,
                         policy: CallPolicy = CallPolicy.COLLECT) -> list[DataResult[R] | Exception]
    async def invoke(self, cmd: DataCommand) -> DataResult           # 按名调用
    async def invoke_many(self, cmds: list[DataCommand]) -> list[DataResult | Exception]
    def catalog(self) -> list[PortInfo]                               # 元数据 + Params JSON Schema + 可用实现
```

调用流程：

```python
async def fetch(self, port, params, *, source=None, policy=CallPolicy.COLLECT):
    p = params if isinstance(params, port.Params) else port.Params.model_validate(params)  # 失败 → InvalidParams
    token = call_policy.set(policy)
    try:
        if policy is CallPolicy.QUERY and port.cache:
            return await self._cache.get_or_load(port, p, lambda: self._select(port, p, source))  # 见 05
        return await self._select(port, p, source)
    finally:
        call_policy.reset(token)

async def _select(self, port, p, source):
    candidates = [a for a in self._registry.adapters(port) if source in (None, a.tool)]
    if not candidates:
        raise NotSupported(f"{port.name} 没有可用实现 {source or ''}")
    attempts = []
    for adapter in candidates:                  # 指定 source 时只有一个 = 策略；否则 = 责任链
        if not adapter.supports(p):
            continue
        try:
            items = await adapter.fetch(p)
            return DataResult(items, adapter.tool, ..., attempts=attempts)
        except InvalidParams:
            raise
        except (RateLimited, SourceUnavailable) as e:
            attempts.append((adapter.tool, repr(e)))
    if not attempts:                            # 没有一个实现支持这组参数
        raise NotSupported(f"{port.name} 没有支持该参数的实现")
    raise SourceUnavailable(f"{port.name} 全部数据源失败: {attempts}")
```

要点：

- 全部实现都 `supports()=False` 抛 `NotSupported`（如北交所分 K）；至少试过一个且都失败才抛 `SourceUnavailable`。调用方据此区分"参数超出能力范围"和"数据源故障"。
- 指定 `source` 时不换源（调用方明确要这个源，换了反而造成数据口径不一致）。
- 只有 `RateLimited` / `SourceUnavailable` 换源。
- `DataResult.source` 一定回传，采集任务写进日志，方便排查不同源的数据差异。
- 当前每个 Port 只有一个实现，换源逻辑先存在但不会触发；接入 akshare 后自动生效。

## 9. 接入方式

```python

    async def invoke(self, cmd: DataCommand) -> DataResult: ...
    async def invoke_many(self, cmds: list[DataCommand]) -> list[DataResult | Exception]: ...

# infrastructure/config/di.py

    ...旧注册保留（过渡期共存）...
    setup_data()

```

- 应用层 / 采集任务（类型化）：`await gateway.fetch(MoneyflowPort, MoneyflowParams(trade_date=d))`。参数写错在 IDE / pyright 阶段就能发现。
