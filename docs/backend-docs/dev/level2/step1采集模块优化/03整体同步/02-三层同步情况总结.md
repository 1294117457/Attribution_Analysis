class CollectRequest(BaseModel):
    mode: Literal["full", "condition"] = "condition"
    params: dict = Field(default_factory=dict)

    @model_validator(mode="after")
    def _strip_empty(self) -> "CollectRequest":
        cleaned = {k: v for k, v in self.params.items()
                   if v not in (None, "", [], {})}
        self.params = cleaned
        return self

class CollectResponse(BaseModel):
    total: int = 0
    success: int = 0
    fail: int = 0
    skip: int = 0
    saved: int = 0
    message: str = ""

## 3. 关键设计决策 & 取舍

### 3.1 25 个 repo 的 BO/ORM 引用

**选择 A（已采用）**：repo 内部 import ORM 模型 + BO，直接在 `_to_row()` 中做转换。
**优点**：service 只需 `await self._repo.save(bos)` 一行；类型清晰。
**代价**：repo 是 infrastructure 层，引用 application 层的 BO 算"反向依赖"（但 BO 在大多数项目里被视为
值对象，放在 application 还是 domain 边界模糊，业界常见做法）。

**方案 B（未选）**：repo 接受 `list[dict]`，转换在 service 里做。会让 service 又脏。
**方案 C（未选）**：repo 接受 domain Entity。需要在 domain 重建 entity（重复定义）。

### 3.2 25 个 Protocol 的入参类型

**采用 `list[object]`** + 文档注释。理由：domain 不应反向依赖 application 的 BO（严格 DDD）。
**待后续**：在 domain 内定义 `BODomain` type alias（dataclass）作为 Pydantic BO 的镜像。

### 3.3 `ConceptMemberRepository.save_by_concept`

唯一**先删后插**的 repo：概念-股票关联表是 M:N，且 symbol 不唯一，需要按 `concept_id` 删除该概念下所有旧成员再插新成员。
其他 24 个 repo 全部走 upsert。

### 3.4 `StockConceptRepository.upsert_by_concept_map`

fetcher 返回 `list[dict]`，需要 `name → concept_id` 映射。service 端缓存这张 map 在 `concept_id_map` 中
避免 N+1 查询。

### 3.5 `NewsArticleRepository.save_dicts`

fetcher 返回 `list[dict]`（BO 缺失），repo 接受 dict。`save_dicts` 命名刻意区分 `save(bos)`，提醒调用方传入的是 dict 而非 BO。

### 3.6 概念 4 个 service 在 collect context

历史上 4 个 concept service 在 concept context，本次按方案决定在 collect context 新增（与 fetcher 同侧）。
**意味着** `contexts.collect.infrastructure.persistence.repositories` 下的 4 个概念 repo 会 import
`contexts.concept.infrastructure.persistence.models.concept`（ORM 模型）和 `contexts.concept.application.bo.concept`（BO）。
**这造成跨 context 反向依赖**（collect 依赖 concept），但与方案 4.4.3 一致。

### 3.7 限流/重试装饰器

方案 Phase 5 才做，本批次保持 service 内的 `await check(RATE_LIMIT)` + 3-retry 内联循环不变。

### 3.8 旧 trigger 命名

方案文档里的 `CollectJobSaveRequest` 已不存在（前置步骤已清理）。新 DTO 命名为 `CollectRequest` / `CollectResponse`，
业务语义清晰，POST 触发即返回。
