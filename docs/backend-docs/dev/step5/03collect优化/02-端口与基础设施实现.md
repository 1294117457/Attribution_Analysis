# 02 端口与基础设施实现

> 阶段 C1（端口定义 + `cancel_check` 上移）、C2（infra 实现，旧代码暂不切换）。

## 1. 端口清单

采集用例需要的 IO 共 6 类，定义在一个文件里：`application/port/collect_port.py`。

| 端口 | 替代现在的 | 使用方 |
| :-- | :-- | :-- |
| `RawDataStorePort` | `existing_column` + `XxxRepoImpl` + `existing_dates` / `existing_symbols` | 14 个声明式任务、`SymbolPlanner` |
| `StockUniversePort` | `select(StockInfoDB.symbol)`、`select(TechKlineDailyDB ...)` | `SymbolPlanner`、日 K 任务 |
| `ConceptStorePort` | `ConceptRepoImpl` 写方法 + `concept_reason` / `concept_snapshot` 里的直写 SQL | 概念 5 个任务 |
| `CollectTaskStorePort` | `SysCollectTaskDB` 读写（`base._finish_task`、`CollectManageService.prepare` / `retry_failed` / `run_plan`） | `CollectRunner`、`CollectManageService` |
| `CollectProgressPort` | `get_redis()` + `collect:progress:*` 写入（`base._update_progress`、`execute_task`、`prepare`） | `CollectRunner`、`CollectManageService` |
| `DataGatewayPort` | `get_data_gateway()` | 已有（`application/port/data`），改为注入 |

约定：

- 每个方法是一个独立事务，实现内部自开 session、自 commit（README §4.2）。
- 参数和返回值只用 Port / BO / 基本类型 / 本文件内的 dataclass，不出现 ORM。

## 2. 端口定义

### 2.1 RawDataStorePort（原始数据入库）

```python
class RawDataStorePort(Protocol):
    def supports(self, port: type[DataPort]) -> bool:
        """该 Port 是否配置了入库映射（启动期校验用）"""

    async def save(self, port: type[DataPort], items: list[BaseModel]) -> int:
        """写入一批 BO，返回写入条数（语义与现在各 RepoImpl.save_batch 一致）"""

    async def existing(self, port: type[DataPort], units: list[str] | None) -> set[str]:
        """库中已有数据的单元。

        units 为交易日（YYYYMMDD）或股票代码，取决于该表的增量列；
        units=None 表示返回全部已有单元（SymbolPlanner 的 only_missing 用）。
        """
```

- 以 Port 为键，不以表为键：任务只知道"取的是哪份数据"，存到哪张表是 infra 的事。
- `existing` 的单元类型由 infra 映射里的增量列决定（交易日列返回 `YYYYMMDD`，股票列返回代码），与现在 `existing_dates` / `existing_symbols` 的输出格式一致。

### 2.2 StockUniversePort（股票范围与日 K 覆盖）

```python
class StockUniversePort(Protocol):
    async def list_symbols(self, list_status: str = "L", exchanges: list[str] | None = None) -> list[str]:
        """按代码升序"""

    async def list_dates(self, symbols: list[str]) -> dict[str, date | None]:
        """上市日期（日 K 窗口裁剪：起点不早于上市日）"""

    async def kline_coverage(self, symbols: list[str]) -> dict[str, tuple[date, date]]:
        """每只股票库中日 K 的 (最早日期, 最新日期)；无数据的不出现在结果里"""
```

不放进领域的 `StockInfoRepository` / `KlineRepository`：那两个是 session 绑定的读写仓储，服务于 `StockInfoService`；这里是采集专用的只读查询，按"自开 session"约定实现更简单。

### 2.3 ConceptStorePort（概念采集读写）

现有 `domain/entitys/concept/repository.py` 明确只暴露读侧（"写侧只被采集任务使用"），且写方法入参是 BO（应用层类型，domain 不能引用）。所以写侧端口放应用层：

```python
class ConceptStorePort(Protocol):
    # 清单
    async def list_active_concepts(self) -> list[tuple[int, str, str]]: ...      # [(id, index_code, name)]
    async def count_active(self) -> int: ...
    async def upsert_concepts(self, bos: list[ConceptListBO]) -> dict[str, int]: ...  # {index_code: id}
    async def deactivate_missing(self, keep_index_codes: list[str]) -> int: ...
    # 成分股
    async def count_members(self, concept_id: int) -> int: ...
    async def replace_members(self, concept_id: int, symbols: list[str]) -> tuple[int, int]: ...  # (新增, 移除)
    # 指数日 K
    async def get_max_trade_dates(self) -> dict[str, date]: ...
    async def upsert_index_th(self, bos: list[ConceptIndexTHBO]) -> int: ...
    # 入选理由（原 concept_reason.py 直写 SQL）
    async def member_symbols(self, only_missing_reason: bool) -> list[str]: ...
    async def update_reasons(self, symbol: str, items: list[ConceptOfStockBO]) -> int: ...  # 返回更新条数
    # 快照（原 concept_snapshot.py 直写 SQL）
    async def active_index_codes(self) -> list[str]: ...
    async def add_snapshot(self, index_code: str, snap: ConceptSnapshotBO, trade_time: datetime) -> None: ...
```

- 前 8 个方法与 `ConceptRepoImpl` 现有方法同名同义，实现直接委托。
- `update_reasons` 的匹配逻辑（按 `index_code` 查 `concept_id`，命中已有关系且 reason 变化才更新）原样搬进实现。
- `add_snapshot` 内部查概念名（查不到用 `index_code`），`trade_time` 由调用方传入（`market_now()`），实现负责去掉时区写入 `TIMESTAMP WITHOUT TIME ZONE` 列。

### 2.4 CollectTaskStorePort（任务行）

```python
@dataclass(frozen=True)
class CollectTaskRecord:
    id: int
    task_type: str
    trigger_type: str
    status: str
    params: dict
    total_count: int
    success_count: int
    fail_count: int
    skip_count: int

class CollectTaskStorePort(Protocol):
    async def has_running(self, task_type: str) -> bool: ...
    async def create(self, *, task_type: str, trigger: str, params: dict, total: int,
                     plan_run_id: int | None, plan_first: bool) -> int: ...
    async def get(self, task_id: int) -> CollectTaskRecord | None: ...
    async def finish(self, task_id: int, *, status: str, success: int, fail: int, skip: int,
                     message: str, duration_ms: int | None = None, total_count: int | None = None) -> None: ...
```

- `create` 包含现在 `prepare` 里"flush 拿 id，`plan_first` 时 `plan_run_id = 自身 id`"的逻辑。
- `has_running` + `create` 是两次调用（现在是同一 session）。防重窗口本来就只防"用户连点"，两次调用间隔毫秒级，可接受。
- `task_to_dict` 改为接收 `CollectTaskRecord` 或任意具备同名属性的对象（路由仍直接传 ORM 行，见 README §7）。

### 2.5 CollectProgressPort（进度）

```python
class CollectProgressPort(Protocol):
    async def init(self, task_id: int, total: int) -> None:
        """写 total/done/success/fail/skip/status=running/current，TTL 86400"""
    async def set_total(self, task_id: int, total: int) -> None: ...
    async def step(self, task_id: int, label: str, *, success: bool, skipped: bool) -> None:
        """done+1、success/fail(+skip)+1、current=label（pipeline）"""
    async def set_status(self, task_id: int, status: str) -> None: ...
```

key 与字段完全沿用 `collect:progress:{task_id}`。`CollectManageService` 构造参数里的 `redis: RedisPort` 被它替代。

### 3.1 SqlRawDataStore

```python
@dataclass(frozen=True)
class _Spec:
    repo: type                 # 现有 XxxRepoImpl（有 save_batch(entities)）
    column: Any                # 增量列（ORM 列）；None 表示不做增量
    unit: str                  # "trade_date" | "symbol"，决定 existing 的单元格式

_SPECS: dict[str, _Spec] = {
    DailyBasicPort.name:   _Spec(FinDailyBasicRepoImpl,  FinDailyBasicDB.trade_date, "trade_date"),
    MoneyflowPort.name:    _Spec(CapMoneyflowRepoImpl,   CapMoneyflowDB.trade_date,  "trade_date"),
    ...                    # 其余 5 个交易日类同理
    AdjFactorPort.name:    _Spec(BaseAdjFactorRepoImpl,  BaseAdjFactorDB.symbol,     "symbol"),
    FinIncomePort.name:    _Spec(FinReportRepoImpl,      FinReportDB.symbol,         "symbol"),
    ...                    # 其余 4 个股票类同理
    NameChangePort.name:   _Spec(BaseNameChangeRepoImpl, None,                       "symbol"),
}

class SqlRawDataStore:
    async def save(self, port, items):
        spec = _SPECS[port.name]
        async with AsyncSessionLocal() as session:
            return await spec.repo(session).save_batch([b.to_entity() for b in items])
```

- 14 条映射与现在 `tushare_tasks.py` 里每个任务的 `existing_column` / `repo` 一一对应，从那里直接搬过来。
- `save` 与现在 `DeclarativeCollectTask.collect_one` 里的两行完全相同，写入语义零变化。
- `existing` 搬 `base.existing_dates` / `existing_symbols` 和 `SymbolPlanner` 里 `select(column).distinct()` 的实现。
- 启动期校验：`setup_collect` 时对每个声明式任务调用 `supports(task.port)`，缺映射直接报错（避免运行时才发现）。

## 4. cancel_check 契约上移

`cancel_check` 现在定义在 `infrastructure/adapter/data/core/context.py`，采集 runner 设置它、Gateway 的限流 / 重试等待读取它。它是"调用方 ↔ Gateway"之间的契约，应放在端口层：

```
application/port/data/context.py      新：call_policy、cancel_check 两个 ContextVar
infrastructure/adapter/data/core/context.py   改为从上面 import，保留 sleep_cancellable（实现细节）
```

应用层的 runner 只 import `application.port.data.context.cancel_check`。

## 5. 验收（C2）

脚本对比（新实现 vs 现有代码路径，结果应完全一致）：

- `RawDataStore.save(MoneyflowPort, items)` 与现在 `CapMoneyflowCollectTask().collect_one(date)` 写入行数一致。

- `StockUniverse.list_symbols()` 与 `SymbolPlanner().units({}, None)` 一致；`kline_coverage` 与日 K `pending_units` 内的查询一致。
- `ConceptStore.update_reasons("600519", ...)` 更新条数与 `ConceptReasonCollectTask().collect_one("600519")` 一致。
