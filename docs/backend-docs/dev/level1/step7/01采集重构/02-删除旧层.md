### 4.2 装饰器逻辑去向

| 旧装饰器 | 旧逻辑 | 新位置 |
|:--|:--|:--|
| `ThrottleDecorator` | 进程内 `asyncio.Semaphore(THROTTLE_GROUPS[group].concurrency)` + `min_interval` 间隔 | **删除 `min_interval`**——业务已用 `RedisCache.rate_limit`（滑动窗口）做跨进程限流。**保留 `Semaphore`** 但下沉到 service：<br>`sem = asyncio.Semaphore(service.CONCURRENCY)` |
| `RetryDecorator` | `for attempt in 3: try/except RateLimited → sleep(60) → retry` | service 内 inline 6 行（见 `DailyKlineService._fetch_with_retry`） |
| `MetricsDecorator` | 写 `ds:stats:{port}:{tool}:{yyyymmdd}` HASH | **改 logger.info**——`logger.info("daily_kline %s %dms success=true", symbol, latency)` |
| `CacheDecorator` | `ds:cache:{port}:{sha1(params)}` + 单飞锁 | **改 `RedisCache.get_or_set`**——service 内 1 行 |
| `CacheDecorator._count` | `ds:stats:{port}:cache:{yyyymmdd}` 记 hits/misses | **删除**——不统计缓存命中率 |

### 4.3 `THROTTLE_GROUPS` 替代

| 旧 `THROTTLE_GROUPS["tushare"]` | 旧职责 | 新 |
|:--|:--|:--|
| `concurrency=COLLECT_MAX_CONCURRENCY` | 进程内并发上限 | **service 类变量**——`DailyKlineService.CONCURRENCY = 5` |
| `min_interval=0.15` | 进程内最小调用间隔 | **删除**——`RedisCache.rate_limit("tushare", 200, 60)` 已限流 |

**原因**：
- 进程内 `min_interval` 是为了防止单进程突发打爆 SDK；滑动窗口 + `Semaphore` 已足够
- 跨进程限流由 `RedisCache.rate_limit` 负责——同一 `("tushare", 200, 60)` key 共享配额

**新的 fetcher 模板**：

```python
# contexts/collect/infrastructure/fetcher/base.py
from __future__ import annotations
from abc import ABC, abstractmethod
from typing import ClassVar
from pydantic import BaseModel


class BaseFetcher(ABC):
    """Fetcher 抽象基类

    命名：业务名 + 数据源 + Fetcher
    例：KlineTushareFetcher / ConceptListAdataFetcher / MinuteKlinePytdxFetcher

    唯一职责：调 SDK 拿数据，返回 list[BO]
    不限流、不并发、不缓存、不入库——这些在 service 里做
    """
    fetcher_type: ClassVar[str]           # "daily_kline_tushare"
    source: ClassVar[str]                 # "tushare" / "adata" / "pytdx"
    label: ClassVar[str] = ""
    description: ClassVar[str] = ""

    @abstractmethod
    async def fetch(self, **params) -> list[BaseModel]:
        ...


__all__ = ["BaseFetcher"]
```

**新的 fetcher 实现（以 KlineTushareFetcher 为例）**：

```python
# contexts/collect/infrastructure/fetcher/tech/DailyKlineTushareFetcher.py
from __future__ import annotations
from datetime import date
from pydantic import BaseModel

from contexts.collect.infrastructure.fetcher.base import BaseFetcher
from contexts.collect.infrastructure.sdk.tushare import TushareClient
from contexts.collect.domain.bo.kline_bo import KlineBO


class DailyKlineTushareFetcher(BaseFetcher):
    """日 K 线 fetcher（Tushare pro.daily）"""

    fetcher_type = "daily_kline_tushare"
    source = "tushare"
    label = "日 K 线（Tushare）"
    description = "Tushare pro.daily 接口"

    def __init__(self, client: TushareClient) -> None:
        self._client = client

    async def fetch(
        self, *, symbol: str, start: date, end: date,
    ) -> list[BaseModel]:
        df = await self._client.daily(
            ts_code=symbol,
            start_date=start.strftime("%Y%m%d"),
            end_date=end.strftime("%Y%m%d"),
        )
        return [KlineBO.model_validate(r.to_dict()) for _, r in df.iterrows()]


__all__ = ["DailyKlineTushareFetcher"]
```

**对比旧 `DailyKlineTushareAdapter(DailyKlinePort, AdapterBase)`**：
- 不再继承 `XxxPort`（Port 类删除）
- 不再继承 `AdapterBase`（Adapter 抽象删除）
- `tool: "tushare"` → `source: "tushare"`（字段重命名）
- `origin: "tushare"` 删（与 source 重复）
- `priority: 100` 删
- `throttle_group: "tushare"` 删
- `Params: DailyKlineParams` / `Item: KlineBO` 类变量删（参数直接 kwargs，返回类型用 Pydantic 推断）
- `fetch(params: DailyKlineParams) → list[KlineBO]` 改成 `fetch(**kwargs) → list[BaseModel]`

| 改前 | 改后 |

| `class XxxTushareAdapter(XxxPort, AdapterBase)` | `class XxxTushareFetcher(BaseFetcher)` |

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    await init_redis()
    await init_db()

    services = setup_services()                              # 22 个 service
    set_service_registry(services)
    run_log_repo = CollectRunLogRepo()
    schedule_repo = CollectScheduleRepo()
    runner = ScheduleRunner(services, run_log_repo)

    async def on_fire(payload):
        await runner.fire_by_schedule_id(payload["schedule_id"])

    scheduler = ApschedulerAdapter(timezone="Asia/Shanghai", on_fire=on_fire)
    for sched in await schedule_repo.list_enabled():
        sched_vo = build_schedule(
            mode=sched.trigger_type, schedule_type=sched.trigger_type,
            times=sched.times, interval_seconds=sched.interval_seconds,
        )
        if sched_vo is not None:
            scheduler.upsert(f"sched:{sched.id}", sched_vo, {"schedule_id": sched.id})
    scheduler.start()

    app.state.services = services
    app.state.runner = runner
    app.state.scheduler = scheduler
    yield
    scheduler.shutdown()
```

## 10. 风险与回退

| 风险 | 概率 | 影响 | 缓解 |
|:--|:-:|:-:|:--|
| 26 个 fetcher 改基类时漏掉某个 | 中 | 中 | 单元测试覆盖：每个 fetcher 至少 1 个 `test_fetch_returns_list_of_bo` |
| 22 个 service 漏写并发/限流 | 中 | 中 | 模板（`DailyKlineService`）严格遵循，code review 逐个对照 |
| 删除顺序错（先删依赖者后删被依赖者） | 低 | 高 | 按"依赖反推图"（§8）顺序删；每步独立 commit |
| `collect_jobs` 数据迁移遗漏 | 低 | 中 | 迁移 SQL（见 01 文档 §3.3）必须先备份 + 验证再删表 |
| 调度触发时 service 未注册 | 低 | 低 | `ServiceRegistry.require()` 抛 `KeyError`，log 告警，调度 skip |
| 多 worker 部署时同时跑同一 schedule | 中 | 中 | APScheduler `max_instances=1` 已保证；新增 `collect_run_log` 上加唯一约束（schedule_id + started_at 时间窗） |

**回退方案**：
- 每个阶段独立 commit
- 回退到任一阶段：`git revert <commit>`
- 数据迁移可逆：迁移 SQL 前 `pg_dump collect_jobs > backup.sql`
- 新表用 `IF NOT EXISTS`，可重复执行
