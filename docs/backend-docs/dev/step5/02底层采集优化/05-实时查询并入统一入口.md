# 05 实时查询并入统一入口：取消 realtime/

> 对应 README 流程 ④ 和使用方式"实时查询"。阶段 P3。

## 1. 现在 realtime 做什么

"实时接口" = 页面当前要看的数据，按需请求数据源，结果只写 Redis，不入库、不建任务记录。现有 2 个：`stock_minute_kline`（pytdx 分 K）、`concept_minute`（同花顺概念分时）。

调用方：

| 调用方 | 方式 |
| :-- | :-- |
| `route/api/v1/minute_kline.py` `GET /minute-klines/{symbol}` | 直接调 framework |
| `route/api/v1/concept.py` `GET /concepts/{index_code}/minute` | 直接调 framework |
| `route/api/v1/collect_task.py` `POST /collect/realtime/{name}/query`、`GET .../stats` | 直接调 framework（采集管理"试查"和统计） |
| `concept_service.get_quotes`、`concept_board_service`（3 处） | 经 `RealtimeQueryPort.query_many` |

`realtime/` 里混了五类职责：

| 职责 | 现在在哪 | 性质 | 改造后去处 |
| :-- | :-- | :-- | :-- |
| 数据定义（facet / label / 数据源） | `BaseRealtimeQuery` 类变量 | 元数据 | XxxPort（01） |
| 取数 | `Query.fetch()` | 底层实现 | XxxAdapter（02） |
| 缓存（TTL 跟交易时段）、单飞锁、超时 | `framework._query` | 横向技术能力 | **`CacheDecorator`**（本文 §3） |
| 同源并发、调用统计 | `framework._fetch` / `_record` | 横向技术能力 | `ThrottleDecorator` / `MetricsDecorator`（03） |
| 参数规范化（days → count） | `Query.normalize` / `fetch` | 接口约束 | Port 的 `Params` 模型校验器（本文 §2） |
| 降级（概念行情失败返回库里最近收盘）、结果组装 | `Query.fallback` / `fetch` | **业务逻辑** | 应用层 Service（本文 §4） |

拆完之后 `realtime/` 里没有剩下的东西，整个目录删除。实时查询就是"应用层 Service 用 `policy=QUERY` 调统一入口"。

## 2. 实时类 Port

声明了 `cache` 的 Port 即为"实时接口"，名称沿用现有的 `stock_minute_kline` / `concept_minute`，保证 `collect_fetchers` 表、前端"试查"、统计接口不变。

## 3. CacheDecorator

```python
# adapter/data/core/cache.py
class CacheDecorator:
    async def get_or_load(self, port, params, load) -> DataResult:
        key = f"ds:cache:{port.name}:{_hash(params)}"     # params.model_dump(mode="json") 排序后 sha1
        hit = await self._read(key, port.Item)            # 命中：反序列化成 Item，cached=True
        if hit: return hit
        if not await self._lock(key):                     # 单飞：SET NX EX 5；等 2s 轮询缓存
            ...
        try:
            result = await asyncio.wait_for(load(), timeout=FETCH_TIMEOUT)   # load = Gateway 选源 + 装饰器链
            await self._write(key, result, ttl=ttl_for(port.cache.ttl_trading))
            return result
        finally:
            await self._unlock(key)
```

- 逻辑从 `realtime/framework.py::_query` 原样搬过来：锁 TTL 5s、等待 2s、轮询 0.1s、超时 10s、Redis 不可用时直接取数不缓存（`try_get_redis`）。
- **缓存键自动生成**，各接口不再手写 `cache_key`。参数先经 `Params` 规范化再算哈希，所以 `days=1` 和 `count=48` 这种等价参数会命中同一份缓存。
- 缓存存的是 `Item.model_dump(mode="json")` 列表 + `source` + `fetched_at`，读出时用 `Item.model_validate` 还原成 BO。
- 缓存放在选源之前：同样的参数不管最终由哪个数据源返回，都命中同一份缓存。
- 失败时不写缓存、不做降级，直接抛给调用方，降级由业务决定（§4）。
- 只在 `policy=QUERY` 且 Port 声明了 `cache` 时启用；采集任务（`COLLECT`）永远不走缓存。

## 4. 业务降级与结果组装移到应用层

### 4.1 概念实时行情：新增 ConceptRealtimeReader

`concept_service` 和 `concept_board_service`（3 处）都在查 `concept_minute`，且都依赖"失败时返回最近收盘"。把这段共用逻辑放到一个应用层小类里，两个 Service 注入使用：

```python
# application/service/concept_realtime.py
class ConceptRealtimeReader:
    def __init__(self, gateway: DataGatewayPort, repo: ConceptRepository): ...

    async def minutes(self, codes: list[str]) -> dict[str, ConceptMinuteVO]:
        results = await self._gateway.invoke_many(
            [DataCommand("concept_minute", {"index_code": c}, policy=CallPolicy.QUERY) for c in codes]
        )
        out, failed = {}, []
        for code, res in zip(codes, results):
            if isinstance(res, DataResult) and res.items:
                out[code] = ConceptMinuteVO.from_bo(res.items[0], cached=res.cached, fetched_at=res.fetched_at)
            else:
                failed.append(code)
        if failed:                                   # 降级：一次查出失败概念的最近日 K 收盘，标 stale
            closes = await self._repo.get_latest_closes(failed)
            out.update({c: ConceptMinuteVO.from_close(c, closes[c], stale=True) for c in failed if closes.get(c)})
        return out
```

- 降级查询从"每个概念单独查一次库"变成"失败的概念一次批量查"。
- `concept_service.get_quotes`、`concept_board_service` 的 3 处调用、`GET /concepts/{index_code}/minute` 都改用它。返回字段（`stale` / `cached` / `fetched_at` 和行情字段）与现在一致。

### 4.2 股票分 K

```python
# stock_info_service
async def get_minute_klines(self, symbol, interval, days, count) -> MinuteKlineVO:
    res = await self._gateway.invoke(DataCommand(
        "stock_minute_kline", {"symbol": symbol, "interval": interval, "days": days, "count": count},
        policy=CallPolicy.QUERY,
    ))
    return MinuteKlineVO(total=len(res.items), items=[_format_bar(b) for b in res.items],
                         cached=res.cached, fetched_at=res.fetched_at)
```

`_format_bar` 是原 `StockMinuteKlineQuery.fetch` 里组装每根 K 线的那段。`GET /minute-klines/{symbol}` 改调这个方法，响应字段不变。分 K 没有降级，与现在一致。

### 4.3 发现的问题：concept_board_service 的实时涨跌幅

`concept_board_service.py` 第 153 行用 `{"symbol": s, "interval": "1d"}` 查 `stock_minute_kline`。`1d` 不在 `BARS_PER_DAY` 里，`normalize` 会抛 `ValueError`，`query_many` 把它吞成一条 error 结果，所以这里的实时涨跌幅**现在每次都取不到**。改造时需要确认这段的本意（是要当日分 K 计算涨跌幅，还是另一个"实时行情快照"接口），再决定改成 `interval="1min"` 还是新增一个 Port。

## 5. 采集管理页相关的改动

| 接口 | 改造后 | 兼容性 |
| :-- | :-- | :-- |
| `GET /collect/catalog` | 实时接口部分改为遍历声明了 `cache` 的 Port：`kind="realtime"`、`ttl_trading` / `consumers` 取自 `cache`、`default_params` 取自 `sample_params`、`source` / `source_label` 取首选 Adapter 的 `origin` 及其中文标签 | 字段不变 |
| `POST /collect/realtime/{name}/query`（试查） | `gateway.invoke(DataCommand(name, body, policy=QUERY))` | 响应仍是 `{data, cached, stale, fetched_at, latency_ms, error}`；**`data` 变为 BO 列表**（原来是各接口自己组装的结构），`stale` 恒为 false（试查不做业务降级） |
| `GET /collect/realtime/{name}/stats` | 读 `ds:stats:{name}:cache:*`（命中）+ `ds:stats:{name}:*:*`（各实现的调用和错误）合并 | 返回字段不变；历史 `rt:stats:*` 不迁移，上线后从零开始统计 |

`origin` 的中文标签放在 `adapter/data/core/registry.py`：`{"tushare": "Tushare", "ths": "同花顺", "tdx": "通达信", "eastmoney": "东方财富"}`。
