# 04 · 临时日志/脚本清理

## 1. 问题描述

工作区有 6 个临时文件：

| 文件 | 来源 | 用途 | 当前是否有用 |
|------|------|------|------------|
| `backend/.b1.err` | 本轮调试启 8001 后端的 stderr | 调试日志 | **无用** |
| `backend/.b1.log` | 上一轮调试的访问日志（curl 测试记录）| 调试日志 | **无用** |
| `backend/.b8.err` | 本轮调试启 8000 后端的 stderr | 调试日志 | **无用** |
| `backend/.vite.log` | 本轮调试启 vite dev server 的输出 | 调试日志 | **无用** |
| `backend/.scratch_v.ps1` | 本轮调试查 uvicorn 进程的 ps1 | 临时脚本 | **无用** |
| `backend/check_after.py` | 早期调通的 asyncpg+redis 连接检查 | 临时脚本 | **可能有用（ad-hoc 数据库诊断）** |

---

## 2. 现状盘点

### 2.1 已确认无用的（4 个调试日志 + 1 个临时 ps1）

- `.b1.err`：上次启 8001 后端的 stderr 抓取文件，已用完
- `.b1.log`：之前一轮调试期的 curl 访问日志，已用完
- `.b8.err`：本轮启 8000 后端的 stderr 抓取文件，已用完
- `.vite.log`：本轮启 vite dev server 的输出文件，已用完
- `.scratch_v.ps1`：调试查进程用的 powershell 片段，已用完

### 2.2 可能仍可保留的（`check_after.py`）

- 内容：检查 PostgreSQL 表存在性 + Redis 连接性
- 历史作用：早期用来诊断环境是否就绪
- **判断**：
  - 如果不再需要诊断环境，**可删**
  - 如果想留作 ad-hoc 工具，**移到 `scripts/` 下**（项目级 diagnostics 目录）
  - 看 git log 是否有提交历史（如没有，就是临时调试产物）
- 当前在 `backend/check_after.py`（与 src/ 同级），**不在 gitignore 中**，**不会被 `.log` 规则忽略**

### 2.3 已 gitignore 的规则（参考）

`.gitignore` 已经忽略了：
```
*.log
logs/
```

所以 `.b1.log` / `.vite.log` 等`.log` 后缀文件**不会进入 git**，只是占工作区磁盘。

### 2.4 不应该清掉的

- `backend/src/backend-start.log` / `backend/src/backend-start2.log` — 旧的后端启动日志（debug 历史参考），可能需要查时序问题
- `backend/.env` / `.env.local` / `.env.smtp.example` — 环境配置（生效中）

## 4. 清理方案

### 4.1 推荐方案：直接删（最小侵入）

**步骤**：
1. 停掉所有后端/vite 进程（释放文件锁）
2. 删 5 个调试文件 + check_after.py：
   ```
   rm backend/.b1.err
   rm backend/.b1.log
   rm backend/.b8.err
   rm backend/.vite.log
   rm backend/.scratch_v.ps1
   rm backend/check_after.py
   ```
3. 如要保留 check_after.py，移到 `backend/scripts/check_connections.py`

### 4.2 备选方案：列入 `.gitignore`（即使每次重建也不会污染）

`★ 不确定点 Q5 ─────────────────────────────────────`
- 在 `.gitignore` 加：
  ```
  # 调试期临时日志
  /.b*.err
  /.b*.log
  /.b8.err
  /.vite.log
  /.scratch_*.ps1
  /.scratch*.py
  ```
- **优点**：以后启后端/vite 时再生成同名文件也会被自动忽略
- **缺点**：临时文件还是会在磁盘上
- 如果想避免生成，应该改启动方式（让脚本输出到 `%TEMP%` 目录）
- `────────────────────────────────────────────────`

### 4.3 推荐步骤

1. **本轮清理**（方案 4.1）：删除 6 个临时文件
2. **后续优化**（方案 4.2，可选）：加 `.gitignore` 规则 + 启动脚本改 `%TEMP%`
3. 不动 `backend/src/backend-start*.log`（历史日志留作参考）
