## 1. 设计原则

### 1.1 五大铁律

1. **零业务代码侵入**：`StockInfoList.vue` / `PoolList.vue` / `Dashboard.vue`（现状版） / 任何已实现的页面 / service / repository 都不动。
2. **零数据库表新增**：所有新功能基于现有表 `stock_infos` / `fin_daily_basics` / `fin_reports` / `tech_kline_dailys` / `concepts` / `stock_concept_members` / `concept_index_ths` / `stock_pools` / `stock_pool_members` / `cap_moneyflows` / `cap_top_lists` / `mkt_sector_dailys`。
3. **DDD 分层零破坏**：新增的 entity / vo / repository 协议 / service 都按 `docs/config/DDD.md` 走，DTO 全部放 `route/dto/`，不破坏现有 DTO 风格（pydantic v2 + `from_attributes` + `Page[T]`）。
4. **前端密度锚点架构零破坏**：所有新页面沿用 `PageWrapper` + `--xxx-page-density` + `--xxx-{top|middle|bottom}-density` + `density-inline` 横向滚动模式（`page-development-guide.md §三 ~ §十四`）。
5. **实时刷新零后端改动**：复用 `infrastructure/adapter/realtime/RealtimeQueryFramework`（`framework.py`）+ 前端 `composables/useRealtimePoll.ts`，**不引入 SSE / WebSocket**。

### 1.2 与 step3/01 登录鉴权的协同

- 已有的 `auth` 模块提供了 `get_current_user_id` / `require_role` / `require_permission`，**新页面直接复用**。
- `stock:read` / `pool:read` 权限已存在；新页面**默认公开**（与现有 `/stock-panel/` 一致），后续如要权限收紧按 `route 层` 加一行 `dependencies=[Depends(require_permission("stock:read"))]` 即可。
- 用户偏好（看板预设 / 视图模式 / 选股集合）暂存 `localStorage`，不存 `sys_user_preferences` 表（避免新增表）。如未来要云端同步，再加一张表 + 接口，本期不做。

### 1.3 命名约定

| 类别 | 约定 | 例子 |
|---|---|---|
| 前端视图目录 | `kebab-case`，与路由名一致 | `views/concept-board/` `views/realtime-board/` `views/stock-screen/` |
| 前端子组件 | `PascalCase.vue` | `ConceptHeatmap.vue` `StockCompareDrawer.vue` |
| 前端 composable | `useXxx.ts` | `useRealtimeBoard.ts` `useColumnPresets.ts` |
| 前端 API | `xxx-board/api.ts` 独立文件 | `views/concept-board/api.ts` |
| 前端密度锚点前缀 | 与目录英文名一致 | `--cb-*`（concept-board） / `--rb-*`（realtime-board） / `--ss-*`（stock-screen） / `--dv-*`（dashboard-view） |
| 前端 localStorage key | `<prefix>-<scope>` | `cb-density` `rb-preset-active` `rb-cols-custom` |
| 后端路由文件 | `route/api/v1/<name>.py`，沿用现有前缀 | `concepts.py`（扩展）/ `stock_panel.py`（扩展）/ `dashboard.py`（新增） |
| 后端 DTO | `route/dto/request/<name>.py` / `route/dto/response/<name>.py` | `request/concept_board.py` / `response/concept_board.py` |
| 后端应用服务 | `application/service/<name>_app_service.py` | 扩展 `concept_app_service.py` / `panel_app_service.py`，新增 `dashboard_app_service.py` |
| 后端领域协议 | 现有 `domain/entitys/<agg>/repository.py` 扩展 | `ConceptRepository.list_board_rows` |
| 后端仓储实现 | 现有 `infrastructure/persistence/repositories/<name>_repository.py` 扩展 | `concept_repository.py` 增方法 |

| 为什么实时走 15s 轮询而不是 SSE？ | 复用现有 `useRealtimePoll` + `RealtimeQueryFramework`，零后端改动；15s 对看盘足够；如未来要"tick 级"再升级 SSE（项目索引 §8 已列待做）。 |
| 为什么看板预设只存 localStorage？ | 单机个性化、零后端压力；如未来要云端同步，加一张 `sys_user_preferences` 表 + 接口即可，本期不做。 |
| 为什么概念大盘是独立路由而不是 SectorBoard 子页？ | 概念 = 同花顺（已有 fetcher）；行业板块 = Tushare（未采集）。两个数据源、两种成熟度，分开更清晰；合并会拖慢上线。 |
| 为什么不重写 StockInfoList？ | 用户明确要求"不修改已实现页面"。本方案通过新建 `/home/realtime-board` 把"实时行情列 + 列自定义"装到新页，不动老页。 |
| 视图切换是否影响性能？ | 不影响。三视图共享同一份数据（`StockRealtimeItem[]`），只在 `v-if` 切换渲染。最大数据集 500 行（与现有 `stock-panel` 同一量级）。 |
| Dashboard 重写是否破坏现有 URL？ | 不。`/home/index` 路由不变，只是 `Dashboard.vue` 内部重写为新组件。`stock-info/api.ts` 等公共 API 仍可用。 |
| 是否需要数据库迁移？ | 不。0 新表 / 0 改列。`migrations/` 目录不动。 |
| 是否需要新增依赖？ | 不。`requirements-base.txt` / `requirements.txt` 都不动。 |
| 是否要更新主索引文档？ | 要。`docs/overview/00-项目索引.md` §4/§5/§7 同步更新（实施时一次性补一行）。 |
| 列自定义的字段从哪来？ | 字段定义写在 `frontend/src/views/realtime-board/columns.ts`（白名单），不允许用户随意加列。 |
