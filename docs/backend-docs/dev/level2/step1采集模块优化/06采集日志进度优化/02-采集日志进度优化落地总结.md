### 1.3 设计说明：META 的职责边界

```
┌─────────────────────────────────────────────────────────────┐
│                      META（ServiceMeta）                    │
│  仅用于：                                                   │
│    1. 前端 catalog 展示（label / description / param_schema）│
│    2. 限速配置（rate_limit）                                │
│    3. 并发数（concurrency）                                 │
│    ❌ 不参与采集日志                                         │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼

│                    Handler（collect_handler）                │
│  采集任务的元信息由 handler 统一创建：                        │
│    - log_id（uuid4）                                        │
│    - service_name / facet / kind                           │
│    - params                                                │
│    - trigger_source = "manual"                             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  Service（daily_kline_service）             │
│  collect() 调用 collect_with_logging() 传入元信息           │
└─────────────────────────────────────────────────────────────┘
```

## 二、架构说明

### 2.1 采集流程

```
前端点击"开始采集"
       │
       ▼
POST /collect/{facet}/{service_name}
       │
       ├─ 同步创建 collect_logs 记录（status=pending）
       ├─ 同步写 Redis pending hash
       ├─ 返回 { log_id: "xxx" }
       │
       ▼
前端收到 log_id，开始轮询
GET /collect/logs/{service_name}
       │
       ▼
后台任务启动
asyncio.create_task(svc.collect(...))
       │
       ├─ AOP 装饰器标记 status=running
       │
       ├─ 每完成一个 symbol → yield 进度
       │     │
       │     └─ AOP 更新 Redis 进度
       │
       └─ 全部完成 → 终态落库 DB + Redis
              │
              ▼
       前端收到终态，停止轮询
```

### 2.2 状态机

```
pending ──→ running ──→ success
                  ├─→ partial_fail
                  └─→ failed
```

| 状态 | 含义 |
|---|---|
| `pending` | 日志已创建，等待采集任务启动 |
| `running` | 采集中，progress 实时更新 |
| `success` | 采集完成，全部成功 |
| `partial_fail` | 采集完成，部分失败 |
| `failed` | 采集失败 |
| `skipped` | 跳过（realtime 类型） |

### 2.3 Redis Key 设计

```
Key:   collect:log:{service_name}:{log_id}
Type:  Hash
TTL:   3600 秒（1小时）

Field: status / progress / saved_count / fail_count / total_count / ...
```

## 六、ServiceMeta 迁移情况

| Service | META | Generator | 状态 |

| 其他 27 个 service | ⏳ 待迁移 | ⏳ 待改造 | 后续迭代 |

### 迁移方式

```python
# 旧写法
class SomeService:
    name = "xxx"
    facet = "tech"
    RATE_LIMIT = ("tushare", 200, 60)
    CONCURRENCY = 5

# 新写法
from contexts.collect.application.service.base import ServiceKind, ServiceMeta

class SomeService:
    META = ServiceMeta(
        name="xxx",
        facet="tech",
        kind=ServiceKind.INCREMENTAL,
        rate_limit=("tushare", 200, 60),
        concurrency=5,
        param_schema=[...],
    )
    
    @collect_logger(META)
    async def collect(self, params, session, log_id=None):
        async for batch in self._collect_impl(params):
            yield batch  # 边采集边 yield
```

## 七、前端轮询机制

| 场景 | 行为 |
|---|---|
| 进入页面有 pending/running 日志 | 自动接着轮询 |
| 触发新采集 | 立即拿到 log_id → 开始轮询 |
| 同一时间多个采集 | 各自独立轮询（按 log_id 区分） |
| 终态（success/partial_fail/failed） | 停止轮询，显示结果 |

轮询频率：**2 秒一次**
