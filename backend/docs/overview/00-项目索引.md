## 1. 项目概览

A 股个股归因分析系统：采集行情 / 估值 / 概念等多维数据入库，前端做股票面板、操作池、采集管理，并为后续 AI 归因提供统一数据入口（`GET /api/v1/stocks/{symbol}/analysis`）。

| 层 | 技术 |
|---|---|
| 后端 | Python 3.13 · FastAPI · SQLAlchemy 2（async + asyncpg）· pydantic-settings |
| 存储 | PostgreSQL（`stock_db`）· Redis（采集进度 hash `collect:progress:{task_id}`） |
| 数据工具 | tushare 1.4.3 · adata 2.9.5 · tdxpy（pytdx 协议）· pandas |
| 前端 | Vue 3 · TypeScript · Vite · Element Plus · Pinia |

## 2. 运行方式

```powershell
# 后端（backend/ 目录，读取 backend/.env）
python .\src\main.py            # uvicorn :8000，WatchFiles 热重载；Swagger: /docs

# 命令行触发采集任务（依次执行并等待完成）
python .\scripts\trigger_collect.py concept concept_membership --limit 20 --param only_missing=true

# 测试
pytest tests\infrastructure\tasks\collect
```

关键配置（`src/infrastructure/config/settings.py`，`.env` 覆盖）：`DATABASE_URL`、`REDIS_URL`、`TUSHARE_TOKEN`、`COLLECT_CONCURRENCY`(3) / `COLLECT_MAX_CONCURRENCY`(8) / `COLLECT_CHUNK_SIZE`(30)。

注意：
- 启动时 `main.py` 的 `lifespan` 会先跑迁移函数（`_migrate_*`，重命名/重建旧表）再 `Base.metadata.create_all`，**没有 Alembic**，新表靠 ORM 自动建、改列需写迁移函数。
- WatchFiles 也监听 `scripts/`、`tests/`，改这些文件会触发重载；重载会等待正在跑的后台采集任务。
- `tests/test_e2e_api.py` 会删除开发库数据，勿在有真实数据的库上跑。

## 3. 后端目录结构（DDD）

分层规则见 [`docs/config/DDD.md`](../config/DDD.md)：`route → application → domain ← infrastructure`，DTO / BO 统一放 `route/dto`。

│   ├── api/router.py               # 聚合 /api/v1
│   ├── api/v1/*.py                 # 8 个路由模块（见 §4）
│   └── dto/request|response/*.py   # 请求 DTO / BO、响应 VO

│   ├── port/registry.py            # FetcherRegistry + setup_default_registry（协议 → 实现 绑定）
│   └── service/*_app_service.py    # collect（采集统一入口）/ concept / kline / panel / pool / pool_operation / stock / stock_analysis
├── domain/
│   ├── entitys/<实体>/             # entity / vo / repository 协议（24 个实体目录）
│   └── services/                   # indicator_calculator(17 指标) / signal_detector / concept_brief_service
└── infrastructure/
    ├── config/                     # settings / di

    │   ├── base.py                 # BaseCollector（限速 / 重试基类）
    │   ├── tushare/                # TushareFetcher + parser
    │   ├── adata/fetcher.py        # AdataConceptFetcher（同花顺概念）
    │   ├── pytdx/                  # PytdxFetcher + parser（通达信分钟 K）
    │   ├── cache/redis_client.py

## 6. 采集框架

> 摘要：[`collectmanage摘要.md`](collectmanage摘要.md)（链路 / 任务表 / 业务侧采集入口 / 已知问题）

- **任务基类** `scheduler/collect/base.py` `BaseCollectTask`
  - 元数据 ClassVar：`name`（task_type）/ `facet` / `sub_facet` / `label` / `description` / `status`（`ready`|`planned`）/ `sort_order`（同子分类内排序）
  - 生命周期：`estimate_total(params)` → `run(params, on_unit_done)` → `TaskSummary`；取消通过 `is_cancelled` 协作式检查（抛 `Cancelled`）
  - 单元接口：`list_units(params)` + `collect_one(unit, params) -> UnitResult`；默认 `run()` 遍历单元（`concurrency` 分批、失败末尾重试一轮），`default_params` 为默认参数
  - 状态判定：仅 `success == 0 且 fail > 0` 时为 failed
- **统一入口** `application/service/collect_app_service.py` `CollectAppService`：`submit`（后台任务，防重 + 记录 + Redis）/ `run_one`（同步单元，业务路由用）/ 方案与任务组 CRUD / `run_group`（串行，`stop_on_fail`）
- **调度器** `scheduler/collect_scheduler.py`：APScheduler（`Asia/Shanghai`），启动时加载启用的 `collect_plans` / `collect_groups`；`.env` `COLLECT_SCHEDULER_ENABLED=false` 可关闭
- **注册表** `scheduler/collect/registry.py`：`main.py` lifespan 注册所有任务；`catalog()` 输出 facet → sub_facet → tasks（按 `(sort_order, label)` 排序），空 facet 不输出。四个 facet：`tech` 技术面 / `capital` 资金面 / `fundamental` 基本面 / `news` 新闻面。
- **Fetcher 绑定** `application/port/registry.py`：

| 协议 | 实现 | 工具 |
|---|---|---|
| `KlineFetcher` / `StockBasicFetcher` / `DailyBasicFetcher` / `FinReportFetcher` | `TushareFetcher` | tushare Pro |
| `MinuteKlineFetcher` | `PytdxFetcher` | tdxpy → 通达信行情服务器 |
| `ConceptFetcher` | `AdataConceptFetcher` | adata → 同花顺 |

- **任务清单**：9 个已实现（`daily_kline` / `stock_basic` / `daily_basic` / `fin_report` / 概念 5 个）+ 14 个 planned，按数据面明细见 [`01-四个数据面采集实现总结.md`](../dev/step2/01当前实现/01-四个数据面采集实现总结.md)。
- **业务复用**：`/stocks/sync`、`/stocks/sync-daily-basic`、`/klines/collect(/batch)`、池操作均调 `run_one`；支持的接口：`daily_kline` / `daily_basic` / `stock_basic` / `fin_report` / `concept_membership` / `concept_reason`。
- **调度**：采集方案（单接口 cron）+ 任务组（多接口按顺序，cron 或手动）；「仅交易日」暂只排除周末。设计见 [`04-修订方案.md`](../dev/step2/04采集管理优化/04-修订方案.md)。
