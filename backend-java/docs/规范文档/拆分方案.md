# Java 单体多模块 + Python 采集服务拆分方案

> 状态：方案设计，不改代码。
> 结论：`backend-java` 为单体多模块（1 个可部署 jar），`collector-python` 为独立 FastAPI 服务（1 个可部署单元）。不拆微服务。
> 原始现状依据（拆分前的 Python 工程）：`backend/src/contexts/{auth,market,concept,user,collect,scheduler} + shared`，`docker-compose.yml`（postgres+redis+backend+frontend）。

---

## 1. 目标形态（最终 2 个可部署单元 + 2 个基础件）

```text
Attribution_Analysis/
├─ backend-java/                        # Java 单体：1 parent pom + 6 modules，打 1 个 fat jar
│  ├─ pom.xml                           # parent，packaging=pom，只管版本+模块列表
│  ├─ attribution-common/               # jar：R/分页/异常/常量，无业务依赖
│  ├─ attribution-collector-client/     # jar：Feign 调 Python，DTO+Client+Fallback
│  ├─ attribution-market/               # jar：行情/K线/面板/归因 Controller+Service+Mapper
│  ├─ attribution-concept/              # jar：概念 Controller+Service+Mapper
│  ├─ attribution-user/                 # jar：自选池 Controller+Service+Mapper
│  ├─ attribution-auth/                 # jar：登录/用户/角色/权限 Controller+Service+Mapper
│  └─ attribution-app/                  # 可执行 jar：启动类+application.yml+组装全部
│     └─ src/main/java/com/attribution/AttributionApp.java
├─ collector-python/                    # = 现 backend/src 中 collect 上下文整体搬迁（FastAPI）
│  ├─ connect/  fetcher/  parser/  service/  route/  cache/
│  └─ 暴露 POST /api/collect/{facet}/{name} + GET /api/collect/services + GET /api/collect/query/{name}
├─ frontend/                            # 不变，API 前缀保持 /api
├─ postgres/  redis/                    # 不变，共用一库一缓存
└─ docker-compose.yml                   # backend → java-app(8080) + collector(8001)
```

部署视图（4 容器）：

```text
frontend(:80) ──▶ java-app(:8080) ──Feign──▶ collector-python(:8001)
                      │                          │
                      └────▶ postgres:5432 ◀─────┘
                      └────▶ redis:6379 ◀────────┘（采集限频+验证码/会话）
```

为什么是单体多模块而不是微服务：`market→concept/user/collect`、`user→market/collect`、`concept→collect(fetcher/connect)` 全是进程内强一致调用（面板组装一次跨 3 上下文，`stock_info JOIN kline JOIN concept`），拆服务即引入 OpenFeign×N + 分布式事务，个人项目无 QPS 分化、无多团队、无 Nacos/Gateway 基建，不值得。模块化已预留未来可拆（某 module 加 `repackage` 即独立 jar）。

## 2. Maven POM 划分（1 父 + 6 子）

### 2.1 parent `backend-java/pom.xml`

* `packaging=pom`，`modules` 按依赖拓扑排序：common → collector-client → market/concept/user/auth → app（app 最后）。
* 只做：`dependencyManagement`（springboot 3.x、mybatis-plus、feign、postgres driver、redis、validation、jjwt）、`properties`（java 21、encoding UTF-8）、公共插件（compiler、surefire）。
* 不放任何业务代码，不配 `spring-boot-maven-plugin.repackage`。

### 2.2 各子模块 pom

| 模块 | packaging | 依赖 | 说明 |
|---|---|---|---|
| attribution-common | jar | spring-web、validation、jackson | R/分页/异常/GlobalExceptionHandler/常量，不依赖任何业务模块 |
| attribution-collector-client | jar | openfeign、common | `CollectorClient` + 请求/响应 DTO + Fallback，只依赖 common |
| attribution-market | jar | common、collector-client、mybatis-plus | 可依赖 concept-api（见 §5），不可依赖 user/auth 的 mapper |
| attribution-concept | jar | common、mybatis-plus | 被 market 依赖，保持零业务依赖（最干净） |
| attribution-user | jar | common、collector-client、mybatis-plus | 可调 market 的 Service（单向），禁止 market→user 与 user→market 双向 |
| attribution-auth | jar | common、mybatis-plus、redis、mail | 登录/权限，独立，不被业务依赖（filter 层除外） |
| attribution-app | 可执行 jar | 全部上述模块 | 唯一含 `spring-boot-maven-plugin(repackage)`、`application.yml`、启动类 |

### 2.3 attribution-app（启动+组装模块）

只放 3 样，不放业务 Controller/Service/Mapper：

```java
package com.attribution; // 顶层包，覆盖 com.attribution.market.** 等
@SpringBootApplication
@MapperScan({
    "com.attribution.market.mapper",
    "com.attribution.concept.mapper",
    "com.attribution.user.mapper",
    "com.attribution.auth.mapper"
})
@EnableFeignClients("com.attribution.collector.client")
public class AttributionApp { public static void main(String[] a){ SpringApplication.run(AttributionApp.class,a);} }
```

> 📌 `@MapperScan` **必须显式列出每个模块的 mapper 包**——新增模块时要手动加进来（见 `../纵向分层规范/Mapper层规范.md` §2）。
> 本项目**不使用** `@EnableScheduling`：调度能力不在 Java 侧（见 `../开发文档/采集模块/采集模块现状文档（三类采集：增量-全量覆盖-实时查询）.md` §6.5）。

* `src/main/resources/application.yml`：全工程唯一配置（server.port=8080、datasource、redis、feign.python.url=http://collector:8001、jwt、mail、mybatis-plus mapper-location）。
* 打包：`mvn -pl attribution-app -am package`，产物 `attribution-app-*.jar` 为唯一 `java -jar`。

## 3. Java 各模块归属（Python route → Java Controller / model → Mapper）

> 原则：Python `contexts/X/interface/route/*` → Java `attribution-X/controller/*`；`contexts/X/infrastructure/persistence/models/*` → `entity/mapper/*`；`application/service/*` → `service/*`。URL 前缀保持 `/api` 不变，前端零改。

### 3.1 attribution-auth（认证+用户+角色权限）

Python 来源：`contexts/auth/interface/route/{auth_login,auth_register,auth_password,route_user,route_role,route_permission}.py`；模型 `auth/.../models/{user,user_role}.py`。

| Java Controller | 端口（保持） | Service | Mapper/表 |
|---|---|---|---|
| AuthController | POST /api/auth/login、/refresh、/logout、GET /api/auth/me、/captcha/generate、POST /api/auth/register、/send-verification-code、POST /api/auth/change-password、/forgot-password/* | AuthService、CaptchaService、EmailCodeService | users、user_role（现仅 user/user_role 模型，role/permission 表需新建或砍功能，二选一，见风险） |
| UserController | GET/POST /api/users、POST /api/users/{id}/reset-password、/roles | UserService | 同上 |
| RoleController / PermissionController | /api/roles、/api/permissions | RoleService | 同上 |

依赖：common + redis（验证码/Token）+ mail。无业务依赖。

### 3.2 attribution-market（行情+K线+四数据面+归因，最重）

Python 来源：`contexts/market/interface/route/{stock,kline,minute_kline,panel,data_board,stock_analysis}.py`；模型 `market/.../models/` 下 20+ 表（stock_info、tech_kline、base_adj_factor/suspend/name_change、cap_moneyflow/margin/top_list/top_inst/block_trade/holder_num、fin_daily_basic/fin_report/fin_top10_*、base_dividend 等）。

| Java Controller | 端口（保持） | Service | 说明 |
|---|---|---|---|
| StockController | GET /api/stocks/meta、/{symbol}、POST /api/stocks/、/sync、DELETE /api/stocks/{symbol}、POST /api/stocks/sync-daily-basic | StockInfoService | 基础 CRUD + 调 collector-client 触发回填 |
| KlineController | GET /api/klines/{symbol}、/{symbol}/stats、/{symbol}/{date}、POST /api/klines/collect、/collect/batch、DELETE | KlineService | 日K；分钟K实时走 `GET /api/minute-klines/{symbol}`（见下） |
| MinuteKlineController | GET /api/minute-klines/{symbol} | MinuteKlineService → collector-client.query(minute_kline) | 不入库，透调 Python |
| PanelController | GET /api/stock-panel/ | PanelService（组装 market+concept+user） | 跨模块调 concept 的 Service，不调其 Mapper |
| DataBoardController | GET /api/data-board/tech/*、/capital/*、/fundamental/*、/overview/{symbol}、/stock-list、/stock-list-all | DataBoardService | 纯读聚合，最大联表处，保持同库 JOIN |

### 3.4 attribution-user（自选池/操作池）

### 3.7 attribution-collector-client（Java→Python 唯一出口）

```java
@FeignClient(name="collector", url="${collector.base-url}", fallback=CollectorFallback.class)
public interface CollectorClient {
  @PostMapping("/api/collect/{facet}/{name}") Map<String,Object> collect(@PathVariable String facet, @PathVariable String name, @RequestBody Map<String,Object> params);
  @GetMapping("/api/collect/services") Map<String,Object> services();
  @GetMapping("/api/collect/query/{name}") Map<String,Object> query(@PathVariable String name, @RequestParam String params);
}
```

* DTO：`CollectRequest{facet,name,params}`，`QueryRequest{name,paramsJson}`。
* 超时：connect 3s / read 60s（采集慢）、重试 1 次 + Fallback 写 run_log。

## 4. collector-python（FastAPI 独立服务 :8001）

### 4.1 范围：collect 上下文整体搬迁，connect/fetcher/parser 原样不动

Python 来源：`contexts/collect/{application/service/**（28 service）,infrastructure/{fetcher,connect,parser,cache},interface/route/**,interface/router.py}`。

28 service（facet 路由与 `interface/router.py:facet_routers` 一致）：

* tech 5：daily_kline、minute_kline（realtime）、adj_factor、suspend、name_change
* capital 9：moneyflow、moneyflow_hsgt、top_list、top_inst、block_trade、margin、hsgt_top10、limit_list_d、holder_number
* fundamental 12：daily_basic、fin_income、top10_holders、top10_floatholders、dividend、stock_basic、stock_concepts、concept_list、concept_members、concept_index_daily、concept_minute（realtime）、concept_snapshot（realtime）
* news 1：news；sentiment 1：sentiment（占位，catalog 隐藏，见 `router.py:_HIDDEN_SERVICES`）

### 4.2 对外契约（Java 侧只调这 3 类）

```text
POST /api/collect/{facet}/{name}   Body: {params:{...}, trigger:"manual"|"schedule"} → {code,msg,data:{affected,elapsed}}
GET  /api/collect/services         → {total, items:[{name,facet,sub_facet,label,description,default_params,param_schema,supports_query,kind,path,query_path}]}
GET  /api/collect/query/{name}?params=<JSON>  → 实时（minute_kline/concept_minute/concept_snapshot 及 has_get=true 的 service）
```

* 入库类（26 个）：fetcher 拉 tushare/adata/pytdx → parser → 写库（RAW_DATABASE_URL/raw_data_db 与主库 attribution_db 双库，见 `settings.py:RAW_DATABASE_URL`；Java 侧需双数据源或先同库后拆）。
* 实时类（3 个 realtime + has_get=both）：不入库，直接返回。
* 限频：`collect/infrastructure/cache/rate_limit.check` + `RATE_LIMIT/CONCURRENCY/DEFAULT_PARAMS` 保留，redis 同实例。

### 4.3 独立事项

* 保留 `shared` 最小子集（response、settings、db_factory、redis_client）随 collector 走，不依赖 Java。
* `concept_realtime.py` 直调 `collect.infrastructure.fetcher/connect` 的捷径在拆分后必须走 HTTP（Java concept → Feign → collector `/query/concept_minute`），不再允许 import。
* collector 自己的 Dockerfile（python:3.12-slim），健康检查 `GET /api/collect/services`。

## 5. 模块依赖规则（防腐关键）

```text
app → market → concept → common
app → user → market（单向！砍掉现有 market→user 一向，见下）
app → auth（孤立）
market/user → collector-client → (HTTP) collector-python
禁止：跨模块调 Mapper；禁止循环依赖；禁止 concept 反向依赖 market。
```

* 现状循环：`market/.../di/stock_info.py` 依赖 `user/.../pool_repository`，同时 `user/.../di/stock_pool.py` 依赖 `market/.../stock_repository`。Java 落地时统一为 `user→market` 单向：面板“是否在池中”由 `PanelService` 调 `userApi.getPoolMembership()`（Service 接口），或前端二次查询 `/pools/by-symbol/{symbol}`，禁止 Mapper 互调。
* 跨模块只调 Service 接口（同进程，构造器注入），保持本地事务 `@Transactional` 可覆盖 `stock_info+kline+pool`。
* collector 调用一律经 `collector-client`，业务 Service 不得直连 HttpClient。

## 7. 落地步骤（只列序，不执行代码）

1. backend-java 搭空架：parent pom + 6 空 module + app 启动类能跑 `GET /ping`。
2. common + collector-client 先行（含 Feign+Fallback 单测调通 collector mock）。
3. collector-python 剥离：复制 `contexts/collect + shared最小集` 为独立工程，`uvicorn :8001` 跑通 28 POST + services + query。
4. auth → concept → user → market 依次搬迁（按表依赖从小到大），每搬一个对照 Python route 逐接口回归。
5. 联调：frontend→java→collector 全链路；采集任务的进度与审计写 `collect_logs` 验证。
6. docker-compose 切换 + 双 .env 上线。

## 8. 风险与待定

1. auth 的 role/permission 模型缺失（仅 user/user_role），搬迁时要么补表要么砍掉角色管理接口。
2. 双库（attribution vs raw_data_db）Java 侧数据源方案待定（推荐第二数据源 + 采集写 raw、业务读 attribution）。
3. `user/di/stock_pool.py` 的后台 operation_dispatcher 语义需在 Java 用线程池重实现，注意取消与进度语义对齐。
4. tushare Token 限频是全局瓶颈，collector 需单实例 + redis 限频，不可水平扩展多副本。
