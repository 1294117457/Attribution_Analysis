# 操作池 - 需求与场景

> 本文档定义"操作池（Stock Pool）"模块的业务需求、用户场景和功能边界。

---

## 1. 业务背景

### 1.1 当前痛点

| 场景 | 现状 | 痛点 |
|------|------|------|
| 用户研究行业 | 在 5000+ 股票中找行业 | 无法快速归类、对比 |
| 长期跟踪一组股票 | 没有"自选股"功能 | 每次都要重新选 |
| 批量采集K线 | 只能在 `DataCollect` 临时加入"备选池" | 备选池不持久，刷新就丢 |
| 准备做归因分析 | 没地方组织输入 | 每次都要重新选股 |
| 多套策略组合对比 | 没有"策略池"概念 | 无法区分多个组合 |

### 1.2 目标

提供一个**持久化、可分类、可批量操作**的股票容器，让用户：
1. 创建多个池（自选股 / 行业组合 / 策略池 / 主题）
2. 一次操作对池内所有股票生效
3. 历史操作可追溯
4. 数据不重复，与已有 `stock_infos` / `klines` 表协同

---

## 2. 用户角色

### 2.1 早期（v1）

**单一角色**：系统使用者（owner），所有池都归属 owner 唯一用户。

### 2.2 未来（v2+，预留字段）

- 团队协作：池可共享给其他用户
- 公开池：模板池（系统预置，不可改）

---

## 3. 核心场景

### 场景 1：创建池并加入股票

**前置条件**：用户进入"操作池"页面

```
用户操作流程：
1. 点击 [新建池]
2. 输入池名称（如"银行股组合"）
3. 选择池类型（自选 / 行业 / 策略 / 自定义）
4. 选择图标 / 颜色（可选）
5. [保存]

6. 进入池详情页
7. 点击 [添加股票]
8. 在股票选择器中搜索 / 多选 / 快速加入代码
9. [确认添加]
10. 池成员列表更新

结果：池与成员持久化到数据库
```

### 场景 2：对池内所有股票执行操作

```
用户操作流程：
1. 进入某个池的详情页
2. 点击 [采集K线]（或 [获取新闻] / [计算归因]）
3. 配置操作参数（采集天数、数据源等）
4. [开始执行]
5. 系统显示：操作已派发，总共 N 只股票
6. 前端通过 SSE 实时看到进度：已完成 5/30
7. 操作完成后显示结果摘要

后端：
- 创建 pool_operation 记录（status=pending）
- 派发后台任务
- 逐只 symbol 调用现有 KlineAppService.collect
- 更新进度（status=running, progress={done, total}）
- 任务完成更新 status=success/partial
```

### 场景 3：查看池的操作历史

```
用户操作流程：
1. 进入某个池的详情页
2. 切换到 [操作历史] Tab
3. 看到所有历史操作记录：
   - 时间、操作类型、参数、状态、进度、摘要
4. 可点击某条记录查看详细每只股票的成功/失败明细
```

### 场景 4：股票反向查询（这只股票在哪些池里）

```
场景：
用户在股票详情页，想知道"我哪些池里有这只股票"

用户操作：
1. 在 StockPanel 选中某只股票（如 000001 平安银行）
2. 弹出菜单：[查看所属池]
3. 显示："已在 3 个池中：自选股、银行股组合、深度研究"
4. 可点击进入对应池
```

### 场景 5：批量管理

```
场景：
用户想调整池成员顺序、删除池、批量清空

用户操作：
1. 进入池详情
2. [删除池] / [清空成员] / [调整排序] / [重命名]
3. 系统弹出确认
4. 执行成功
```

## 4. 功能清单（v1 范围）

### 4.1 池管理（CRUD）

| 功能 | 说明 | 必须？ |
|------|------|-------|
| 创建池 | 名称、类型、颜色、图标、描述 | ✅ |
| 查看池列表 | 显示所有池 + 成员数 + 创建时间 | ✅ |
| 查看池详情 | 池元信息 + 成员列表 + 操作历史 Tab | ✅ |
| 修改池 | 改名称/颜色/图标/描述 | ✅ |
| 删除池 | 级联删除成员和操作记录 | ✅ |
| 重命名池 | 单独接口（高频操作） | ✅（可与修改池合一） |

### 4.2 池成员管理

| 功能 | 说明 | 必须？ |
|------|------|-------|
| 添加单个成员 | symbol + memo | ✅ |
| 批量添加成员 | symbol 列表 | ✅ |
| 删除单个成员 | 按 symbol | ✅ |
| 批量删除成员 | symbol 列表 | ✅ |
| 清空池 | 保留池，删所有成员 | ✅ |
| 修改成员备注 | 改 memo | ✅（P1） |
| 调整成员顺序 | 拖拽改 sort_order | ❌（预留字段，P2） |
| 列出成员 | 分页 + 关联股票基本信息 | ✅ |

### 4.3 池内批量操作

| 操作类型 | 说明 | 必须？ |
|---------|------|-------|
| 采集K线 | 对池内所有股票调 `KlineAppService.collect` | ✅ |
| 获取新闻 | 对池内所有股票调 `NewsService.fetch` | ⏳ P2 |
| 计算归因 | 对池内所有股票调 `FactorService.calc` | ⏳ P2 |

**v1 只实现"采集K线"**，其余预留接口。

### 4.4 操作记录与进度

| 功能 | 说明 | 必须？ |
|------|------|-------|
| 创建操作记录 | 发起操作时写入 | ✅ |
| 更新进度 | SSE/WebSocket 推送 | ✅ |
| 查询操作记录 | 单条 + 列表 | ✅ |
| 操作明细 | 每只 symbol 的成功/失败明细 | ✅ |

### 4.5 反向查询

| 功能 | 说明 | 必须？ |
|------|------|-------|
| 查询某股票在哪些池 | `GET /pools/by-symbol/{symbol}` | ✅ |
| 查询池内某股票的状态 | "已采集K线 / 待采集" | ✅ P1 |

## 5. 非功能需求

### 5.1 性能

| 指标 | 要求 |
|------|------|
| 池列表加载 | < 200ms（池数 < 1000） |
| 成员列表加载 | < 500ms（成员数 < 1000） |
| 大池批量操作 | 支持 1000+ 成员不阻塞 HTTP |
| 操作进度延迟 | < 2s |

### 5.2 可靠性

| 指标 | 要求 |
|------|------|
| 操作任务失败 | 单只失败不影响其他；记录错误，可重试 |
| 并发安全 | 同池并发操作需要排队 / 锁定 |
| 进度持久化 | 任务重启后能从 DB 恢复进度 |

### 5.3 可用性

| 指标 | 要求 |
|------|------|
| 系统预置池 | 首次启动自动创建"我的自选" |
| 错误提示 | 明确的失败原因（股票不存在 / 网络失败） |
| 操作可中断 | 用户可主动取消进行中的操作 |

## 7. 边界与限制

### 7.1 v1 不做的事

| 不做 | 原因 |
|------|------|
| 池数据快照 | 增加复杂度，价值低（数据已有全局表） |
| 多用户协作 | 早期不必要，预留字段 |
| 池分享链接 | P2 |
| 拖拽排序 | P2 |
| 池导入/导出 | P2 |
| 池模板（公开池） | P2 |

### 7.2 边界情况处理

| 场景 | 处理 |
|------|------|
| 删除池时还在跑任务 | 任务继续跑完，记录保留但 pool_id 置 NULL（不级联删） |
| 添加不存在的 symbol | 报错：股票不存在（先调 `/stocks/query` 校验） |
| 添加退市股票 | 允许（业务场景：复盘退市股） |
| 重名池名 | 允许（不强制唯一） |
| 池成员数超过 1000 | 警告，但允许（业务可能存在） |
| 操作过程中池被删除 | 任务标记为 aborted，写入终止原因 |
| 并发发起两次同池采集 | 排队或拒绝（取决于策略） |

## 9. 与其他模块的依赖

| 依赖方向 | 被依赖模块 | 用途 |
|---------|----------|------|
| 操作池 → 股票 | `stock_info` 域 | 校验 symbol 存在性、获取股票基本信息 |
| 操作池 → K线 | `kline` 域 | 池级采集 K 线时调用 `KlineAppService.collect` |
| 操作池内部 | - | 自洽，不依赖其他池 |

**操作池本身不修改股票或 K 线表**，只读取并引用。

## 10. 名词表

| 名词 | 含义 |
|------|------|
| Pool | 操作池 |
| Pool Member | 池成员（一条 (pool_id, symbol) 记录） |
| Pool Operation | 一次池级批量操作（如采集K线） |
| Operation Record | 操作记录（pool_operations 表的一行） |
| Pending | 操作已创建未开始 |
| Running | 操作进行中 |
| Success | 操作全部成功 |
| Partial | 部分成功（部分失败） |
| Failed | 操作失败（未跑起来） |
| Default Pool | 系统预置的"我的自选"池（不可删） |
| Dispatcher | 任务派发器（决定同步/异步、并发度） |
