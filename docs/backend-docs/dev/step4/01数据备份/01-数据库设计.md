| 表名 | 用途 | 写入方 |

| `sys_backup_records` | 备份任务全生命周期 | 备份 service |

## 2. `sys_backup_records` — 备份记录

### 2.1 用途

记录每一次备份任务的：**配置（粒度 / 表 / 路径）+ 状态 + 产物**。

### 2.2 SQL 定义

```sql
CREATE TABLE IF NOT EXISTS sys_backup_records (
    id              BIGSERIAL    PRIMARY KEY,
    name            VARCHAR(128) NOT NULL,                 -- 文件名: full_20261006_153000_abc123.sql
    backup_type     VARCHAR(16)  NOT NULL,                 -- full | schema | data
    scope           VARCHAR(16)  NOT NULL,                 -- all | partial（partial = 选了子集）
    tables          JSONB        NOT NULL DEFAULT '[]'::jsonb,  -- ["stock_infos", "tech_kline_dailys"]; all 时 = 全表快照
    tables_count    INTEGER      NOT NULL DEFAULT 0,        -- 备份的表数量（冗余便于展示）
    output_dir      TEXT         NOT NULL,                  -- 实际输出目录（已 resolve 绝对路径）
    file_path       TEXT,                                   -- 实际产物绝对路径（成功后填）
    file_size       BIGINT,                                 -- 字节
    row_count       BIGINT       NOT NULL DEFAULT 0,        -- 总行数
    progress        INTEGER      NOT NULL DEFAULT 0,        -- 0-100
    progress_msg    VARCHAR(255) NOT NULL DEFAULT '',       -- 当前阶段文案 "COPY stock_infos..."
    status          VARCHAR(16)  NOT NULL DEFAULT 'pending',-- pending | running | success | failed | interrupted
    error_message   TEXT,
    started_at      TIMESTAMPTZ,
    finished_at     TIMESTAMPTZ,
    created_by      INTEGER      NOT NULL,                 -- user_id（来自 sys_users）
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS ix_sys_backup_records_status ON sys_backup_records (status);
CREATE INDEX IF NOT EXISTS ix_sys_backup_records_created_by ON sys_backup_records (created_by);
CREATE INDEX IF NOT EXISTS ix_sys_backup_records_created_at ON sys_backup_records (created_at DESC);

COMMENT ON TABLE sys_backup_records IS '备份任务记录：一次备份 = 一行';
COMMENT ON COLUMN sys_backup_records.backup_type IS 'full=结构+数据 / schema=仅结构 / data=仅数据';
COMMENT ON COLUMN sys_backup_records.scope IS 'all=全表 / partial=用户选了子集';
COMMENT ON COLUMN sys_backup_records.tables IS '备份的表名列表（all 时存全表名快照，便于审计）';
COMMENT ON COLUMN sys_backup_records.status IS 'pending=排队 / running=执行中 / success=成功 / failed=失败 / interrupted=被中断';
```

### 2.3 状态机

```
pending ──(asyncio.create_task 启动)──► running
                                            │
                            ┌───────────────┼───────────────┐
                            ▼               ▼               ▼
                         success         failed       interrupted
                            │           (异常退出)    (进程崩溃)
                            │               │               │
                            ▼               ▼               ▼
                       (产物存在)        (无产物)       (无产物)
```

**进程崩溃检测**：

```python
# main.py lifespan 启动期（与现有 _migrate_sys_collect_tasks 类似）
async with async_engine.begin() as conn:
    await conn.execute(text(
        "UPDATE sys_backup_records SET status='interrupted', "
        "finished_at=NOW(), error_message='服务重启，任务中断' "
        "WHERE status IN ('pending', 'running')"
    ))
    await conn.execute(text(
        "UPDATE sys_restore_records SET status='interrupted', "
        "finished_at=NOW(), error_message='服务重启，任务中断' "
        "WHERE status IN ('pending', 'running')"
    ))
```

## 3. `sys_restore_records` — 恢复记录

### 3.1 用途

记录每一次恢复任务：**来源 + 模式 + 自动 pre-backup 关联**。

### 3.2 SQL 定义

```sql
CREATE TABLE IF NOT EXISTS sys_restore_records (
    id                  BIGSERIAL    PRIMARY KEY,
    name                VARCHAR(128) NOT NULL,                  -- 任务名
    source_type         VARCHAR(16)  NOT NULL,                  -- file | upload | history
    source_path         TEXT         NOT NULL,                  -- 实际文件绝对路径
    source_backup_id    BIGINT,                                 -- 来源备份记录 id（history 模式时填；file/upload 模式为 NULL）
    restore_mode        VARCHAR(16)  NOT NULL,                  -- cover | upsert
    tables              JSONB        NOT NULL DEFAULT '[]'::jsonb,  -- 备份头里的表列表
    tables_count        INTEGER      NOT NULL DEFAULT 0,
    pre_backup_id       BIGINT,                                 -- 恢复前自动备份的 id（失败回滚用）
    progress            INTEGER      NOT NULL DEFAULT 0,
    progress_msg        VARCHAR(255) NOT NULL DEFAULT '',
    status              VARCHAR(16)  NOT NULL DEFAULT 'pending',-- pending | running | success | failed | rolled_back
    rows_inserted       BIGINT       NOT NULL DEFAULT 0,        -- 实际写入行数
    rows_skipped        BIGINT       NOT NULL DEFAULT 0,        -- upsert 模式跳过数
    error_message       TEXT,
    started_at          TIMESTAMPTZ,
    finished_at         TIMESTAMPTZ,
    created_by          INTEGER      NOT NULL,
    created_at          TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS ix_sys_restore_records_status ON sys_restore_records (status);
CREATE INDEX IF NOT EXISTS ix_sys_restore_records_created_by ON sys_restore_records (created_by);
CREATE INDEX IF NOT EXISTS ix_sys_restore_records_created_at ON sys_restore_records (created_at DESC);
CREATE INDEX IF NOT EXISTS ix_sys_restore_records_source_backup_id ON sys_restore_records (source_backup_id);

COMMENT ON TABLE sys_restore_records IS '恢复任务记录：一次恢复 = 一行';
COMMENT ON COLUMN sys_restore_records.source_type IS 'file=本地路径 / upload=前端上传 / history=从历史备份选';
COMMENT ON COLUMN sys_restore_records.restore_mode IS 'cover=全量覆盖（DROP+CREATE+COPY） / upsert=增量（ON CONFLICT DO NOTHING）';
COMMENT ON COLUMN sys_restore_records.pre_backup_id IS '恢复前自动做的备份 id，失败时回滚用';
COMMENT ON COLUMN sys_restore_records.status IS 'rolled_back=失败后已自动回滚到 pre_backup';
```

### 3.3 状态机

```
pending ──► running ──┬──► success
                      │
                      ├──► failed（事务内异常，整体回滚，无副作用）
                      │
                      └──► rolled_back（罕见：事务外异常，自动从 pre_backup 还原）
```

**回滚机制**：

```python
# _run_restore 主流程
try:
    async with async_engine.begin() as conn:
        await conn.execute(text(sql_text))  # 单事务 DROP+CREATE+COPY
    status = "success"
except Exception as e:
    # 事务已回滚，无需做 rolled_back
    status = "failed"
```

> ⚠️ 因为 DROP+CREATE+COPY 都在**单一事务**内执行，PostgreSQL 失败会自动回滚，不需要"从 pre_backup 还原"。`pre_backup_id` 主要是**给运维/审计**留个"撤销"通道，万一恢复成功后发现业务问题，运维可手动从 pre_backup 再恢复一次。

## 4. 备份文件头部签名（约定）

恢复时强校验的前 5 行（**必须有**）：

```sql
-- backup_name: {name}
-- generator: attribution-analysis
-- generator_version: 2.0
-- backup_type: full | schema | data
-- tables_count: {N}
-- created_at: {ISO8601}
-- schema_version: {Base.metadata 版本号（来自 settings.BACKUP_SCHEMA_VERSION）}
```

**校验逻辑**（恢复时）：

```python
REQUIRED_HEADERS = [
    "backup_name:", "generator:", "generator_version:",
    "backup_type:", "tables_count:", "created_at:",
]

def parse_header(sql_text: str) -> dict:
    """仅读取头部 5 行"""
    lines = sql_text.splitlines()[:20]  # 头部签名
    header = {}
    for line in lines:
        line = line.strip()
        if not line.startswith("--"):
            break
        if ":" in line:
            k, v = line.lstrip("- ").split(":", 1)
            header[k.strip()] = v.strip()
    # 强校验
    missing = [k for k in REQUIRED_HEADERS if not any(h.startswith(k) for h in header)]
    if missing:
        raise InvalidBackupFileError(f"缺少头部: {missing}")
    if header.get("generator") != "attribution-analysis":
        raise InvalidBackupFileError("非本系统生成的备份")
    return header
```

## 5. 不需要新表的部分

| 数据 | 存哪 | 理由 |
|---|---|---|
| 路径配置（白名单 / 用户自定义）| **`SysBackupConfigDB` 改成 key-value 存 `sys_app_config` 或 `redis`** | 简单 KV，避免再加表；用现有 `sys_app_config` 表（如无则复用 `sys_backup_records` 第一行的 `output_dir` 字段当默认）|
| 备份进度 | `sys_backup_records.progress` + `progress_msg` | 单条记录已覆盖 |
| 备份文件元信息 | `sys_backup_records.file_path / file_size / row_count` | 单条记录已覆盖 |

> 简化决策：v1 **不引入 `sys_app_config` 表**，路径默认从 ENV 读取，前端不持久化到服务端。如果运维需要改默认路径，改 ENV 重启即可。

## 9. 与现有表的关系

| 现有表 | 备份/恢复时怎么处理 |
|---|---|
| `stock_infos / tech_kline_dailys / ...`（38 张业务表）| **全量备份**，恢复时按模式 `cover / upsert` 处理 |
| `sys_users / sys_roles / sys_permissions / sys_user_roles / sys_role_permissions` | **备份**（保留用户体系）；恢复时 `cover` 模式会**覆盖所有用户**包括 admin，**恢复后默认 admin 仍可登录**（密码 hash 同步覆盖）|
| `sys_refresh_tokens` | **备份但恢复时清空**（恢复后所有用户需重新登录）|
| `sys_collect_tasks` | **备份**；恢复时清空 `status='running'` 的记录（与 main.py `_migrate_sys_collect_tasks` 一致）|
| `sys_backup_records / sys_restore_records` | **不备份自己**（递归自备份无意义且危险）|
| `collect_fetchers / collect_plans / collect_plan_items` | **备份**（采集元数据）|

    "sys_restore_records",     # 不自备份

## 10. 字段设计取舍

| 决策 | Why |
|---|---|
| `tables` 用 JSONB 而非关联表 | 备份是"快照"语义，不需要规范化查询；JSONB 灵活 |
| `file_size` 用 BIGINT | 文件可能 > 2GB（BIGINT = 8 字节，够用）|
| `progress` 用 INTEGER（0-100）| 比 FLOAT 简单，比"按表"细粒度好做轮询 |
| `created_by` 必填 | 审计需要；备份是高危操作 |
| `source_backup_id` 允许 NULL | upload / file 模式来源不一定是历史备份 |
| `pre_backup_id` 允许 NULL | v1 暂不实现自动 pre-restore；保留字段为 v2 自动备份留接口 |
| 不加 `tags / description` | v1 不需要；想加时 `JSONB` 加 key 即可 |
