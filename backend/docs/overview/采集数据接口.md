# 采集数据接口 · 使用手册

> 面向"前端采集管理页"和"接口测试人员"。所有 HTTP 端点以 `/api/v1` 为前缀；本文示例均省略此前缀。

最后更新：2026-10-02

---

## 0. 文档约定

- **Base URL**：`http://localhost:8000`（开发环境）
- **响应结构**：统一由 `route.api._response` 包装
  - 成功：`{"code": 0, "data": ...}`
  - 业务错误：`{"code": 0, "data": {"message": "..."}}`（沿用旧契约，部分端点 200 + 文案）
  - HTTP 错误：`{"code": != 0, "message": "..."}`
- **两类接口**：
  - **批量采集接口**（`kind=batch`）：写入数据库 → 启动后台任务 → 实时进度轮询
  - **实时接口**（`kind=realtime`）：只读外部数据 + Redis 缓存（15 秒）→ 试查即返回

## 2. 批量采集接口（7 个 ready + 14 个 planned）

### 2.1 通用三步流程

不管哪个 batch 接口，都按这三步调用：

| 步骤 | 端点 | 说明 |
|---|---|---|
| ① 创建任务 | `POST /collect/tasks` | body: `{task_type, params}`；返回 `task_id` |
| ② 轮询进度 | `GET /collect/tasks/{task_id}/progress` | 每 2 秒轮一次；`status=running/done/failed/cancelled` |
| ③ 详情 | `GET /collect/tasks/{task_id}` | 完成后看 `message` 汇总 |

**取消**（可选）：`POST /collect/tasks/{task_id}/cancel?force=false`（礼貌取消）或 `?force=true`（强制改 DB 状态）。

**冲突处理**：
- 同 `task_type` 已存在 `running` 任务 → 返回 200 + `data.message = "..."`（不返回 `task_id`）
- 看 `data.message` 包含 "已在运行" 字样即拒绝
- 旧服务残留的 `running` 任务：每次启动会标 `failed`（单进程假设）

### 2.2 `daily_kline`（日 K 线）

**数据源**：Tushare `daily` + 17 个技术指标

**写入表**：`tech_kline_dailys`（含 open/close/high/low/ma5/ma10/ma20/macd/rsi 等）

**默认参数**：`{"days": 7}` —— 自动算 `start_date = today - 7 days`

**可覆盖参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| `days` | int | 与 `start_date`/`end_date` 互斥；往前 N 天（含今天） |
| `start_date` | str | `YYYY-MM-DD` 或 `YYYYMMDD`；与 `end_date` 配对 |
| `end_date` | str | `YYYY-MM-DD` 或 `YYYYMMDD`；默认今天 |
| `symbols` | list[str] | 指定股票代码 6 位（如 `["000001", "600000"]`）；不传则全市场 |
| `concurrency` | int | 并发数（默认 3，上限 `COLLECT_MAX_CONCURRENCY`） |

**典型调用**：

```bash
# ① 最近 7 天（默认）
curl -X POST http://localhost:8000/api/v1/collect/tasks \
  -H 'Content-Type: application/json' \
  -d '{"task_type": "daily_kline", "params": {}}'

# ② 指定日期范围
curl -X POST http://localhost:8000/api/v1/collect/tasks \
  -H 'Content-Type: application/json' \
  -d '{"task_type": "daily_kline", "params": {"start_date": "2026-10-01", "end_date": "2026-10-02"}}'

# ③ 指定几只股票
curl -X POST http://localhost:8000/api/v1/collect/tasks \
  -H 'Content-Type: application/json' \
  -d '{"task_type": "daily_kline", "params": {"symbols": ["000001", "600000"]}}'
```

**进度返回示例**：

```json
{
  "code": 0,
  "data": {
    "total": 5572, "done": 1234, "success": 1100, "fail": 134, "skip": 0,
    "status": "running", "current": "000966", "percent": 22.1
  }
}
```

**已知坑**：
- **Tushare daily 限频**：5000 积分账号限 500 次/分钟；并发过大（`period=10`）会触发限频
- **A 股停牌**：返回空数据 → `skipped=True`（不是失败）
- **Tushare 数据入库**：交易日每天 15:00-16:00 入库；早于 15:00 跑任务时"今天"的数据可能没有

**限频处理**（2026-10-02 修复）：
- 代码已识别 Tushare 限频异常 → chunk 末尾自动 backoff 1s → 2s → 4s → ... → 60s
- 日志看 `WARNING 任务 X: 本 chunk 触发限频，backoff Xs`

### 2.3 `stock_basic`（股票基本信息）

**数据源**：Tushare `stock_basic`

**写入表**：`stock_infos`（约 5500+ 只）

**默认参数**：`{"list_status": "L"}`

**可覆盖参数**：

| 参数 | 类型 | 说明 |
|---|---|---|
| `list_status` | str | `L`（默认，上市中）/ `D`（已退市）/ `P`（暂停上市） |

**典型调用**：

```bash
# 同步上市中股票
curl -X POST http://localhost:8000/api/v1/collect/tasks \
  -H 'Content-Type: application/json' \
  -d '{"task_type": "stock_basic", "params": {}}'

# 同步退市股票（多用于补全历史 K 线表）
curl -X POST http://localhost:8000/api/v1/collect/tasks \
  -H 'Content-Type: application/json' \
  -d '{"task_type": "stock_basic", "params": {"list_status": "D"}}'
```

**注意**：
- 任务只有 1 个单元（"all"），跑得快（10 秒内）
- **必须先跑这个**才能跑 `daily_kline`（按 symbols 全市场过滤需要 stock_infos）

| `only_missing` | bool | 跳过库中已有财报的股票（断点续采） |
| `limit` | int | 只采前 N 只（调试用） |

**典型调用**：


**注意**：

## 4. 实时接口（2 个）

### 4.1 `stock_minute_kline`（分钟 K 线）

**数据源**：通达信 pytdx（**实时接口，不入库**）

**缓存策略**：工作日交易时段 15 秒，其他时段缓存到下个工作日。

**速率限制**：pytdx 进程内并发 = 1（单连接加锁）。

#### 端点：`POST /collect/realtime/stock_minute_kline/query`

**Body**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `symbol` | str | 是 | 6 位股票代码 |
| `interval` | str | 否 | `1min` / `5min` / `15min` / `30min` / `60min`（默认 `5min`） |
| `days` | int | 否 | 1-5 天（默认 1） |
| `count` | int | 否 | 兼容旧版 ≤ 1200（与 `days` 互斥） |

**响应**：

```json
{
  "code": 0,
  "data": {
    "data": [
      {"time": "2026-10-02 09:31", "open": 11.5, "close": 11.6, "high": 11.7, "low": 11.5, "volume": 12345, "amount": 142500},
      ...
    ],
    "cached": false,
    "stale": false,
    "fetched_at": "2026-10-02T14:35:12",
    "latency_ms": 234
  }
}
```

**调用示例**：

```bash
curl -X POST http://localhost:8000/api/v1/collect/realtime/stock_minute_kline/query \
  -H 'Content-Type: application/json' \
  -d '{"symbol": "000001", "interval": "5min", "days": 1}'
```

**注意**：
- **北交所代码**（8/4/92 开头）返回 400（pytdx 不支持）
- `1min` 只能取 1 天
- 缓存命中返回 `cached: true` + `latency_ms` 接近 0
- 单飞锁：第一次请求会等约 2 秒后读缓存

#### 端点：`GET /collect/realtime/stock_minute_kline/stats?days=1`

返回按天的调用统计（calls / hits / misses / errors / latency_sum / last_error）。

## 5. 采集方案（cron 定时）

每个 batch 接口都有一条采集方案（在 `collect_plans` 表）。**前端 PlanCard.vue 编辑**。

### `GET /collect/plans`

返回所有接口的方案（含默认占位）。

### `GET /collect/plans/{task_type}`

单个方案。

### `PUT /collect/plans/{task_type}`

保存方案。Body：

```json
{
  "enabled": true,
  "cron": "0 15 * * 1-5",
  "params": {"days": 1},
  "trading_day_only": true
}
```

- `cron`：5 段（分 时 日 月 周）；非法返回 400
- `enabled=false` → 不调度
- `trading_day_only=true` → 仅交易日触发（**当前只过滤周末，节假日不处理**）
- 保存后同步刷新 APScheduler 的 job

### `POST /collect/plans/{task_type}/run`

**立即**按方案参数跑一次（不等下次定时）。

## 6. 任务组（顺序批量）

### `GET /collect/groups`

任务组列表。

### `POST /collect/groups`

Body：

```json
{
  "name": "盘后采集套件",
  "enabled": true,
  "cron": "30 15 * * 1-5",
  "trading_day_only": true,
  "stop_on_fail": true,
  "items": [
    {"task_type": "stock_basic", "params": {}},
    {"task_type": "daily_kline", "params": {"days": 1}},
    {"task_type": "daily_basic", "params": {"days": 1}},
    {"task_type": "fin_report", "params": {}},
    {"task_type": "concept", "params": {}},
    {"task_type": "concept_membership", "params": {}},
    {"task_type": "concept_index_th", "params": {}}
  ]
}
```

**规则**：
- `items` 顺序执行
- 某项 `failed` / `cancelled` 且 `stop_on_fail=true` → 停止后续
- 实时接口**不能加入任务组**（前端过滤 + 后端校验）
- 已在运行的项 → 跳过继续

### `PUT /collect/groups/{id}` / `DELETE /collect/groups/{id}`

修改 / 删除。

### `POST /collect/groups/{id}/run`

立即执行（后台顺序）。

## 8. 业务调用顺序建议

首次部署 / 灾难恢复后，按以下顺序跑：

1. **`stock_basic`**（基础，约 10 秒）→ 拿到股票主表
2. **`daily_kline`**（带日期参数 `start_date=2020-01-01`）→ 历史 K 线回填
3. **`daily_basic`**（带 `days=200`）→ 历史估值
4. **`fin_report`**（带 `years=3` + `only_missing=true`）→ 历史财报
5. **`concept`** → 概念清单
6. **`concept_membership`** → 概念成分股
7. **`concept_index_th`**（带 `full=true`）→ 概念日 K 全量

日常盘后：

- `daily_kline`（默认 `days=1`）
- `daily_basic`（默认 `days=1`）
- `concept_index_th`（默认增量）

## 9. 常见问题与排错

### Q1：创建任务返回 200 但没 `task_id`？

`data.message` 包含 "已在运行" 或 "未知任务类型"。检查：
- 同 `task_type` 是否已在跑（看 `/collect/tasks?status=running`）
- `task_type` 拼写（参考目录树 `items[].sub_groups`）

### Q2：进度一直不动？

- 看后端日志：`grep "DailyKline\|Tushare" backend/logs/*.log`
- 99% 是 Tushare 限频：`WARNING ... 本 chunk 触发限频，backoff Xs`
- 等 1-2 分钟；Tushare 限频惩罚期 60 秒

### Q3：单元全部失败但无明显错误？

检查：
1. 任务详情 `message` 字段（汇总）
2. 单只股票日志：`WARNING 股票 000001 采集业务异常: ...`
3. `error` 字段在 Redis：`collect:progress:{task_id}` 的 `fail` 计数

### Q4：Tushare 报"name 'xxx' is not defined"？

模块导入残缺。**必查** `tushare.py` 顶部 imports——本仓库曾因 `from datetime import date, timedelta` 缺 `datetime` 导致全部失败（2026-10-02 修复）。任何 fetcher 改完 import 后必须重启服务。

### Q5：实时接口试查 `cached: false` 但 `fetched_at` 不变？

降级命中：检查 Redis `rt:{name}:{key}` 是否在过期时间内；非交易时段 TTL 较长。

### Q6：取消任务无效？

- 普通取消要在单元**之间**检查（单只 fetch 中途不响应）
- 单只超时 60s → 自动下一只
- 不响应：`POST /collect/tasks/{id}/cancel?force=true`

### Q7：怎么知道 Tushare 限频恢复了？

观察日志：
- 失败单元 `error: 限频: ...` 减少
- 单元耗时恢复正常（5000 积分账号正常 ~200ms / 只）

### Q8：实时接口 `RealtimeQueryError: 502`？

adata / pytdx 上游故障。检查：
- `GET /collect/realtime/{name}/stats?days=1` 看 `last_error`
- 跨接口联动：`concept_minute` 失败时 `stock_minute_kline` 不一定失败（不同数据源）
