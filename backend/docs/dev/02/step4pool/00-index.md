## 1. 为什么需要"操作池"？

### 1.1 现状

| 模块 | 状态 |
|------|------|
| 股票基础信息 | ✅ 已完成（step3） |
| K线采集/查询 | ✅ 已完成（step2） |
| 备选池（前端临时） | ⚠️ 仅存在于 `DataCollect.vue` 内存中，刷新即丢失 |

**问题**：
1. **不能复用**：用户每次采集都要重新选股
2. **不能分类**：用户无法组织"自选股 / 行业组合 / 策略池"
3. **不能批量**：操作永远是单只股票级别，无法一次操作一组
4. **场景割裂**：未来要做新闻、归因、因子计算等，每种都各做一套选股流程

### 1.2 操作池要解决什么？

```
┌───────────────────────────────────────────────────────────────┐
│  用户视角                                                       │
├───────────────────────────────────────────────────────────────┤
│  1. 创建自己的投资组合/分类                                        │
│     "我的自选" / "银行股组合" / "新能源赛道"                          │
│                                                                │
│  2. 把感兴趣的股票归入不同的池                                       │
│                                                                │
│  3. 对池内所有股票统一执行操作                                       │
│     • 批量采集K线                                                 │
│     • 批量获取新闻                                                 │
│     • 批量计算归因指标                                              │
│     • 批量导出数据                                                 │
│                                                                │
│  4. 持久化，下一次打开还在                                           │
└───────────────────────────────────────────────────────────────┘
```

## 2. 核心概念定义

### 2.1 名词解释

| 术语 | 英文 | 定义 |
|------|------|------|
| **操作池** | Stock Pool | 用户创建的、有命名的、持有一组股票代码的容器 |
| **池成员** | Pool Member | 池内的一个股票条目（含符号、备注、排序） |
| **池操作** | Pool Operation | 对池内所有成员发起的批量任务（如采集、计算） |
| **操作记录** | Operation Record | 池操作执行一次的历史记录（参数、状态、结果） |
| **备选池**（保留旧概念） | Pick Pool | 前端临时内存区，用户操作前临时选股 |

### 2.2 关键边界

| 维度 | 操作池（持久化） | 备选池（临时内存） |
|------|----------------|------------------|
| 生命周期 | 持久化在数据库 | 页面刷新即丢失 |
| 复用 | 跨页面、跨会话 | 仅当前会话 |
| 用途 | 长期持有 + 批量操作 | 临时选股 + 单次操作 |
| 关联数据 | 0~N 个池操作记录 | 无 |

**两者并存**：备选池不删除（保留作为"草稿区"），操作池是新的持久化能力。

## 3. 数据架构总览

### 3.1 三张表

```
┌────────────────────┐
│   stock_pools      │  ← 操作池主表（池元信息）
│────────────────────│
│ id                 │
│ name               │
│ description        │
│ pool_type          │  watchlist/industry/strategy/custom
│ color / icon       │
│ is_default         │
│ created_at         │
│ updated_at         │
└─────────┬──────────┘
          │ 1:N
          ▼
┌────────────────────────────┐
│   stock_pool_members       │  ← 池成员关联表
│────────────────────────────│
│ pool_id                    │
│ symbol                     │  FK→stock_infos.symbol（逻辑外键）
│ memo                       │  用户备注
│ sort_order                 │
│ added_at                   │
└────────────────────────────┘

┌────────────────────────────┐
│   pool_operations          │  ← 池操作记录表（异步任务跟踪）
│────────────────────────────│
│ id                         │
│ pool_id                    │
│ operation_type             │  kline_collect / news_fetch / factor_calc
│ status                     │  pending/running/success/partial/failed
│ params                     │  JSONB
│ result_summary             │  JSONB
│ progress                   │  done/total
│ error_message              │
│ started_at / finished_at   │
│ created_at                 │
└────────────────────────────┘
```

### 3.2 数据流原则

| 数据类型 | 存放位置 | 设计原因 |
|---------|---------|---------|
| 股票元信息 | `stock_infos`（已有） | 全局共享，一份数据 |
| K线行情 | `daily_klines`（已有） | 全局共享，按 symbol |
| 池元信息 | `stock_pools` | 唯一持有 |
| 池成员 | `stock_pool_members` | 唯一持有 |
| 池操作记录 | `pool_operations` | 唯一持有 |
| **不在池内复制任何股票/K线明细数据** | - | 避免冗余 + 保持一致性 |

## 5. 决策一览

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| 1 | 多用户支持？ | **暂不支持**（单用户） | 早期不必过度设计 |
| 2 | 池成员上限？ | **不限** | 业务无硬限制 |
| 3 | 明细数据存哪？ | **全局表（按 symbol）** | 避免冗余 |
| 4 | 池操作执行模型？ | **异步 + WebSocket/SSE 进度推送** | 大批量采集不能阻塞 HTTP |
| 5 | 是否复用旧备选池？ | **不复用** | 备选池是临时区，操作池是持久组合 |
| 6 | 池操作记录保留时间？ | **永久保留**（可手动清理） | 审计需要 |
| 7 | 是否引入"池数据快照"？ | **不引入** | 池只持有"引用" |
| 8 | 前端是否支持拖拽调整成员顺序？ | **暂不支持**，预留 `sort_order` 字段 | P1 后续 |
| 9 | 池是否可分享？ | **不支持**，但预留 `share_token` 字段 | P2 后续 |
| 10 | 默认池（自选股）？ | **系统预置 1 个**，不可删除 | 必选项 |

## 6. 与现有模块的关系

```
        ┌─────────────────────┐
        │   stock_infos 表    │  ← 已存在，池关联引用
        └──────────┬──────────┘
                   │
        ┌──────────▼──────────┐
        │  stock_pool_members │  ← 池成员：建立股票→池的关联
        └──────────┬──────────┘
                   │
        ┌──────────▼──────────┐     ┌─────────────────────┐
        │   stock_pools       │     │  pool_operations    │
        │   (池元信息)         │◄────│  (池批量操作记录)     │
        └─────────────────────┘     └──────────┬──────────┘
                                                │
                                  ┌─────────────▼──────────────┐
                                  │  对池内每只 symbol 调用的     │
                                  │  现有能力：                   │
                                  │  • KlineAppService.collect │
                                  │  • StockAppService.*       │
                                  │  • 未来：News/Factor/...    │
                                  └────────────────────────────┘
```

**操作池对现有模块是"消费者"，不修改任何现有表与接口**。
