## 3. 与后端 3 个核心接口的对应

| 前端调用 | 后端端点 | 文件 |
|---|---|---|
| `listServicesCached()` | `GET /api/collect/services` | `api.ts` |
| `runService(name, {mode, params})` | `POST /api/collect/{facet}/{name}` | `api.ts` |
| `queryService(name, params)` | `GET /api/collect/query/{name}?params=<JSON>` | `api.ts` |

### 3.1 左树数据流

```
App mount
  → useCatalog.load()
    → listServicesCached() ──GET /collect/services──▶ 后端 _build_catalog()
    → buildCatalog(items)  # 前端按 facet/sub_facet 二级聚合
  → catalog.value = [...]
  → CatalogTree 渲染 facet → sub_facet → service
  → 用户点击 service_name → CollectTaskPane 渲染对应卡片
```

### 3.2 采集数据流

```
用户填参数 / 选全量
  → CollectActionCard.start() → emit('start', { mode, params })
  → CollectTaskPane.runServiceAndWait() → runService(name, payload)
  → POST /api/collect/{facet}/{name}  body: { mode, params }
  → 后端 route → service.collect(mode, **params) → fetcher → repo.save()
  → CollectResponse: { total, success, fail, skip, saved, message }
  → 右侧「最近一次执行结果」卡片显示统计
```

### 3.3 实时查询数据流（kind=realtime 或 supports_query=true）

```
用户填参数
  → RealtimePanel.runQuery() → queryService(name, kwargs)
  → GET /api/collect/query/{name}?params=<JSON>
  → 后端 query_service_endpoint() → cls().get(**kwargs) → 返回 list[dict]
  → el-table 预览前 20 条
```

## 7. 已知遗留（不在本任务范围）

1. **实时查询 service 的 `cls()` 构造问题**：`query_service_endpoint` 用 `cls()` 无参构造，但部分 service 在 `get()` 内部访问 `self._session`，无 session 会报 AttributeError。这影响 RealtimePanel 试查按钮的可点击性。修复方向：让 query endpoint 也走 `Depends(get_db)`（参照 collect_service.py 工厂模式），不破坏 service 签名。

2. **占位 tab 无实际功能**：「调度计划」「采集历史」目前是 el-empty 卡片，等 scheduler / logs 后端实现后再补。

3. **采集运行无进度 / 取消**：当前是同步等待 `runService` 返回 CollectResponse；后端暂时无 stream / 进度推送，前端不做轮询。
