# 05 实时查询并入统一入口：取消 realtime/

> 对应 README 流程 ④ 和使用方式"实时查询"。阶段 P3。

## 1. 现在 realtime 做什么

"实时接口" = 页面当前要看的数据，按需请求数据源，结果只写 Redis，不入库、不建任务记录。现有 2 个：`stock_minute_kline`（pytdx 分 K）、`concept_minute`（同花顺概念分时）。

调用方：

| 调用方 | 方式 |
| :-- | :-- |
| `route/api/v1/minute_kline.py` `GET /minute-klines/{symbol}` | 直接调 framework |
| `route/api/v1/concept.py` `GET /concepts/{index_code}/minute` | 直接调 framework |
| `route/api/v1/collect_task.py` `POST /collect/realtime/{name}/query`、`GET .../stats` | 直接调 framework（采集管理"试查"和统计） |
| `concept_service.get_quotes`、`concept_board_service`（3 处） | 经 `RealtimeQueryPort.query_many` |

`realtime/` 里混了五类职责：

| 职责 | 现在在哪 | 性质 | 改造后去处 |
| :-- | :-- | :-- | :-- |
| 数据定义（facet / label / 数据源） | `BaseRealtimeQuery` 类变量 | 元数据 | XxxPort（01） |
| 取数 | `Query.fetch()` | 底层实现 | XxxAdapter（02） |
| 缓存（TTL 跟交易时段）、单飞锁、超时 | `framework._query` | 横向技术能力 | **`CacheDecorator`**（本文 §3） |
| 同源并发、调用统计 | `framework._fetch` / `_record` | 横向技术能力 | `ThrottleDecorator` / `MetricsDecorator`（03） |
| 参数规范化（days → count） | `Query.normalize` / `fetch` | 接口约束 | Port 的 `Params` 模型校验器（本文 §2） |
| 降级（概念行情失败返回库里最近收盘）、结果组装 | `Query.fallback` / `fetch` | **业务逻辑** | 应用层 Service（本文 §4） |

拆完之后 `realtime/` 里没有剩下的东西，整个目录删除。实时查询就是"应用层 Service 用 `policy=QUERY` 调统一入口"。

## 2. 实时类 Port

声明了 `cache` 的 Port 即为"实时接口"，名称沿用现有的 `stock_minute_kline` / `concept_minute`，保证 `collect_fetchers` 表、前端"试查"、统计接口不变。

```python
# application/port/data/base.py
@dataclass(frozen=True)
class CachePolicy:
    ttl_trading: int                 # 交易时段缓存秒数；非交易时段由 domain.service.market_session.ttl_for 决定
    consumers: tuple[str, ...] = ()  # 采集管理页展示：谁在调用本接口
```

```python
# application/port/data/tech.py
class MinuteInterval(StrEnum):
    M1 = "1min"
    M5 = "5min"
    M15 = "15min"
    M30 = "30min"
    M60 = "60min"

BARS_PER_DAY = {MinuteInterval.M1: 240, MinuteInterval.M5: 48, MinuteInterval.M15: 16,
                MinuteInterval.M30: 8, MinuteInterval.M60: 4}

class MinuteKlineParams(BaseModel):
    model_config = ConfigDict(extra="forbid")

    symbol: Symbol                                   # 01 §4.1 公共类型
    interval: MinuteInterval = MinuteInterval.M5     # 粒度
    days: int = Field(1, ge=1, le=5)                 # 范围：最近 N 个交易日

    @model_validator(mode="after")
    def _one_day_for_1min(self):                     # 唯一需要手写的跨字段规则
        if self.interval is MinuteInterval.M1 and self.days != 1:
            raise ValueError("1min 只支持当天")
        return self

class MinuteKlinePort(DataPort[MinuteKlineParams, MinuteKlineBO]):
    name, label = "stock_minute_kline", "股票分 K"
    facet, sub_facet = "tech", "kline"
    description = "通达信 1/5/15/30/60 分钟 K 线；1 分钟仅当天，其他周期最多 5 日"
    Params, Item = MinuteKlineParams, MinuteKlineBO
    cache = CachePolicy(ttl_trading=15, consumers=("股票列表展开行 · 分 K",))
    sample_params = {"symbol": "600519", "interval": "5min", "days": 1}
```

```python
# application/port/data/concept.py
class ConceptMinutePort(DataPort[ConceptMinuteParams, ConceptMinuteBO]):
    name, label = "concept_minute", "概念实时行情"
    facet, sub_facet = "fundamental", "concept"
    Params, Item = ConceptMinuteParams, ConceptMinuteBO     # Params 校验 6 位 index_code
    cache = CachePolicy(ttl_trading=15, consumers=("详情抽屉 · 概念 Tab",))
    sample_params = {"index_code": "885525"}
```

`ConceptMinutePort` 返回 `list[ConceptMinuteBO]`（单条时列表只有一个元素），保持所有 Port 返回值形状一致。

**和现在 `normalize` 的差异**：

| 现在 | 改造后 | 原因 |
| :-- | :-- | :-- |
| `interval: str`，运行时判断是否在 5 个值里 | `MinuteInterval` 枚举 | 写错（如 `"1d"`）在类型检查和入口校验阶段就报错，不会被吞成"无数据" |
| `days` 和 `count` 两种范围写法并存 | 只有 `days` | "最近 N 根"是通达信的取数方式，换算放到 `PytdxMinuteKlineAdapter`（02 §4）。前端只传 `interval` + `days`，`count` 没有调用方 |
| 6 位代码、范围用 `if` 手写 | `Symbol` 公共类型、`Field(ge, le)` | 声明式，JSON Schema 自动带上约束（`/data/catalog`、Agent 工具直接可用） |
| 未知字段静默忽略 | `extra="forbid"` | 多传、拼错的字段直接 `InvalidParams` |

**北交所校验不放进 `Params`**：现在 `normalize` 里的"北交所代码，分K暂不支持"是通达信这个数据源的能力限制，不是数据本身的约束。放进 `Params` 会让请求在选源前就被拒，以后接入支持北交所的源也用不上。改造后由 `PytdxMinuteKlineAdapter.supports()` 返回 False（02 §4），Gateway 抛 `NotSupported`；`stock_info_service.get_minute_klines` 捕获后转成原来的提示文案，页面看到的报错不变。

## 3. CacheDecorator

```python
# adapter/data/core/cache.py
class CacheDecorator:
    async def get_or_load(self, port, params, load) -> DataResult:
        key = f"ds:cache:{port.name}:{_hash(params)}"     # params.model_dump(mode="json") 排序后 sha1
        hit = await self._read(key, port.Item)            # 命中：反序列化成 Item，cached=True
        if hit: return hit
        if not await self._lock(key):                     # 单飞：SET NX EX 5；等 2s 轮询缓存
            ...
        try:
            result = await asyncio.wait_for(load(), timeout=FETCH_TIMEOUT)   # load = Gateway 选源 + 装饰器链
            await self._write(key, result, ttl=ttl_for(port.cache.ttl_trading))
            return result
        finally:
            await self._unlock(key)
```

- 逻辑从 `realtime/framework.py::_query` 原样搬过来：锁 TTL 5s、等待 2s、轮询 0.1s、超时 10s、Redis 不可用时直接取数不缓存（`try_get_redis`）。
- **缓存键自动生成**，各接口不再手写 `cache_key`。参数先经 `Params` 校验并补默认值再算哈希，所以 `{"symbol": "600519"}` 和 `{"symbol": "600519", "interval": "5min", "days": 1}` 命中同一份缓存。
- 缓存存的是 `Item.model_dump(mode="json")` 列表 + `source` + `fetched_at`，读出时用 `Item.model_validate` 还原成 BO。
- 缓存放在选源之前：同样的参数不管最终由哪个数据源返回，都命中同一份缓存。
- 失败时不写缓存、不做降级，直接抛给调用方，降级由业务决定（§4）。
- 只在 `policy=QUERY` 且 Port 声明了 `cache` 时启用；采集任务（`COLLECT`）永远不走缓存。

## 4. 业务降级与结果组装移到应用层

### 4.1 概念实时行情：新增 ConceptRealtimeReader

`concept_service` 和 `concept_board_service`（3 处）都在查 `concept_minute`，且都依赖"失败时返回最近收盘"。把这段共用逻辑放到一个应用层小类里，两个 Service 注入使用：

```python
# application/service/concept_realtime.py
class ConceptRealtimeReader:
    def __init__(self, gateway: DataGatewayPort, repo: ConceptRepository): ...

    async def minutes(self, codes: list[str]) -> dict[str, ConceptMinuteVO]:
        results = await self._gateway.fetch_many(
            ConceptMinutePort, [ConceptMinuteParams(index_code=c) for c in codes], policy=CallPolicy.QUERY,
        )
        out, failed = {}, []
        for code, res in zip(codes, results):
            if isinstance(res, DataResult) and res.items:
                out[code] = ConceptMinuteVO.from_bo(res.items[0], cached=res.cached, fetched_at=res.fetched_at)
            else:
                if isinstance(res, InvalidParams):       # 参数错是代码 bug，打日志，不当作数据源故障
                    logger.error("concept_minute 参数错误 %s: %r", code, res)
                failed.append(code)
        if failed:                                   # 降级：一次查出失败概念的最近日 K 收盘，标 stale
            closes = await self._repo.get_latest_closes(failed)
            out.update({c: ConceptMinuteVO.from_close(c, closes[c], stale=True) for c in failed if closes.get(c)})
        return out
```

- 降级查询从"每个概念单独查一次库"变成"失败的概念一次批量查"。
- `concept_service.get_quotes`、`concept_board_service` 的 3 处调用、`GET /concepts/{index_code}/minute` 都改用它。返回字段（`stale` / `cached` / `fetched_at` 和行情字段）与现在一致。

### 4.2 股票分 K

```python
# application/service/stock_info_service.py
async def get_minute_klines(self, params: MinuteKlineParams) -> MinuteKlineVO:
    try:
        res = await self._gateway.fetch(MinuteKlinePort, params, policy=CallPolicy.QUERY)
    except NotSupported:
        raise InvalidParams(f"{params.symbol} 为北交所代码，分K暂不支持")   # 保持原提示文案
    return MinuteKlineVO(total=len(res.items), items=[_format_bar(b) for b in res.items],
                         cached=res.cached, fetched_at=res.fetched_at)
```

```python
# route/api/v1/minute_kline.py
@router.get("/{symbol}")
async def get_minute_klines(
    symbol: str,
    interval: MinuteInterval = Query(MinuteInterval.M5),
    days: int = Query(1, ge=1, le=5),
    service: StockInfoService = Depends(get_stock_info_service),
):
    try:
        params = MinuteKlineParams(symbol=symbol, interval=interval, days=days)
        return R.ok(await service.get_minute_klines(params))
    except (ValidationError, InvalidParams) as e:
        return R.err(str(e), 400)
    except (RateLimited, SourceUnavailable) as e:
        return R.err(str(e), 502)
```

- 应用层用类型化的 `gateway.fetch(MinuteKlinePort, ...)`，不用 `invoke(DataCommand("stock_minute_kline", {...}))`（DDD.md §2.2 反例）。
- 路由直接复用 `MinuteInterval` 枚举，FastAPI 在入口校验，OpenAPI 文档里显示可选值。路由不再直接 import `infrastructure.adapter.realtime`，改为经 `StockInfoService`（现在的写法违反 DDD.md §4 "route 不依赖 infrastructure"）。
- 删除路由的 `count` 参数（前端 `getMinuteKlines` 只传 `interval` / `days`）。前端 `interval?: string` 同步收紧为 `'1min' | '5min' | '15min' | '30min' | '60min'`。
- `_format_bar` 是原 `StockMinuteKlineQuery.fetch` 里组装每根 K 线的那段，响应字段不变。分 K 没有降级，与现在一致。
- 错误码：`days` 超出 1–5 现在就由 FastAPI 返回 422，不变；`interval` 非法从现在的 400 变为 422（前端是固定下拉选项，正常不会触发）；跨字段规则（1min 只支持当天）和北交所提示仍为 400；数据源失败 502。

`StockInfoService` 构造时注入 `DataGatewayPort` 这一步提前到 P3 做（06 §2.1 的构造改动），P3 只新增 `get_minute_klines`，`sync_stocks` 等方法仍保留 `fetcher` 参数，到 P4 再改。

### 4.3 概念看板的成分股实时涨幅（不处理）

`concept_board_service.query_board_members` 用 `interval="1d"` 查分 K 取实时涨幅，参数非法且分 K 返回里也没有涨跌幅字段，这一列现在始终为空。概念看板后续会下线，本次不修。删除 `realtime/` 时这段调用一并删除，`pct_change` 固定返回 `None`，与现在的实际表现一致。

## 5. 采集管理页相关的改动

| 接口 | 改造后 | 兼容性 |
| :-- | :-- | :-- |
| `GET /collect/catalog` | 实时接口部分改为遍历声明了 `cache` 的 Port：`kind="realtime"`、`ttl_trading` / `consumers` 取自 `cache`、`default_params` 取自 `sample_params`、`source` / `source_label` 取首选 Adapter 的 `origin` 及其中文标签 | 字段不变 |
| `POST /collect/realtime/{name}/query`（试查） | 经 `DataQueryService.query(name, body)`（06 §4.1，P3 先建好，P6 的 `/data/*` 复用），内部 `gateway.invoke(DataCommand(name, body, policy=QUERY))`。试查运行时才知道接口名，属于按名调用的正当场景 | 响应仍是 `{data, cached, stale, fetched_at, latency_ms, error}`；**`data` 变为 BO 列表**（原来是各接口自己组装的结构），`stale` 恒为 false（试查不做业务降级） |
| `GET /collect/realtime/{name}/stats` | 读 `ds:stats:{name}:cache:*`（命中）+ `ds:stats:{name}:*:*`（各实现的调用和错误）合并 | 返回字段不变；历史 `rt:stats:*` 不迁移，上线后从零开始统计 |

`origin` 的中文标签放在 `adapter/data/core/registry.py`：`{"tushare": "Tushare", "ths": "同花顺", "tdx": "通达信", "eastmoney": "东方财富"}`。

## 6. 删除清单

- `infrastructure/adapter/realtime/` 整个目录（`base.py`、`framework.py`、`registry.py`、两个 Query）。
- `application/port/realtime_query_port.py`。
- `main.py` 中的 `setup_realtime_registry(...)`；`collect_fetchers` 对账改为读 Port（采集任务 + 声明了 `cache` 的 Port）。
- `di.py` 中 `realtime=get_realtime_query_framework()` 的两处注入，改为注入 `ConceptRealtimeReader`。
- `CollectManageService` 的 `realtime_registry` 依赖：方案项校验"实时接口不能加入方案"改为判断该名称是否为声明了 `cache` 的 Port（通过 `DataGatewayPort.catalog()` 或一个只读的 `is_realtime(name)` 方法）。

## 7. 验收

- 股票列表展开行的分 K、详情抽屉的概念 Tab、概念看板正常；`/collect` 页"试查"和统计正常。
- `GET /minute-klines/600519?interval=1d` 由 FastAPI 在入口拦截，走 `main.py` 现有的 `RequestValidationError` 处理返回 422，`errors` 里带枚举可选值；`?interval=1min&days=2` 返回 400"1min 只支持当天"；北交所代码返回 400 原提示文案。
- `route/api/v1/minute_kline.py`、`concept.py`、`collect_task.py` 中 grep 不到 `infrastructure.adapter.realtime`。
- 15 秒内重复请求同一概念分时，第二次 `cached=true`；并发请求只打一次数据源。
- 模拟 adata 限流时，概念实时行情返回 `stale=true` 的降级数据；QUERY 策略下不会等待 60 秒。
