# 06 数据源适配器 — `TushareAdapter` / `AdataAdapter`

> 阶段 D6。**唯一**按数据源写代码的层。其它所有层（Port / ORM / Repo / Task / 入库）均不感知 source。
>
> 本节与 [`10-分库与表结构.md`](10-分库与表结构.md) 一致：port name 与表名约定见 10-分库 §4。

## 1. 抽象

```python
# contexts/data/infrastructure/fetcher/adapter.py

@runtime_checkable
class DataSourceAdapter(Protocol):
    """每个数据源（tushare / adata / pytdx）一个实现"""

    name: str

    async def fetch(self, port_name: str, params: dict) -> list[dict]:
        """
        按 port_name 调第三方 SDK，返回 dict 列表

        - port_name: 与 sys_data_ports.name 对齐
        - params: DynamicPort.build_params 校验后已映射好的入参
        - 返回的 dict 字段名必须与目标表的列名一致（snake_case 短名）
        """
```

**字段名一致性是数据源适配层的核心契约**：
- 适配器返回的 dict 键名 = 目标表列名
- 建表时运维按适配器输出键名建列
- 不一致 → 采集时字段校验失败，任务 fail

## 2. `TushareAdapter`

```python
# contexts/data/infrastructure/fetcher/tushare.py

class TushareAdapter:
    name = "tushare"

    def __init__(self, token: str, max_retries: int = 3):
        self._pro = ts.pro_api(token)
        self._max_retries = max_retries

    async def fetch(self, port_name: str, params: dict) -> list[dict]:
        method_name = self._port_to_method(port_name)
        method = getattr(self._pro, method_name)
        # Tushare 大部分接口是同步；放线程池
        loop = asyncio.get_running_loop()
        df = await loop.run_in_executor(
            None,
            lambda: self._with_retry(method, **params),
        )
        return self._normalize(port_name, df.to_dict(orient="records"))

    @staticmethod
    def _port_to_method(port_name: str) -> str:
        """
        14 个 port name 都没有业务前缀（cap_/fin_/base_），
        直接对应到 tushare 方法名：

        moneyflow      → pro.moneyflow
        margin         → pro.margin
        daily_basic    → pro.daily_basic
        adj_factor     → pro.adj_factor
        ...
        """
        return port_name

    def _normalize(self, port_name: str, rows: list[dict]) -> list[dict]:
        """Tushare 字段名是 ts_code/trade_date 等，已经与表列名对齐，直接返回"""
        return rows
```

### 2.1 字段名映射

Tushare 字段基本已经是 snake_case 短名。**当前阶段**：直接对齐；个别接口（如 `probar`）字段长名才需要映射。映射表按需扩展到 `_NORMALIZE` 函数内。

### 2.2 限频 / 重试

Tushare 限频是 IP 维度的 200 次/分。`TushareAdapter` 不做限频（由 `DataGateway` 横向装饰器统一管理，与 step5 一致）。

## 3. `AdataAdapter`

```python
# contexts/data/infrastructure/fetcher/adata.py

class AdataAdapter:
    name = "adata"

    def __init__(self):
        # adata 不需要 token
        pass

    async def fetch(self, port_name: str, params: dict) -> list[dict]:
        method_name = self._port_to_method(port_name)
        method = getattr(adata, method_name)
        loop = asyncio.get_running_loop()
        df = await loop.run_in_executor(None, lambda: method(**params))
        rows = df.to_dict(orient="records")
        return self._normalize(port_name, rows)

    def _normalize(self, port_name: str, rows: list[dict]) -> list[dict]:
        # adata 字段名一般是 stock_code/trade_date，与 tushare 不同，需要映射
        return self._ALIAS.get(port_name, lambda r: r)(rows)
```

字段名映射示例（`ALIAS`）：

```python
_ALIAS: dict[str, Callable[[list[dict]], list[dict]]] = {
    "moneyflow": lambda rs: [
        {**r, "ts_code": r.pop("stock_code")} for r in rs
    ],
    # ... 按需加
}
```

**重要**：`_ALIAS` 必须把 adata 字段名映射成与目标表列名一致的 snake_case 短名。

## 4. 启动期注册

```python
# contexts/data/infrastructure/fetcher/registry.py

class AdapterRegistry:
    def __init__(self):
        self._adapters: dict[str, DataSourceAdapter] = {}

    def register(self, adapter: DataSourceAdapter) -> None:
        self._adapters[adapter.name] = adapter

    def get(self, name: str) -> DataSourceAdapter:
        if name not in self._adapters:
            raise KeyError(f"no adapter registered for source: {name}")
        return self._adapters[name]


# di.py
def build_data_gateway(registry: AdapterRegistry) -> DataGateway:
    return DataGateway(registry=registry)
```

启动时：

```python
registry = AdapterRegistry()
registry.register(TushareAdapter(token=settings.TUSHARE_TOKEN))
registry.register(AdataAdapter())
gateway = build_data_gateway(registry)
```

## 5. 演示（D6 验收）

新增一个数据源（演示用 `adata` 跑 `moneyflow`）：

```sql
-- 1. 在 raw_data_db 库建 raw_cap_moneyflow_adata 表
\c raw_data_db
CREATE TABLE capital_moneyflow_adata (    -- ★ 新加 _adata 后缀
    ts_code        VARCHAR(16)   NOT NULL,
    trade_date     DATE          NOT NULL,
    buy_sm_vol     BIGINT,
    -- ... 列名与 AdataAdapter._ALIAS 输出对齐
    PRIMARY KEY (ts_code, trade_date)
);

-- 2. sys_data_ports 插入 1 条
INSERT INTO sys_data_ports (
    name, label, source, unit, kind, facet, params_schema, upsert_mode
) VALUES (
    'moneyflow_adata',
    '资金流向(adata)',
    'adata',                   -- ★ 指定数据源
    'trade_date',
    'batch',
    'capital',                 -- ★ 5 个面之一
    '{"type": "object", "properties": {"trade_date": {"type": "string", "pattern": "^\\d{8}$"}}, "required": ["trade_date"]}',
    'by_unique'
);
```

> ⚠️ **库名**：新表建在 `raw_data_db`（采集库），不是 `attribution_db`（业务库）。详见 [`10-分库与表结构.md §3.2`](10-分库与表结构.md)。

**零代码改动**：
- `AdataAdapter._port_to_method` 找到 `moneyflow_adata` 对应的 adata 方法（按 `moneyflow` 剥后缀）
- `AdataAdapter._ALIAS["moneyflow"]` 把 `stock_code` 映成 `ts_code`
- 用户采集时选 `capital_moneyflow_adata` 表
- 字段映射校验通过 → 试运行 → 入库

**新增数据源 = 1 张表 + 1 条 SQL + 1 段 adapter `_ALIAS`（按需）**。

## 9. port name 命名约定

| 维度 | 旧（step5） | 新（step6） |
|:--|:--|:--|
| **port name** | 带业务前缀（`cap_moneyflow` / `fin_daily_basic`） | **去掉业务前缀**（`moneyflow` / `daily_basic`） |
| **表名** | `cap_moneyflow` / `fin_daily_basic` | 短前缀（`capital_moneyflow` / `fundamental_daily_basic`） |
| **库** | 单库（`attribution_db`） | **双库**：`attribution_db`（业务）+ `raw_data_db`（raw） |
| **数据库引擎** | MySQL | **PostgreSQL** |

> 旧的 14 个 port name 在 D0 改名后就是新名（详见 [09-实施计划 §0](09-实施计划.md)）。
